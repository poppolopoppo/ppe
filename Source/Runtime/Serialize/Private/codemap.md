# Source/Runtime/Serialize/Private/

The Private Serialize folder implements the concrete serialization logic, format details, parser/tokenizer implementations, and the transaction system that powers all format serializers. This is where the actual work happens: BinaryFormat.h and BinaryFormat.cpp implement the FAT-like binary format details, JsonSerializer.cpp and Json.h implement JSON serialization logic, TransactionLinker.cpp and TransactionLinker.h implement cross-reference resolution, TransactionSaver.cpp and TransactionSaver.cpp provide read-only views of loaded references, and TransactionSerializer.cpp and TransactionSerializer.h implement the transaction manager that orchestrates BuildTransaction → Parse → Link → Save/Load. The Lexer and Parser private implementations (Lexer.cpp, ParseExpression.cpp, etc.) provide the tokenizer and recursive-descent parser that power the Text/DSL format. Without this folder, the Public format serializers would have no underlying implementation — the ISerializer interface would have no concrete fulfillers, the transaction system would lack its orchestrator and linker, and the DSL pipeline would be unable to tokenize or parse script sources.

## Responsibility

This folder owns the concrete implementation that makes serialization formats work. The transaction system is centered in TransactionSerializer.cpp/h, which implements FTransactionSerializer (BuildTransaction, SaveTransaction, LoadTransaction, MountToDB), FTransactionSaver (provides a read-only view of top/imported/loaded/exported refs), and FTransactionLinker (ResolveClass, ResolveImport, Resolve for cross-reference fixing during deserialization). BinaryFormat.h/cpp implement the low-level binary/FAT format details (FATFormat.h defines the index-based container format). Json.cpp/h and JsonSerializer.cpp/h implement the JSON serialization logic, including RTTI_to_Json and Json_to_RTTI helpers. The private Lexer implementation (Lexer.cpp, Symbol.cpp, Symbols.cpp, LookAheadReader.cpp, Match.cpp, Symbols.cpp) provides the tokenizer that produces FMatch tokens from input streams, while the private Parser implementation (ParseExpression.cpp, ParseStatement.cpp, ParseList.cpp, ParseItem.cpp, Grammar.cpp, ParseContext.cpp, Parser.cpp, ParseResult.h, ParseExpression-inl.h) provides the recursive-descent parser that builds the AST. All concrete implementations are DLL-safe with DLL_IMPORT/EXPORT guards and are not intended for external consumption — external systems should use the Public format serializers (FBinarySerializer, FJsonSerializer, etc.) or the ISerializer interface.

## Design

Key design decisions center on the transaction system's three-way separation: FTransactionSerializer orchestrates the save/load cycle, FTransactionSaver provides a read-only view of the linearized transaction state (top references, imported/loaded/exported refs), and FTransactionLinker resolves cross-references during deserialization. The linker pattern decouples parsing from object resolution: the parser produces an AST without knowing what objects the references point to, and the linker fixes each reference using FMetaDatabase lookups after all sources have been parsed. This allows circular references and cross-module references to be resolved correctly. The parser pipeline is designed for extensibility: new grammar rules can be added to the parser without changing the core tokenizer or transaction logic. The FAT format uses a custom index format (FATFormat.h) for random-access multi-object containers, distinct from the simple binary format (BinaryFormat.h). The JSON serializer provides RTTI_to_Json/Json_to_RTTI helpers for round-trip conversion via FMetaProperty. The Lexer uses a lookahead reader pattern (LookAheadReader) and produces FMatch tokens with symbol, span, and value information. The Parser uses recursive-descent with a stack-based approach for nested structures.

## Flow

Serialization flow begins when FTransactionSerializer.SaveTransaction(ctx, sources) is called: FetchSources() → filenames → BuildTransaction(ctx, sources) → FLexer (private Lexer.cpp) tokenizes each source file → Parser (private ParseExpression.cpp etc.) produces AST → FParseContext evaluates AST → FAtom results → FTransactionLinker.Resolve() → FMetaTransaction (loaded refs) → ISerializer.Serialize() → output stream. Load: FTransactionSerializer.LoadTransaction(ctx, sources) → same pipeline → FTransactionLinker.Resolve() → FMetaTransaction → ISerializer.Deserialize() → object graph. For the Text/DSL format: FLexer (Lexer.cpp) tokenizes the input → produces FMatch (symbol + span + value) → Parser recursive-descent → AST nodes (ParseExpression.cpp, ParseStatement.cpp, etc.) → FParseContext with SLABHEAP(Atom) temporary allocations → FAtom results → FMetaObject property population → RTTI-driven type resolution. Transaction lifecycle: FTransactionSerializer.Load() → Mount() → Mounted, Unmount() → Unload() → Unloaded, with FLinearizedTransaction flattening imported/loaded/exported refs for cross-reference resolution. The parser AST nodes flow from TLiteral/TBinaryFunction at the expression level through FObjectDefinition/FPropertyStatement at the statement level, with PCParseExpression = TRefPtr<FParseExpression> for ref-counted AST nodes.

## Integration

This folder integrates closely with the Public Serialize folder and all other Runtime modules via real paths under Source/. Downstream: Source/Runtime/Serialize/Public/ where the format serializers (FBinarySerializer, FJsonSerializer, FTextSerializer, FFATSerializer, FMarkupSerializer) depend on the concrete implementations here for their underlying logic; Source/Runtime/RTTI/ where all serializers depend on FMetaObject/FMetaProperty/FAtom for type-aware (de)serialization; Source/Runtime/VFS/ where the transaction system reads source files via FVirtualFileSystem; Source/Runtime/Serialize/Public/Parser/ and Source/Runtime/Serialize/Public/Lexer/ where the DSL infrastructure originates; Source/Runtime/Network/ and Source/Runtime/Remoting/ where serialized data flows in HTTP responses. Specific paths: Source/Runtime/Serialize/Private/Binary/BinaryFormat.h, Source/Runtime/Serialize/Public/Json/JsonSerializer.h, Source/Runtime/Serialize/Private/Lexer/Lexer.cpp, Source/Runtime/Serialize/Private/Parser/ParseExpression.cpp, Source/Runtime/Serialize/Private/Parser/ParseContext.cpp, Source/Runtime/Serialize/Private/TransactionLinker.cpp, Source/Runtime/Serialize/Private/TransactionSaver.cpp, Source/Runtime/Serialize/Private/TransactionSerializer.cpp. The transaction linker also resolves imports from Source/ other modules via FMetaClass lookups.
