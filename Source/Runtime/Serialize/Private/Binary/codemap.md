# Source/Runtime/Serialize/Private/Binary/

The Private Binary serializer folder implements the low-level binary format details that underlie the public FBinarySerializer. BinaryFormat.h defines the exact wire format, including the magic number, version, property count, and property data blocks that FBinarySerializer serializes. The binary format is schema-less: type information is carried via FAtom (void* + PTypeTraits) at runtime, and the serializer walks the FMetaClass property hierarchy to determine which properties to serialize and their offsets. BinaryFormat.cpp implements the actual read/write logic, using the FMetaDatabase for type lookups and FMetaProperty for offset-based property access. This folder is the implementation detail that makes the public FBinarySerializer work — external systems should not need to include headers from this folder, as the Public folder's FBinaryFormat.h provides the stable API surface.

## Responsibility

This folder owns the concrete binary format implementation that powers the public FBinarySerializer. BinaryFormat.h defines the wire format structure, and BinaryFormat.cpp implements the actual serialization logic. The folder handles the low-level details of writing/reading object data to/from a binary stream, including the magic number header, property count, and per-property data blocks. Each property is written as: [property_index][property_type][property_data], where property_type is encoded via PTypeTraits through FAtom type erasure. The serializer walks FMetaClass->_propertiesAll to determine which properties to serialize, and uses FMetaProperty::Get() to read/write typed data. This folder also supports the FAT format's underlying binary container format, as defined by FATFormat.h.

## Design

The design of the binary format implementation centers on schema-less, type-aware binary encoding via PTypeTraits and FAtom. The wire format consists of: [4-byte magic number][4-byte version][4-byte property count][for each property: 4-byte property index][type-encoded data via FAtom]. The property data is encoded using PTypeTraits to determine the type and size, enabling the serializer to read/write the correct number of bytes without a per-file schema. The serializer uses FMetaProperty::Get() to read data at the stored offset and FMetaProperty::Set() to write data back. The format is forward-compatible: new properties are ignored on load if the version doesn't match, and removed properties are simply not written on save. The format supports nested objects through recursive property traversal, and arrays through length-prefixed blocks.

## Flow

Serialization flow for the Binary format implementation: FBinarySerializer (Public) → BinaryFormat.cpp → walk FMetaClass->_propertiesAll → for each property, FMetaProperty::Get() reads data via FAtom→PTypeTraits → write [property_index][type_data] to stream. Deserialization reverses: read magic/version/property count → for each property: read [property_index][type_data] → FAtom→PTypeTraits → FMetaProperty::Set() to populate FMetaObject. The transaction system can wrap this: FTransactionSerializer.BuildTransaction() → parse → FTransactionLinker.Resolve() → BinaryFormat.cpp read/write → output. The flow is: module init → FMetaDatabase population → runtime queries → property access → BinaryFormat read/write → serializer output.

## Integration

This folder integrates with the Public Serialize folder and the RTTI system via real paths under Source/. Downstream: where the public API is defined; Source/Runtime/RTTI/ where FMetaObject/FMetaProperty/FAtom provide type-aware property traversal; Source/Runtime/Serialize/Private/FAT/ where the underlying FAT format shares the same binary details; Source/Runtime/VFS/ where binary save/load operations use FVirtualFileSystem; Source/Runtime/Network/ and Source/Runtime/Remoting/ where binary snapshots can be sent in HTTP responses. Specific paths: Source/Runtime/Serialize/Private/Binary/BinaryFormat.h. The binary format also integrates with Source/Runtime/Serialize/Public/TransactionSerializer.h for transaction-wrapped operations.
