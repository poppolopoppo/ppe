# Source/Runtime/Serialize/Private/Json/

The Private JSON serializer folder implements the concrete JSON serialization logic that powers the public FJsonSerializer. JsonSerializer.cpp and Json.h provide the actual JSON generation and parsing functions, including the RTTI_to_Json and Json_to_RTTI helper functions that enable round-trip conversion between engine objects and JSON. The Private folder also includes Json.cpp for general JSON utility functions. This folder is the implementation detail that makes the public FJsonSerializer work — external systems should not need to include headers from this folder, as the Public folder's FJsonSerializer.h provides the stable API surface. The JSON format is human-readable and widely compatible, and the Private implementation handles the low-level details of JSON object generation, array construction, value conversion, and round-trip type preservation.

## Responsibility

This folder owns the concrete JSON serialization implementation that powers the public FJsonSerializer. JsonSerializer.cpp implements the actual JSON generation/parsing logic, including the RTTI_to_Json helper that converts an FMetaObject into a JSON object (dictionary), recursively serializing each property, and the Json_to_RTTI helper that performs the reverse, taking a JSON object and populating an FMetaObject instance via CreateInstance() and property setters. Json.h provides the type declarations and function prototypes, while Json.cpp provides general JSON utility functions. The RTTI_to_Json helper walks the object tree top-down, producing JSON with property names as keys and typed values as JSON values (numbers for int/float/bool, strings for FName/String, null for null). The Json_to_RTTI helper walks JSON top-down, creating objects and setting properties, handling primitives, arrays, dictionaries, and nested objects. Round-trip conversion preserves value types for primitives but may lose some type-specific details (enum ordinal vs string, flag bitmasks, template instantiations).

## Design

The design of the JSON serializer implementation centers on RTTI-driven property traversal and value conversion. The RTTI_to_Json helper uses FMetaClass to discover properties at runtime, FMetaProperty to get each property's value through FAtom type erasure, and a JSON writer to produce the output. The helper handles primitives (int as JSON number, float as JSON number, bool as JSON true/false, string as JSON string, null as JSON null), arrays (JSON arrays with typed elements), dictionaries (JSON objects with string keys), and nested objects (recursive JSON objects). The Json_to_RTTI helper performs the reverse: it walks the JSON top-down, creating FMetaObject instances via CreateInstance() and setting properties via FMetaProperty::Set() with FAtom type erasure. The helper preserves value types for primitives but may round enums and flags to their closest JSON representation. The implementation is designed for high-fidelity round-trips on common types while acknowledging that some type-specific details may be lost in the JSON representation.

## Flow

Serialization flow for JSON: User code calls FJsonSerializer.Serialize(ctx, output) or FJsonSerializer.Deserialize(ctx, input). Save path: FJsonSerializer → RTTI_to_Json helper → FMetaClass→_propertiesAll traversal → for each FMetaProperty, FMetaProperty::Get() → FAtom→typed value → JSON writer outputs key-value pair. For nested objects, the process recurses into the child FMetaClass. Load path: FJsonSerializer → JSON parser reads the object → for each key, look up FMetaProperty by FName → FMetaProperty::Set() with FAtom→typed value → FMetaObject property set → CreateInstance() if root object is new. The RTTI_to_Json and Json_to_RTTI helpers are the core of the flow, handling the conversion between FMetaObject's type-erased data and JSON's value types. The transaction system can wrap this: FTransactionSerializer.BuildTransaction() → parse → FTransactionLinker.Resolve() → FJsonSerializer.Serialize() → output.

## Integration

This folder integrates with the Public Serialize folder and the RTTI system via real paths under Source/. Downstream: where the public API is defined; Source/Runtime/RTTI/ where FMetaObject/FMetaProperty/FAtom provide type-aware property traversal; where the actual JSON logic lives; Source/Runtime/Network/ and Source/Runtime/Remoting/ where JSON is the primary format for HTTP responses and API data; Source/Runtime/VFS/ where JSON save/load operations use FVirtualFileSystem. Specific paths: Source/Runtime/Serialize/Private/Json/JsonSerializer.cpp, Source/Runtime/Serialize/Public/Json/Json.h, Source/Runtime/Network/Public. JSON is also the default format for the OpenAPI/Swagger documentation served by FSwaggerEndpoint.
