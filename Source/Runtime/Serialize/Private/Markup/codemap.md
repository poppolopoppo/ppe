# Source/Runtime/Serialize/Private/Markup/

The Private Markup folder implements the concrete XML/Markup serialization logic that powers the public FMarkupSerializer. Markup.cpp and MarkupSerializer.cpp provide the actual XML generation and parsing functions, including fragment-based support and the minify option. The Private folder is the implementation detail that makes the public FMarkupSerializer work — external systems should not need to include headers from this folder, as the Public folder's FMarkupSerializer.h provides the stable API surface. The markup format supports human-readable XML (de)serialization of engine objects, with fragment-based parsing meaning partial object graphs can be (de)serialized, and a minify option that strips whitespace and comments for smaller file sizes. Markup.h and MarkupSerializer.h in the Public folder provide the core types and interface, while Markup.cpp and MarkupSerializer.cpp in the Private folder implement the concrete logic.

## Responsibility

This folder owns the concrete XML markup serialization implementation that powers the public FMarkupSerializer. Markup.cpp implements the general XML handling logic, while MarkupSerializer.cpp implements the actual XML generation/parsing logic, including the RTTI-driven property traversal, element/attribute writing, and deserialization matching. The minify post-processing step removes all whitespace outside of text content and removes XML comment nodes. The serializer handles nested elements (recursive property graphs), attributes (name-value pairs on elements), text content (element text between tags), and CDATA sections (unparsed character data). The fragment-based design means the serializer can handle partial XML documents, making it suitable for configuration scenarios where only a subset of an object's properties need to be persisted or loaded. The serializer skips properties marked as transient or readonly, and respects the public/private/readonly/dynamic/transient flags on each property.

## Design

The design of the markup serializer implementation centers on fragment-based XML parsing and the minify option. FMarkupSerializer uses FMetaClass to discover the object's properties at runtime, and FMetaProperty to read/write each property's value through FAtom type erasure. When serializing, the producer writes XML elements with property names as element names and typed values as text content or attributes. When deserializing, the consumer reads XML elements and matches them to FMetaProperty by FName. The minify option is a post-processing step that removes all whitespace outside of text content and removes XML comment nodes. The serializer handles nested elements (recursive property graphs), attributes (name-value pairs on elements), text content (element text between tags), and CDATA sections (unparsed character data). The Private implementation is designed for high-fidelity round-trips on common types while acknowledging that some type-specific details may be lost in the XML representation. The Public folder's FMarkupSerializer.h provides the stable API that external systems use, while the Private folder's Markup.cpp/MarkupSerializer.cpp contain the concrete implementation details.

## Flow

Serialization flow for Markup: User code calls FMarkupSerializer.Serialize(ctx, output) or FMarkupSerializer.Deserialize(ctx, input). Save path: FMetaObject→_propertiesAll traversal → for each FMetaProperty, read value via FMetaProperty::Get() → FAtom→typed value → XML writer outputs element/attribute with property name as element name or attribute name and typed value as text content. For nested objects, the process recurses into the child FMetaClass, writing nested XML elements. Load path: XML parser reads the document → for each element, look up FMetaProperty by FName (matching element name) → FMetaProperty::Set() with FAtom→typed value → FMetaObject property set → CreateInstance() if root object is new. The minify pass is applied after deserialization as a post-processing step. The serializer also handles attributes on elements, converting them to property values, and CDATA sections, passing the content through as raw text. The flow is: FMetaObject → FMetaProperty → FAtom → XML writer → output document.
