# Source/Runtime/Serialize/Public/Parser/

The Parser folder implements the recursive-descent parser that powers the DSL (Domain Specific Language) for the Text/Script format. The parser consumes FMatch tokens from the Lexer and builds an abstract syntax tree (AST) of FParseExpression and FParseStatement nodes, which are then evaluated by FParseContext to produce FAtom results that populate FMetaObject instances. The parser is a recursive-descent implementation with a stack-based approach for nested structures, supporting expression parsing (unary, binary, ternary operators, parentheses, casts, subscripts), statement parsing (variable export, object definitions, property statements, function calls), and tuple/list/dictionary literals. The Parser AST nodes include: TLiteral<T> for literal values (int, float, string, bool, null), FVariableExport for export/public/private variable binding, FVariableReference for $path.to.variable references, TUnaryFunction<T> for unary operators (-x, !x, etc.), TBinaryFunction<T> for binary operators (+, -, *, /, ==, &&, ||, etc.), TTernary<Test> for ternary conditionals (cond ? true : false), FObjectDefinition for object literals with property statements, FPropertyReference for obj.property access, FTupleExpr for tuple literals (a, b, c), FArrayExpr for array literals [a, b, c], FDictionaryExpr for dictionary literals {key: value...}, FCastExpr for explicit (Type)expr casts, FFunctionCall for obj.func(args...) via RTTI, and FSubscriptOperator for obj[index] with multi-type support. The parser also produces a FParseContext with a SLABHEAP(Atom) temporary allocation arena for evaluation.

## Responsibility

This folder owns the parser component that converts the token stream from the Lexer into an abstract syntax tree (AST) representing the DSL script's structure and semantics. The recursive-descent parser is organized into several major classes: FParseExpression (abstract base for all expression nodes) and its concrete subclasses (TLiteral, FVariableReference, TUnaryFunction, TBinaryFunction, TTernary, FCastExpr, FFunctionCall, FSubscriptOperator), FParseStatement (abstract base for all statement nodes) and its subclasses (FVariableExport, FObjectDefinition, etc.), FParseItem (common base with source location FSpan), and FParseContext (evaluation context with local/global scopes, atom heap, and the scope object that provides RTTI-driven type resolution). The parser's job is to correctly associate each token with the appropriate AST node, respect operator precedence and grammar rules, and produce an AST that can be evaluated by FParseContext to produce FAtom values that carry type-erased data via PTypeTraits. The parser also handles error recovery and produces FParseResult objects that carry success/failure status and error messages with source location information.

## Design

The design of the parser centers on the recursive-descent pattern with a shared FParseContext that provides the evaluation infrastructure. Each expression subclass implements a single parsing method that knows how to parse its construct from the token stream, and each statement subclass similarly knows how to parse its construct. The parser respects operator precedence through the nesting of parsing methods: primary expressions (literals, subscripts, casts) are parsed at the lowest level, unary operators at the next level, binary operators at the next, and ternary at the top. This nesting ensures that `a + b * c` is parsed correctly without explicit precedence declarations. The FParseContext provides the evaluation infrastructure: a SLABHEAP(Atom) temporary allocation arena for FAtom results, a scope object (RTTI object) for variable resolution, and local/global variable maps. The parser also produces FParseItem nodes that carry source location (FSpan from Location.h) for error reporting. The AST nodes are ref-counted via PCParseExpression = TRefPtr<FParseExpression>, and the parser handles error recovery by consuming tokens until a synchronizing token is found and producing a failed FParseResult.

## Flow

Data flow for parsing: FLexer produces a sequence of FMatch tokens → Parser consumes tokens via recursive-descent methods → AST is built of FParseExpression/FParseStatement nodes → FParseContext evaluates the AST → FAtom results are produced → FMetaObject property population via RTTI. The parsing flow begins when the parser is initialized with a token stream from the lexer. It then parses a complete script source unit (typically starting with a top-level expression or statement). The recursive-descent methods consume tokens one at a time, creating AST nodes as they go. Precedence is handled by method nesting: primary parsing → unary → binary → ternary. After the AST is fully built, FParseContext::Eval() is called, which walks the AST, evaluating each node. For FLiteral<T>, the value is directly produced as an FAtom. For FVariableReference, the parser looks up the variable in the scope object's local/global maps. For FFunctionCall, the parser invokes FMetaFunction::Invoke() via RTTI. For FPropertyReference, the parser reads the property via FMetaProperty::Get(). The result is an FAtom that carries type-erased data, which can then be used by the serializer or stored in an FMetaObject. The parser also produces FParseResult objects for error cases, including the position (line, column) where the error occurred.

## Integration

This folder integrates with adjacent modules via real paths under Source/. Downstream: Source/Runtime/Serialize/Public/Lexer/ where the FMatch token stream originates; Source/Runtime/Serialize/Private/Parser/ where the concrete parser implementation (ParseExpression.cpp, ParseContext.cpp, etc.) lives; Source/Runtime/Serialize/Public/Text/ where the Text/DSL format is the primary consumer; Source/Runtime/RTTI/ where typenames in DSL source resolve to FMetaClass/FMetaProperty during evaluation; Source/Runtime/Serialize/Public/Text/Grammar.h where grammar startup initializes parser symbols. Specific paths: Source/Runtime/Serialize/Public/Parser/ParseContext.h, Source/Runtime/Serialize/Public/Parser/ParseExpression.h, Source/Runtime/Serialize/Public/Lexer/Lexer.h, Source/Runtime/Serialize/Private/Parser/ParseExpression.cpp, Source/Runtime/Serialize/Private/Parser/ParseContext.cpp, Source/Runtime/Serialize/Public/Text/Grammar.h, Source/Runtime/Serialize/Public/Text/Grammar.h. The parser also integrates with Source/Runtime/Serialize/Public/ISerializer.h for the Text format's Save/Load pipeline.
