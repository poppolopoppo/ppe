# Source/Runtime/Serialize/Public/FAT/

The FAT (File Allocation Table) serializer folder implements the .fat format for multi-object indexed containers. FFATSerializer implements the ISerializer interface and provides a format that supports random access to individual objects within a contiguous file, with an index table that maps object indices to file offsets. The FAT format is designed for scenarios where many objects need to be stored in a single file and individual objects need to be accessed without loading the entire file into memory. The format includes an index that maps object indices to file offsets, supports compression of object data, and enables incremental load/mount cycles via the transaction system. FATFormat.h in the Private folder details the exact index structure and object layout. This format is commonly used for asset bundles, level data, and any scenario where many related objects need to be packaged together with fast random access.

## Responsibility

This folder owns the FAT format serializer that provides indexed, random-access storage of multiple engine objects within a single file. FFATSerializer implements ISerializer::Deserialize() and ISerializer::Serialize(), using the FAT index format to map object indices to file offsets. The format writes: [header with magic, version, object count][index table: for each object, [offset][size]][object data blocks]. On deserialization, the index is read first, enabling random access to any object by its index without scanning the entire file. The serializer supports compression of individual object blocks, and the transaction system can wrap FAT serialization for incremental mount/unmount cycles. The format is schema-less like the binary format but adds an index layer for multi-object access.

## Design

The design of the FAT format centers on the index table as the key enabler of random access. The index table is a sorted array where each entry contains: [object_index → file_offset, object_size]. The index is built during serialization by writing each object's data and recording its file offset and size in the index. During deserialization, the index is read first, allowing any object to be loaded by seeking to the recorded offset and reading the recorded size. The format supports compression of individual object blocks (compressed vs uncompressed flag in the index entry). The transaction system can wrap FAT operations: FTransactionSerializer.BuildTransaction() → parse → FTransactionLinker.Resolve() → FFATSerializer.Serialize() → output, with MountToDB() enabling incremental loading. The format is designed to be extensible: new fields can be added to the header/index format without breaking compatibility, and objects can be versioned. The Private folder's FATFormat.h defines the exact wire format.

## Flow

Serialization flow for FAT: User code creates an FFATSerializer with an ISerializer::Saver or ISerializer::DeserializeContext and calls Serialize() or Deserialize(). Save path: FMetaObject hierarchy traversal → for each root object, CreateInstance() → walk properties → write object data to file → record [offset, size] in index table → repeat for all objects → write index table at end of file. Load path: read header (magic, version, object count) → read index table (for each object, [offset, size]) → for each object, seek to offset → read size bytes → FMetaObject::RTTI_Load() → property population via FMetaProperty::Get() → FAtom type erasure. The transaction system can wrap this: FTransactionSerializer.LoadTransaction() → BuildTransaction → FTransactionLinker.Resolve() → FFATSerializer.Deserialize() → individual object loads with index random access. The format supports incremental mount: new objects can be added to an existing FAT file by appending data and updating the index, without re-writing the entire file.

This folder integrates with adjacent modules via real paths under Source/. Downstream consumers: Source/Runtime/RTTI/ where FFATSerializer depends on FMetaObject/FMetaProperty/FAtom for type-aware property traversal; Source/Runtime/Serialize/Private/FAT/ where FATFormat.h and the concrete serializer implementation live; Source/Runtime/VFS/ where FAT file operations use FVirtualFileSystem::Read/Write at specific offsets; Source/Runtime/Serialize/Public/ where this folder is at the public API surface; Source/Runtime/Application/ where asset bundles and level data are packaged in FAT format.
