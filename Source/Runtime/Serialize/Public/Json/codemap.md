# Source/Runtime/Serialize/Public/Json/

The JSON serializer folder implements the JSON (.json) format for engine object (de)serialization. FJsonSerializer implements the ISerializer interface and provides RTTI_to_Json and Json_to_RTTI helper functions that enable round-trip conversion between engine objects and JSON. The JSON format is human-readable and widely compatible, making it suitable for editor tools, debugging, configuration files, and cross-engine data exchange. The serializer uses FMetaClass/FMetaProperty/FAtom traversal to determine which properties to serialize and their values, producing JSON that mirrors the object's runtime state. Json.h in the Public folder and JsonSerializer.cpp/h in the Private folder provide the implementation details. This format is commonly used for save games, configuration, API responses, and any scenario where human readability or interoperability with non-engine tools is desired.

## Responsibility

This folder owns the JSON format serializer that provides human-readable (de)serialization of engine objects with full RTTI-driven type awareness. FJsonSerializer implements ISerializer::Deserialize() and ISerializer::Serialize(), using FMetaClass to traverse the object's property hierarchy and FMetaProperty to read/write each property's value. The RTTI_to_Json helper converts an FMetaObject into a JSON object (dictionary), recursively serializing each property. The Json_to_RTTI helper performs the reverse, taking a JSON object and populating an FMetaObject instance via CreateInstance() and property setters. The serializer handles primitives (int, float, bool, string, null), arrays, dictionaries, and nested objects. Round-trip fidelity is high for simple types and property graphs, but type information is encoded as property names and JSON values rather than a formal schema, so some type details (enums with flags, bitmasks, template types) may be lost or rounded on round-trip.

## Design

The design of the JSON serializer centers on RTTI-driven property traversal without requiring a per-class schema definition in the JSON file. FJsonSerializer uses FMetaClass to discover properties at runtime, FMetaProperty to get/set each property's value through FAtom type erasure, and produces JSON that mirrors the object graph. The serializer handles primitives (int as number, float as number, bool as true/false, string as string, null), arrays (JSON arrays), dictionaries (JSON objects), and nested objects (recursive JSON objects). Property names in JSON correspond to the FName of each FMetaProperty. The serializer skips properties marked as transient or readonly, and respects the public/private/readonly/dynamic/transient flags on each property. Round-trip conversion preserves value types for primitives but may lose some type-specific details (enum ordinal vs string, flag bitmasks, template instantiations). The Private folder's JsonSerializer.cpp/h implement the actual JSON generation/parsing logic, including the RTTI_to_Json and Json_to_RTTI helper functions.

## Flow

Serialization flow for JSON: User code creates an FJsonSerializer and calls Serialize(ctx, output) or Deserialize(ctx, input). Save path: FMetaObject→_propertiesAll traversal → for each FMetaProperty, read value via FMetaProperty::Get() → FAtom→typed value → JSON writer outputs key-value pair. For nested objects, the process recurses into the child FMetaClass. Load path: JSON parser reads the object → for each key, look up FMetaProperty by FName → FMetaProperty::Set() with FAtom→typed value → FMetaObject property set → CreateInstance() if root object is new. The RTTI_to_Json helper walks the object tree top-down, producing JSON; Json_to_RTTI walks JSON top-down, creating objects and setting properties. The transaction system can wrap this: FTransactionSerializer.BuildTransaction() → parse → FTransactionLinker.Resolve() → FJsonSerializer.Serialize() → output.
