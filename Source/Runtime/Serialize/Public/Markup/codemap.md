# Source/Runtime/Serialize/Public/Markup/

The Markup serializer folder implements the XML/Markup (.xml) format for engine object (de)serialization. FMarkupSerializer implements the ISerializer interface and provides fragment-based XML parsing with an optional minify option. The markup format is designed for scenarios where human-readable XML is desired, such as configuration files, level description, or data exchange with tools that understand XML. The serializer supports fragment-based parsing, meaning it can (de)serialize partial object graphs without requiring a complete document, and includes a minify option that strips whitespace and comments for smaller file sizes. Markup.h and MarkupSerializer.h in the Public folder provide the core types and interface, while Markup.cpp and MarkupSerializer.cpp in the Private folder implement the concrete logic. ## Responsibility

This folder owns the markup/XML format serializer that provides human-readable XML (de)serialization of engine objects with fragment-based support. FMarkupSerializer implements ISerializer::Deserialize() and ISerializer::Serialize(), using FMetaClass/FMetaProperty/FAtom for type-aware property traversal. The fragment-based design means the serializer can handle partial XML documents, making it suitable for configuration scenarios where only a subset of an object's properties need to be persisted or loaded. The minify option strips whitespace and XML comments to reduce file size. The serializer handles nested elements, attributes, text content, and CDATA sections. Property names in XML correspond to the FName of each FMetaProperty, and attribute values are converted to/from typed values via FAtom and PTypeTraits. The serializer skips properties marked as transient or readonly, and respects the public/private/readonly/dynamic/transient flags on each property.

## Design

The design of the markup serializer centers on fragment-based XML parsing and the minify option. FMarkupSerializer uses FMetaClass to discover the object's properties at runtime, and FMetaProperty to read/write each property's value through FAtom type erasure. When serializing, the producer writes XML elements with property names as element names and typed values as text content or attributes. When deserializing, the consumer reads XML elements and matches them to FMetaProperty by FName. The minify option is a post-processing step that removes all whitespace outside of text content and removes XML comment nodes. The serializer handles nested elements (recursive property graphs), attributes (name-value pairs on elements), text content (element text between tags), and CDATA sections (unparsed character data). The Private folder's MarkupSerializer.cpp implements the actual XML generation/parsing logic, including the minify pass.

## Flow

Serialization flow for Markup: User code creates an FMarkupSerializer and calls Serialize(ctx, output) or Deserialize(ctx, input). Save path: FMetaObject→_propertiesAll traversal → for each FMetaProperty, read value via FMetaProperty::Get() → FAtom→typed value → XML writer outputs element/attribute with property name as element name or attribute name and typed value as text content. For nested objects, the process recurses into the child FMetaClass, writing nested XML elements. Load path: XML parser reads the document → for each element, look up FMetaProperty by FName (matching element name) → FMetaProperty::Set() with FAtom→typed value → FMetaObject property set → CreateInstance() if root object is new. The minify pass is applied after deserialization as a post-processing step. The serializer also handles attributes on elements, converting them to property values, and CDATA sections, passing the content through as raw text.
