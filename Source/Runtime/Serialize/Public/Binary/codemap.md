# Source/Runtime/Serialize/Public/Binary/

The Binary serializer folder implements the compact binary format (.bin) for engine object (de)serialization. FBinarySerializer implements the ISerializer interface and handles schema-less binary encoding, making it suitable for fast load/store operations where the object layout is known at compile time but not necessarily encoded in the file. The binary format is the most lightweight of the supported formats, using compact type representation via PTypeTraits and FAtom type erasure. BinaryFormat.h in the Private folder details the low-level format structure. This serializer is the default for engine-internal save/load operations where performance and minimal file size are paramount, and it integrates with the transaction system for incremental load/mount cycles.

## Responsibility

This folder owns the binary format serializer that provides compact, fast (de)serialization of engine objects without requiring a schema definition in the file. FBinarySerializer implements ISerializer::Deserialize() and ISerializer::Serialize() using schema-less binary encoding where type information is carried via FAtom (void* + PTypeTraits) at runtime. The format is designed for engine-internal use cases where save/load performance and minimal file size are critical, such as editor project files, runtime state snapshots, and network snapshots. BinaryFormat.h in the Private folder details the format structure. The binary serializer does not perform any textual or human-readable encoding — it is purely binary, making it unsuitable for manual inspection or cross-engine compatibility, but ideal for the performance-critical path.

## Design

The design of the binary format centers on compactness and speed. FBinarySerializer uses PTypeTraits to encode type information alongside data, enabling type-aware read/write without a per-file schema. The format encodes each property as: [property_offset_or_id][typed_data_via_FAtom], with variable-length integers for efficient encoding of large arrays and strings. The serializer walks FMetaClass->_propertiesAll to determine which properties to serialize and their offsets, using FMetaProperty::Get() to read/write typed data through FAtom. The format supports nested objects, arrays, and maps, with recursive property traversal. BinaryFormat.h in the Private folder defines the exact wire format, including magic number, version, property count, and property data blocks. The serializer is designed to be forward-compatible: new properties are ignored on load if the version doesn't match, and removed properties are simply not written on save.

## Flow

Serialization flow for the Binary format: User code creates an FBinarySerializer with an ISerializer::Saver or ISerializer::DeserializeContext and calls Serialize() or Deserialize(). The serializer walks the FMetaClass hierarchy starting from the root object, iterating _propertiesAll and _propertiesSelf for each class. For each property, FMetaProperty::Get() reads/writes the typed data through an FAtom wrapper. The FAtom bundles a void* data pointer with PTypeTraits type information, enabling the serializer to know the type and size of each data element without a schema. The serializer outputs/writes: [magic_number][version][property_count][for each property: property_index][property_type][property_data]. Deserialization reverses this process: read magic/version, read property count, for each property read type and data, create FMetaObject instance via CreateInstance(), set property values via FMetaProperty::Set(). The transaction system can wrap this: FTransactionSerializer.BuildTransaction() → parse → FTransactionLinker.Resolve() → FBinarySerializer.Serialize() → output.
