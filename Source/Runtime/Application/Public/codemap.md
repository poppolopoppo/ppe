# Source/Runtime/Application/Public/

## Responsibility
This folder group encompasses the public-facing application layer of the PPE engine, containing the core abstractions that other subsystems depend on. Exposes FApplicationBase, FApplicationWindow, FInputAction, FGenericPlatformApplicationMisc, and the FWindow class through public headers, defining the modular domain-driven architecture, service registration boundaries, and the public API surface that application code, HAL implementations, and concrete programs (ShaderToy, VoxelCube, WindowTest) depend on. All classes use RTTI_DECL for runtime type identification and TPtrRef for ref-counted dependencies.

## Design
The public folders (Application, Input, Input/Device, Input/Action, HAL, Window, Viewport) expose abstracted interfaces while the private folders encapsulate concrete implementations behind those interfaces. FApplicationBase declares pure virtual methods OnInitialize, OnDutyCycle, and OnShutdown, registered via RTTI_MODULE_DECL. FApplicationWindow extends FApplicationBase adding window ownership, IWindowListener integration, and message loop management. The modular domain (FModularDomain) drives component activation order. Pure virtual interfaces ( = delete) enforce concrete implementation in platform-specific subclasses. FWindow owns the platform-specific window handle and implements IWindowListener for callback routing. All classes support EXTERN_LOG_CATEGORY for structured tracing.

## Flow
App startup calls FModularDomain::Initialize → component modules register → FApplicationWindow::OnInitialize platform services initialize, create the platform window via the HAL layer, and acquire IInputService, IRHIService, and IWindowService through the modular domain. The duty-cycle loop calls OnDutyCycle each frame, which polls input, advances the RHI frame graph, and processes UI overlay. OnShutdown tears down modules in reverse order, destroys the window, and releases platform resources. Derived apps (FShaderToyApp, FVoxelCubeApp, FWindowTestApp) override lifecycle methods while calling base class equivalents. Input flow: device poll → state fill → action binding evaluation → result delivery. UI flow: NewFrame → widget rendering → dockspace render.
