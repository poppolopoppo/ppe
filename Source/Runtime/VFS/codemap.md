# Source/Runtime/VFS/

## Responsibility
The VFS folder provides a virtual file system abstraction that decouples file operations from the native filesystem. It implements a trie-based mount point registry (`FVirtualFileSystemTrie`) that maps virtual aliases to concrete file system components, enabling package-style resource loading, overlay filesystems, and platform-independent path resolution. The singleton `FVirtualFileSystem` exposes unified APIs (`ReadAll`, `WriteAll`, `Copy`, `Compress`, `Mount`, `Enumerate*`) while individual mount components implement read (`IVirtualFileSystemComponentReadable`), write (`IVirtualFileSystemComponentWritable`), and combined read-write (`IVirtualFileSystemComponentReadWritable`) interfaces. Native filesystem access is encapsulated by `FVirtualFileSystemNativeComponent`, which resolves virtual aliases to real paths. This abstraction layer is used by serialization, remoting, and all modules requiring portable data access.

## Design
Key patterns include a trie-based mount registry using `ASSOCIATIVE_VECTORINSITU<FMountingPoint, PVirtualFileSystemComponent, 8>` for sorted vector-map lookups, component composition via separate readable/writable/readwritable interfaces, and alias resolution through `Unalias()` conversions. The `FVirtualFileSystemComponent` base class defines a protected constructor taking an `FDirpath` alias and pure virtual `Readable()`/`Writable()`/`ReadWritable()` accessors. Standard mount points (`DataDir()`, `ProcessDir()`, `SavedDir()`, `SystemDir()`, `TmpDir()`, `UserDir()`, `WorkingDir()`) are provided by the `FVFSModule` module. Thread safety is ensured by `FReadWriteLock` on trie operations. The component hierarchy supports the small-buffer optimization pattern where components can choose their internal storage strategy, and the native component maps virtual paths to native filesystem operations via `FWString` target paths.

## Flow
Data flow begins with `FVirtualFileSystem::Get()` (singleton) which delegates to `FVirtualFileSystemTrie`. Mount operations route through `Mount()`/`MountNativePath()` on the trie, storing component references keyed by `FMountingPoint` alias. File operations flow as: `FVirtualFileSystem::ReadAll/WriteAll` → `Trie` lookup → component's `OpenReadable`/`OpenWritable`/`OpenReadWritable` → platform-specific implementation. Enumerate/Glob/Match operations iterate trie nodes, aggregating results across all mounted components. Unmount removes the component from the `_nodes` vector. The `FVFSModule` startup registers standard mount points (`DataDir`, `ProcessDir`, etc.) by creating native components with well-known aliases. All trie modifications are protected by `FReadWriteLock` for thread safety.

## Integration
Connects to `Source/Runtime/Remoting/` via `FRTTIEndpoint` which could expose VFS operations through custom HTTP endpoints; connects to `Source/Runtime/Serialize/` as `FTransactionSerializer` uses `FVirtualFileSystem` for source file access during deserialization; connects to `Source/Runtime/Network/` as HTTP endpoints may need to read configuration files from the virtual filesystem.
