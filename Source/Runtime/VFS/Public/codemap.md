# Source/Runtime/VFS/Public/

## Responsibility
The Public VFS folder exposes the virtual file system API surface implemented by the PPE runtime, providing types and classes usable by client code and other modules for portable file operations across platforms. This folder provides `FVirtualFileSystem` singleton entry point, `FVirtualFileSystemTrie` for mount point registry, `FVirtualFileSystemComponent` abstract base, and the component interfaces `IVirtualFileSystemComponentReadable`, `IVirtualFileSystemComponentWritable`, `IVirtualFileSystemComponentReadWritable`. The folder serves as the primary include point (`VFS/Public/VirtualFileSystem.h`) for all VFS declarations, with the design ensuring that client code depends on stable abstractions while implementation details remain in the Private subfolder hierarchy. `FVFSModule` provides standard mount points (`DataDir()`, `ProcessDir()`, `SavedDir()`, `SystemDir()`, `TmpDir()`, `UserDir()`, `WorkingDir()`) as well-known virtual aliases.

## Design
Key patterns include the trie-based mount registry pattern using `ASSOCIATIVE_VECTORINSITU<FMountingPoint, PVirtualFileSystemComponent>` for sorted vector-map lookups of mounting points to components, enabling efficient enumeration and glob operations; the component composition pattern where separate readable, writable, and readwritable interfaces allow components to implement only the operations they support, with `FVirtualFileSystemComponent` as the protected-base class taking an `FDirpath` alias; the alias resolution pattern where `Unalias()` converts virtual paths to native paths per component, enabling package-style resource loading and overlay filesystems; and the standard mount points pattern where `FVFSModule` registers well-known directories at module startup. Thread safety is ensured by `FReadWriteLock` on trie operations, allowing concurrent reads and serialized writes. All public types are designed for cross-platform compatibility, with native path mapping encapsulated by `FVirtualFileSystemNativeComponent`.

## Flow
Client code includes `Source/Runtime/VFS/Public/VirtualFileSystem.h` to access the singleton `FVirtualFileSystem::Get()`. Mount operations: call `FVirtualFileSystem::Mount(alias, component)` → `FVirtualFileSystemTrie.Mount()` → stores `PVirtualFileSystemComponent` keyed by `FMountingPoint` alias in `_nodes` vector; file read operations: `FVirtualFileSystem::ReadAll(filename)` → `Trie.Lookup(filename)` → finds component → `component->OpenReadable(filename)` → component reads from native path; enumerate/glob/match: iterate trie nodes, aggregate results across all mounted components; unmount: `FVirtualFileSystem::Unmount(alias)` → `Trie.Unmount()` → removes component from `_nodes`. Standard mount points: `FVFSModule::Startup()` creates `FVirtualFileSystemNativeComponent` instances with aliases `DataDir`, `ProcessDir`, `SavedDir`, `SystemDir`, `TmpDir`, `UserDir`, `WorkingDir` and mounts them via `FVirtualFileSystem::Mount()`.

## Integration
Connects to `Source/Runtime/VFS/Private/` as all public VFS types have corresponding Private implementation details under `VFS/Private/`. Connects to `Source/Runtime/Serialize/` as `FTransactionSerializer` uses `FVirtualFileSystem` for source file access during deserialization. Connects to `Source/Runtime/Remoting/` as `FRTTIEndpoint` could expose VFS operations through custom HTTP endpoints. Connects to `Source/Runtime/Network/` as HTTP endpoints may need to read configuration files from the virtual filesystem. Real paths: `Source/Runtime/VFS/Public/VirtualFileSystem.h`, `Source/Runtime/VFS/Public/VirtualFileSystemTrie.h`, `Source/Runtime/VFS/Public/VirtualFileSystemComponent.h`, `Source/Runtime/VFS/Public/VirtualFileSystemNativeComponent.h`, `Source/Runtime/VFS/Public/VFSModule.h`, `Source/Runtime/VFS/Public/VirtualFileSystem_fwd.h`.
