# Source/Runtime/RTTI/Public/RTTI/

The Public RTTI sub-folder provides the foundational type definitions, forward declarations, and macro infrastructure that underpins the entire reflection system. RTTI.h, RTTI_fwd.h, and RTTIModule.h contain the core type definitions (FMetaClass, FMetaProperty, FMetaEnum, FMetaFunction, FMetaObject, FMetaDatabase), forward declarations, and the RTTI_MODULE_DECL macro used across all modules to register their types into the singleton FMetaDatabase. Any module that wishes to participate in the reflection system must emit RTTI_MODULE_DECL in its .cpp, which causes the compiler to instantiate and register the module's FMetaClass, FMetaEnum, FMetaFunction, and FMetaProperty objects. The forward header RTTI_fwd.h minimizes compile-time dependencies by declaring types forward-declared, while RTTI.h contains the full definitions. This folder is the entry point for any code that #includes <RTTI.h> or <RTTIModule.h> — it is the smallest possible surface area needed to start using reflection, and all deeper metadata lives in the Private/ and Public/ sub-folders of the broader RTTI and Serialize hierarchies.

## Responsibility

This folder owns the foundational type definitions and macro infrastructure that make RTTI usable across the engine. RTTI.h defines the core types (FMetaClass, FMetaProperty, FMetaEnum, FMetaFunction, FMetaObject, FMetaDatabase) that every other RTTI component relies on. RTTI_fwd.h provides minimal forward declarations to reduce header dependency chains. RTTIModule.h defines the RTTI_MODULE_DECL macro that each module's .cpp must invoke to register its types into the global FMetaDatabase. Without this folder, no module could register its reflection data, and the FMetaDatabase would be empty. The macro system (RTTI_CLASS_HEADER, RTTI_ENUM_HEADER, RTTI_FUNCTION_HEADER, RTTI_PROPERTY_HEADER, RTTI_OBJECT_HEADER) expands in module .cpp files to create the concrete metadata objects that populate FMetaDatabase. This folder ensures that the registration API is stable, DLL-safe (DLL_IMPORT/EXPORT), and sufficient for all downstream consumers.

## Design

The design is minimal and header-focused. RTTI.h contains the canonical type definitions for all FMeta* types, using DLL_IMPORT/EXPORT for cross-DLL compatibility. RTTI_fwd.h forward-declares only what is needed, reducing compilation times for code that doesn't need full definitions. The RTTI_MODULE_DECL macro in RTTIModule.h is the sole integration point: modules place `IMPLEMENT_MODULE(RTTI, ModuleName)` or similar, which expands the macro to register all their FMetaClass/FMetaEnum/FMetaFunction/FMetaProperty objects into FMetaDatabase. The macro system is designed so that adding a new class to a module requires only adding RTTI_CLASS_HEADER to the class declaration and the module init line — no other changes needed. All types are designed for safe static initialization order, with FMetaDatabase as a singleton guaranteed to be alive after module init.

## Flow

Flow begins at module startup: the module's .cpp file includes RTTI.h and calls RTTI_MODULE_DECL (typically as part of IMPLEMENT_MODULE or a module-specific init function). The macro expansion registers the module's FMetaClass, FMetaEnum, FMetaFunction, and FMetaProperty objects into the singleton FMetaDatabase. After all modules have been initialized, FMetaDatabase contains the complete type hierarchy. At runtime, code can include RTTI.h and use the public types immediately — no further initialization needed. Serialization flow: ISerializer → FMetaDatabase→FindClass→FMetaClass→_propertiesAll→FMetaProperty→Get()→FAtom→ISerializer output. Remoting: FRTTIEndpoint → FMetaDatabase → JSON. The flow is linear: module init → FMetaDatabase population → runtime queries → property access → serialization/remoting output.

## Integration

This folder integrates with the broader RTTI hierarchy and all downstream modules via real paths under Source/. Downstream consumers: Source/Runtime/RTTI/Public/ where FMetaClass/FMetaProperty/FMetaObject/etc. are defined and used; Source/Runtime/RTTI/Private/ where the concrete implementations (MetaClass.cpp, MetaDatabase.cpp, etc.) live; Source/Runtime/Serialize/Public/ and Source/Runtime/Serialize/Private/ where all serializers depend on the RTTI type definitions for property-level (de)serialization; which reads FMetaDatabase through these type definitions. Specific paths: Source/Runtime/RTTI/Public/RTTI.h, Source/Runtime/RTTI/Public/RTTI_fwd.h, Source/Runtime/RTTI/Public/RTTIModule.h, Source/Runtime/RTTI/Private/MetaClass.cpp, Source/Runtime/RTTI/Private/MetaDatabase.cpp. The RTTI_MODULE_DECL macro is the integration point that connects this folder to every module in the project.
