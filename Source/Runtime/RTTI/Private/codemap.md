# Source/Runtime/RTTI/Private/

The Private RTTI folder implements the concrete metadata that populates the singleton FMetaDatabase and powers all reflection-driven systems across the engine. This is where the macro-registered type descriptors (FMetaClass, FMetaProperty, FMetaEnum, FMetaFunction, FMetaObject) get their substance: MetaClass.cpp, MetaDatabase.cpp, MetaObject.cpp, MetaProperty.cpp, MetaEnum.cpp, MetaFunction.cpp, and MetaTransaction.cpp contain the actual implementation of property enumeration, database management, ref-counted object lifetime, and transaction state machine logic. The folder also houses the RTTI module registration macros (RTTI_CLASS_HEADER, RTTI_ENUM_HEADER, RTTI_MODULE_DECL) that compile-time populate FMetaDatabase with all known classes, enums, and modules. Without this folder, the public types in Source/Runtime/RTTI/Public/ would be empty shells — the FMetaDatabase would be empty, FMetaObject would have no properties or functions, and all serialization, remoting, and VFS operations would fail due to missing type descriptors.

## Responsibility

This folder owns the implementation that fills the FMetaDatabase singleton and maintains the complete runtime reflection hierarchy. MetaDatabase.cpp implements the FMetaDatabase singleton with read/write guards (FMetaDatabaseReadable, FMetaDatabaseReadWritable) and HashMap-based lookups for classes, enums, objects, transactions, and modules. MetaClass.cpp implements property enumeration (_propertiesAll, _propertiesSelf), inheritance traversal (Parent()), and CreateInstance(). MetaObject.cpp implements ref-counting, load/unload virtual methods, and _outer transaction linking. MetaProperty.cpp implements offset-based property get/set with traits awareness. MetaEnum.cpp implements value↔string conversion and flags handling. MetaFunction.cpp implements the invoke thunk for runtime function calls. MetaTransaction.cpp implements the state machine (Unloaded→Loading→Loaded→Mounting→Mounted) and _topObjects linearization. All concrete metadata objects are registered via RTTI_MODULE_DECL macros in each module's .cpp file, which emit the class descriptors into the global FMetaDatabase.

## Design

Key design decisions center on the ref-counted FMetaObject with _outer linking to SCMetaTransaction, creating an ownership tree that mirrors the transaction lifecycle (Unloaded→Loading→Loaded→Mounting→Mounted). FMetaDatabase uses ASSOCIATIVE_VECTORINSITU hash maps for _classes, _enums, _objects, _transactions, and _modules, providing sorted iteration and fast lookup. Property data flows through FAtom (void* + PTypeTraits), enabling type-erased read/write across heterogeneous types. MetaTransaction implements a linearized FLinearizedTransaction for cross-reference resolution during deserialization. The facet system (FMetaClassFacet, etc.) is implemented here as a mechanism for adding behavior to FMetaClass without modifying the core struct. Small-buffer optimization in FAny (3×intptr_t in-situ) is defined in the private detail headers. All implementations are DLL-safe with DLL_IMPORT/EXPORT guards and are not intended for external consumption — external systems should use the public API in Source/Runtime/RTTI/Public/.

## Flow

Flow begins when each module's RTTI_MODULE_DECL macro expands in the module's .cpp, registering FMetaClass/FMetaEnum/FMetaFunction/FMetaProperty instances into the singleton FMetaDatabase. At runtime, FMetaDatabase::Get()->FindClass(name) returns a FMetaClass*, whose _propertiesAll (HashMap) or _propertiesSelf (VectorInSitu) are enumerated. FMetaProperty::Get() reads data at the stored offset via PTypeTraits, producing an FAtom. FMetaFunction::Invoke() executes the thunk with FAny parameter values. FMetaObject::RTTI_Load()/RTTI_Unload() virtual methods are called during transaction Mount/Unmount. FMetaTransaction::Load() → Mount() → Mounted, with FLinearizedTransaction resolving imported/loaded/exported refs. Serialization: FTransactionSerializer → BuildTransaction → FMetaObject property traversal → FAtom → ISerializer output. Remoting: FRTTIEndpoint → FMetaDatabase → JSON. Transaction lifecycle: FMetaTransaction Unmount() → Unload() → Unloaded, with _linearized flattening cross-references.

## Integration

This folder integrates closely with the Public RTTI folder and all other Runtime modules via real paths under Source/. Downstream: Source/Runtime/RTTI/Public/ where the public type descriptors (FMetaClass, FMetaProperty, etc.) are forwarded from private implementations; Source/Runtime/Serialize/Public/ and Source/Runtime/Serialize/Private/ where all format serializers (FBinarySerializer, FJsonSerializer, FTextSerializer, FFATSerializer, FMarkupSerializer) depend on FMetaObject/FMetaProperty for property-level (de)serialization; reads the FMetaDatabase for auto-generated REST API; Source/Runtime/VFS/ where FMetaObject enables transactional file operations; Source/Runtime/Network/ where serialization of RTTI data flows through JSON. Specific paths: Source/Runtime/Serialize/Private/Binary/BinaryFormat.h, Source/Runtime/Serialize/Public/Json/JsonSerializer.h, Source/Runtime/Serialize/Public/Text/TextSerializer.h, Source/Runtime/VFS/Public/VirtualFileSystem.h The transaction system (MetaTransaction.cpp) also integrates with Source/Runtime/Serialize/Private/TransactionLinker.cpp for import resolution during deserialization.
