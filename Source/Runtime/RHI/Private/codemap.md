# Source/Runtime/RHI/Private/

## Responsibility
The Private RHI folder contains the implementation details, concrete API encapsulators, and internal types not intended for public consumption. This folder implements the API-specific backends (Vulkan and DX11) behind the IDeviceAPIEncapsulator interface, defines the FDeviceAPIDependantResourceBuffer abstract base and its concrete subclasses, and provides the internal resource management logic used by the entire rendering subsystem. The Private RHI is where API-specific details are fully realized, including Vulkan memory allocation, descriptor binding, and command buffer recording.

## Design
The Private RHI implements two concrete encapsulators: DX11DeviceAPIEncapsulator and FVulkanDeviceAPI, both fulfilling the IDeviceAPIEncapsulator interface. FDeviceAPIDependantResourceBuffer is the abstract base for API-specific buffer implementations, with Vulkan and DX11 subclasses handling resource creation, mapping, and destruction. The design incorporates reference-counted resource management through FDeviceResourceSharable, enabling pooling and deduplication across rendering modules. Bit-packed metadata (stride/mode/usage in a single u32) is implemented via Meta::TBit at the implementation level. Memory allocation for RHI resources defaults to TMemoryPool but can be customized via the allocator interface.

## Flow
Resource creation flows through the encapsulator's Create() method, which dispatches to the appropriate API-specific implementation. Buffer data transfers (GetData, SetData, CopyFrom, CopySubPart) virtual-dispatch through FDeviceResource to the API backend. The FCommandBufferBatch class collects command submissions and records them into API-specific command buffers. The DX11 path records immediate-mode DX11 commands; the Vulkan path records command buffer submissions that are later submitted to queues. Resource destruction follows the Destroy() factory pattern, which releases API-specific handles and decrements reference counts on sharable resources.

## Integration
This folder integrates directly with Source/Extensions/RHIVulkan/ through the FVulkanDeviceAPI class, which implements IDeviceAPIEncapsulator for Vulkan. Buffer resources (FDeviceAPIDependantResourceBuffer Vulkan subclasses) are consumed by the Vulkan frame graph (TVulkanFrameTask<_Task>) and the command buffer system (FVulkanCommandBuffer). Memory allocation draws from TMemoryPool in Source/Runtime/Core/Public/Memory/ and TSlabHeap in Source/Runtime/Core/Public/Allocator/. The FCommandBufferBatch class in Source/Extensions/RHIVulkan/Public/Vulkan/Command bridges RHI submissions to Vulkan command buffers. The swapchain and presentation flow connects through FVulkanSwapchain in Source/Extensions/RHIVulkan/Private/Vulkan/Instance/.
