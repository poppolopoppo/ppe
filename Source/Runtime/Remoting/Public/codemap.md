# Source/Runtime/Remoting/Public/

## Responsibility
The Public Remoting folder exposes the remoting endpoint API surface implemented by the PPE runtime, providing types and classes usable by client code and other modules for HTTP-based service exposure. This folder provides `IRemotingEndpoint` interface, `FBaseEndpoint` base class, `FRTTIEndpoint` for auto-generated RTTI exposure, `FSwaggerEndpoint` for OpenAPI/Swagger UI, `FOpenAPI` for OpenAPI 3.0 document building, and `FRemotingContext` per-request context. The folder serves as the primary include point (`Remoting/Public/RemotingEndpoint.h`) for all remoting declarations, with the design ensuring that client code depends on stable endpoint interfaces while implementation details remain in the Private subfolder hierarchy. `FRemotingModule` owns the `FRemotingService` and manages module lifecycle.

## Design
Key patterns include the endpoint registry pattern where `FRemotingServer` maintains `TThreadSafe<FEndpointMap, EThreadBarrier::RWLock>` with read-write lock synchronization, storing `std::variant<URemotingEndpoint, PBaseEndpoint>` entries for type-safe endpoint management; the auto-generated REST pattern where `FRTTIEndpoint` mirrors the entire `FMetaDatabase` using mirror types (`FRTTIClass`, `FRTTIEnum`, `FRTTIProperty`, `FRTTIFunction`, `FRTTIParameter`, `FRTTIModule`, `FRTTITransaction`) cached thread-safely by `FRTTITraitsCache` (HASHMAP); the OpenAPI-first pattern where `FOpenAPI` builds the OpenAPI 3.0 document structurally via `DefineRTTIMetaClass()`, `Traits()`, and `DefineRTTISchemas()`, with schemas for traits, objects, operations, and parameters; the Swagger UI pattern where `FSwaggerEndpoint` serves the Swagger UI HTML page and renders the OpenAPI spec; the variant-based endpoint dispatch pattern where `IRemotingEndpoint::EndpointDispatchIFP()` handles path/method routing to the correct operation; and the per-request context pattern where `FRemotingContext` carries cookie/post/query maps, localhost address, endpoint enumerator, and a sync event for callback coordination. All public types are designed for cross-module use, with `FRemotingModule.Start()` registering default endpoints (`FRTTIEndpoint`, `FSwaggerEndpoint`).

## Flow
Bootstrap flow: `FRemotingModule.Get()` → `FRemotingModule.Start(domain)` → `FRemotingServer.Start()` → registers default endpoints (`FRTTIEndpoint`, `FSwaggerEndpoint`) → `FHttpServer.Start(workerCount)` begins listening on `FAddress` localhost; request cycle: `FHttpServer.OnRequest` → `FRemotingServer.Route()` → iterates `_endpoints` variant values (read-lock) → `IRemotingEndpoint.EndpointProcess(ctx)` → `EndpointDispatchIFP()` path/method routing → `PrivateEndpointProcess(ctx, relativePath)` or `PrivateEndpointOpenAPI(api)` dispatch → response serialization via `FOpenAPI`/`FJsonSerializer`; for `FRTTIEndpoint`: `EndpointProcess` dispatches to 6 operation categories (Traits, Objects, Transactions, Modules, Classes, Enums) by reading from `FMetaDatabase` and serializing via `FOpenAPI`; for `FSwaggerEndpoint`: `PrivateEndpointOpenAPI()` populates `FOpenAPI`; `PrivateEndpointProcess()` serves Swagger UI HTML with embedded spec; tick flow: `FRemotingServer.Tick(dt)` processes pending `FRemotingCallback` events via `TThreadSafeEvent<FRemotingCallback, true>.Wait()`; shutdown flow: `FRemotingModule.Shutdown()` → `FRemotingServer.Shutdown()` → `FHttpServer.Shutdown()` → unregisters all endpoints. Per-request: `FRemotingContext` is constructed with cookie/post/query maps and localhost `FAddress`, a sync event waits for callback completion, and the context is destroyed after response serialization.

## Integration
Connects to `Source/Runtime/Network/` as `FRemotingServer` inherits `Network::FHttpServer`, uses `FHandShaker` for connection management, and `FRemotingContext` carries `Network::FAddress` localhost and `FRemotingCookieMap`/`FRemotingPostMap`/`FRemotingQueryMap`. Connects to `Source/Runtime/RTTI/` as `FRTTIEndpoint` reads entire `FMetaDatabase` (classes, enums, objects, transactions, modules) and exposes them via auto-generated REST API; responses serialized via `FOpenAPI` and `FJsonSerializer`; `FOpenAPI.DefineRTTIMetaClass()` traverses `FMetaClass` hierarchy. Connects to `Source/Runtime/VFS/` as custom endpoints may expose file system operations; `FOpenAPI` may reference VFS-mounted resources. Real paths: `Source/Runtime/Remoting/Public/RemotingEndpoint.h`, `Source/Runtime/Remoting/Public/Remoting/RTTIEndpoint.h`, `Source/Runtime/Remoting/Public/Remoting/OpenAPI.h`, `Source/Runtime/Remoting/Public/Remoting/SwaggerEndpoint.h`, `Source/Runtime/VFS/Public/VirtualFileSystem.h`, `Source/Runtime/Remoting/Public/Remoting/BaseEndpoint.h`.
