# Source/Runtime/Remoting/Public/Remoting/

## Responsibility
The Remoting/Public folder provides the public-facing remoting infrastructure that owns the `FRemotingServer`, endpoint registration, and HTTP routing. It exposes a pluggable endpoint system via `IRemotingEndpoint` interface, auto-generated REST API coverage through `FRTTIEndpoint` for the entire RTTI database, and OpenAPI/Swagger UI generation via `FOpenAPI`/`FSwaggerEndpoint`. The `FRemotingModule` owns the `FRemotingService` lifecycle, and `FRemotingServer` acts as an `FHttpServer` wrapper that registers and routes requests to configured endpoints. This folder is the primary integration point for exposing application functionality and RTTI metadata over HTTP without manual route definition.

## Design
Key patterns include the endpoint variant registry in `FRemotingServer` using `std::variant<URemotingEndpoint, PBaseEndpoint>` stored in a `FLATMAP_INSITU<Remoting, Network::FName, FRegisteredEndpoint, 8>` for ordered iteration. The `IRemotingEndpoint` base class defines the contract with `EndpointPrefix()`, `EndpointOpenAPI(FOpenAPI*)`, and `EndpointProcess(const FRemotingContext&)` pure virtual methods. `FBaseEndpoint` provides common base functionality. `FRTTIEndpoint` auto-generates REST operations from the entire `FMetaDatabase` (classes, enums, objects, transactions, modules) without manual route definition. `FOpenAPI` builds the OpenAPI 3.0 document JSON structurally via `DefineRTTISchemas()` and per-type schema definitions (`DefineRTTIMetaClass`, `Traits`). `FSwaggerEndpoint` serves the Swagger UI HTML page and renders the OpenAPI spec generated by `FOpenAPI`. Parameter locations (Body, Cookie, FormData, Headers, Path, Query) are mapped from OpenAPI annotations. The endpoint dispatch mechanism uses `EndpointDispatchIFP()` for path/method routing to `FProcessFunc` callbacks with `FOperation` descriptors containing path, parameters, and method.

## Flow
Initialization flows: `FRemotingModule.Start()` → `FRemotingServer.Start()` → register endpoints (`FRTTIEndpoint`, `FSwaggerEndpoint`, custom `IRemotingEndpoint` instances) → `FHttpServer.Start(workers)` begins request handling. Request flow: `FHttpServer.OnRequest` → `FRemotingServer.Route()` → `IRemotingEndpoint.EndpointProcess(ctx)` → `EndpointDispatchIFP()` path/method matching → `PrivateEndpointProcess()` or `PrivateEndpointOpenAPI()` dispatch. For `FRTTIEndpoint`: `EndpointProcess` dispatches to operations (Traits, Objects, Classes, Enums, Modules, Transactions) by reading from `FMetaDatabase` and serializing responses via `FOpenAPI`/`FJsonSerializer`. For `FSwaggerEndpoint`: `PrivateEndpointOpenAPI()` populates `FOpenAPI` struct, `PrivateEndpointProcess()` serves Swagger UI HTML. Response serialization flows through `FRemotingContext` which carries `FRemotingCookieMap`, `FRemotingPostMap`, `FRemotingQueryMap`, and a `TPublicEvent<FRemotingCallback>` sync event. `FRemotingServer.Tick()` processes pending callbacks.

## Integration
Connects to `Source/Runtime/Network/` as `FRemotingServer` inherits `Network::FHttpServer` and uses `FHandShaker` for connection management; `FHttpServer.Start()` provides the TCP endpoint; `FRemotingContext` carries `Network::FAddress` localhost. Connects to `Source/Runtime/RTTI/` as `FRTTIEndpoint` reads entire `FMetaDatabase` (classes, enums, objects, transactions, modules) and exposes them via auto-generated REST API; responses serialized via `FOpenAPI` and `FJsonSerializer`. Connects to `Source/Runtime/VFS/` as custom endpoints may expose file system operations; `FOpenAPI` may reference VFS-mounted resources. Neighbor paths: `Source/Runtime/Network/Public/Http/Server.h`, `Source/Runtime/RTTI/Public/RTTI/Module.h`, `Source/Runtime/RTTI/Public/MetaDatabase.h`, `Source/Runtime/VFS/Public/VirtualFileSystem.h`.
