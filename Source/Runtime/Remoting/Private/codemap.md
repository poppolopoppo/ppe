# Source/Runtime/Remoting/Private/

## Responsibility
The Private Remoting folder implements the detail-level infrastructure underlying the public remoting API, containing endpoint detail implementations, context management, and module lifecycle logic not exposed in the public header hierarchy. This folder provides the concrete `FRTTIEndpoint::` mirror database traversal, `FOpenAPI::` document building detail, `FSwaggerEndpoint::` Swagger UI rendering, `FBaseEndpoint::` common endpoint functionality, and `FRemotingContext::` per-request structure. The design separates public endpoint interface (`Source/Runtime/Remoting/Public/`) from private detail (`Source/Runtime/Remoting/Private/`), enabling stable endpoint contracts while isolating RTTI database traversal, OpenAPI document construction, and per-request context management. `FRemotingModule` singleton owns the `FRemotingService` and manages module startup/shutdown.

## Design
Key patterns include the RTTI mirror pattern where `FRTTIEndpoint` mirrors the entire `FMetaDatabase` using `FRTTIClass`, `FRTTIEnum`, `FRTTIProperty`, `FRTTIFunction`, `FRTTIParameter`, `FRTTIModule`, `FRTTITransaction` mirror types, with `FRTTITraitsCache` (HASHMAP) providing thread-safe caching of `PTypeTraits` → `PRTTITraits` conversions for safe exposure of RTTI data via REST; the OpenAPI document builder pattern where `FOpenAPI` constructs the OpenAPI 3.0 document via `DefineRTTIMetaClass()` traversing `FMetaClass` hierarchy, `DefineTraitSchemas()` for trait definitions, `DefineOperationSchemas()` for per-operation schemas, and `DefineParameterSchemas()` for parameter locations (body, cookie, formData, headers, path, query); the variant-based endpoint registry pattern where `FRemotingServer._endpoints` stores `std::variant<URemotingEndpoint, PBaseEndpoint>` with `TThreadSafe<FEndpointMap, EThreadBarrier::RWLock>` read-write lock; the per-request context pattern where `FRemotingContext` carries `FRemotingCookieMap`, `FRemotingPostMap`, `FRemotingQueryMap`, `FRemotingAddress` localhost, an `FEndpointEnumerator` for the requesting endpoint, and a `TThreadSafeEvent<FRemotingCallback, true>` sync event for callback coordination; the base endpoint pattern where `FBaseEndpoint` provides common functionality `EndpointPrefix()`, `EndpointOpenAPI()`, `EndpointProcess()` with derived classes `FRTTIEndpoint`, `FSwaggerEndpoint`, `FProcessEndpoint` implementing the virtual methods; the variant dispatch pattern where `IRemotingEndpoint::EndpointDispatchIFP()` routes by path and HTTP method to the correct operation. All private types are detail implementations not for direct client consumption.

## Flow
Bootstrap flow: `FRemotingModule.Start()` → `FRemotingServer.Start()` → registers default private endpoints (`FRTTIEndpoint`, `FSwaggerEndpoint`) in `_endpoints` variant map with read-write lock → `FHttpServer.Start(workerCount)` begins listening; request cycle: `FHttpServer.OnRequest` → `FRemotingServer.Route()` (read-lock iterates `_endpoints`) → `IRemotingEndpoint.EndpointProcess(ctx)` → `EndpointDispatchIFP()` routes by path/method → `PrivateEndpointProcess(ctx, relativePath)` for `FRTTIEndpoint` dispatches to 6 categories (Traits, Objects, Transactions, Modules, Classes, Enums) by reading from `FMetaDatabase` via mirror types and serializing via `FOpenAPI`/`FJsonSerializer`; for `FSwaggerEndpoint`: `PrivateEndpointOpenAPI()` populates `FOpenAPI` structure; `PrivateEndpointProcess()` serves Swagger UI HTML with embedded spec; tick: `FRemotingServer.Tick(dt)` processes pending `FRemotingCallback` events via `TThreadSafeEvent<FRemotingCallback, true>.Wait()` — the sync event blocks until callback completes; shutdown: `FRemotingModule.Shutdown()` → `FRemotingServer.Shutdown()` → `FHttpServer.Shutdown()` → unregisters all endpoints from `_endpoints`. Per-request: `FRemotingContext` constructed with cookie/post/query maps, localhost address, endpoint enumerator, sync event waits for callback, context destroyed after response serialization.

## Integration
Connects to `Source/Runtime/Remoting/Public/` as all private types implement the interfaces exposed by public headers; `FRTTIEndpoint::` private implementation satisfies the public `FRTTIEndpoint` contract; `FOpenAPI::` private implementation satisfies the public `FOpenAPI` contract; `FSwaggerEndpoint::` private implementation satisfies the public `FSwaggerEndpoint` contract. Connects to `Source/Runtime/Network/` as `FRemotingServer` inherits `Network::FHttpServer`, uses `FHandShaker` for connection management, and `FRemotingContext` carries network address. Connects to `Source/Runtime/RTTI/` as `FRTTIEndpoint` reads entire `FMetaDatabase` (classes, enums, objects, transactions, modules) and exposes them via auto-generated REST API; responses serialized via `FOpenAPI` and `FJsonSerializer`; `FOpenAPI.DefineRTTIMetaClass()` traverses `FMetaClass` hierarchy. Connects to `Source/Runtime/VFS/` as custom endpoints may expose file system operations; `FOpenAPI` may reference VFS-mounted resources. Real paths: `Source/Runtime/Remoting/Public/RemotingModule.h`, `Source/Runtime/Remoting/Public/RemotingServer.h`, `Source/Runtime/Remoting/Public/Remoting/RTTIEndpoint.h`, `Source/Runtime/Remoting/Public/Remoting/OpenAPI.h`, `Source/Runtime/Remoting/Public/Remoting/SwaggerEndpoint.h`, `Source/Runtime/VFS/Public/VirtualFileSystem.h`, `Source/Runtime/Remoting/Public/Remoting/BaseEndpoint.h`.
