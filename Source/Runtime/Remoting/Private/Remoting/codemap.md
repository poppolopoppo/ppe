# Source/Runtime/Remoting/Private/Remoting/

## Responsibility
The Remoting/Private folder provides the low-level base classes and implementation details that underpin the public remoting API. It defines `FBaseEndpoint` with shared endpoint functionality, the `FRemotingContext` per-request structure carrying cookie/post/query maps and sync events, and the parameter/location mapping infrastructure (`EParameterLocation`, `FParameter`). This folder also owns the `FHandShaker`-related types and the `FRemotingService` forward declaration. The private layer abstracts away the variant-based endpoint registry, dispatch mechanics, and OpenAPI generation details from public consumers, offering a clean extension point via `IRemotingEndpoint` while encapsulating the complexity of RTTI mirror types, trait caching, and request routing.

## Design
Key patterns include the `FParameter` struct with `EParameterLocation` enum (Body, Cookie, FormData, Headers, Path, Query) and `FRequired/Structured` flags, the `FRemotingContext` carrying `FRemotingCookieMap` (Network::FHttpHeader::FCookieMap), `FRemotingPostMap` (Network::FHttpHeader::FPostMap), `FRemotingQueryMap` (Network::FUri::FQueryMap), and a `TPublicEvent<FRemotingCallback>` for sync coordination. `FBaseEndpoint` provides `EndpointPrefix()`, `EndpointOpenAPI(FOpenAPI*)`, `EndpointProcess(const FRemotingContext&)`, and protected `EndpointDispatchIFP()` for path/method routing. The `EParameterLocation` enum maps OpenAPI parameter locations to C++ code generation patterns. `FRemotingService` (forward-declared, defined in extension) owns the service-level lifecycle. `FRTTITraitsCache` provides thread-safe caching of `PTypeTraits` → `PRTTITraits` conversions. The variant-based endpoint map `std::variant<URemotingEndpoint, PBaseEndpoint>` in `FRemotingServer` enables homogeneous storage of heterogeneous endpoint types. Private endpoint methods `PrivateEndpointOpenAPI()` and `PrivateEndpointProcess()` are the extension points for concrete endpoint implementations.

## Flow
Request processing: `FHttpServer.OnRequest` → `FRemotingServer.Route()` → iterates `FEndpointMap` variant values → calls `IRemotingEndpoint.EndpointProcess(ctx)` on each → `EndpointDispatchIFP()` matches path/method → calls `PrivateEndpointProcess(ctx, relativePath)` → processes parameters per `EParameterLocation` → returns response. OpenAPI generation: `FRemotingServer.Tick()` → `FRemotingContext` construction with cookie/post/query maps → `EndpointDispatchIFP()` with `FOperation` descriptor → `PrivateEndpointOpenAPI(api)` populates `FOpenAPI` struct field-by-field → `PrivateEndpointProcess()` processes the request. Trait caching: `FRTTITraitsCache` (thread-safe HASHMAP) converts `RTTI::PTypeTraits` → `PRTTITraits` on first access, subsequent calls use the cache. Keep-alive: `FRemotingCallback` invoked via `WaitForSync()` with `TPublicEvent` synchronization.

## Integration
Connects to `Source/Runtime/Remoting/Public/Remoting/` as `FBaseEndpoint` is the base class for `FSwaggerEndpoint` and `FRTTIEndpoint`; `FRemotingContext` is constructed and used by `FRemotingServer` which inherits publicly from `FBaseEndpoint` via the public hierarchy. Connects to `Source/Runtime/Network/` as `FRemotingContext` carries `FRemotingCookieMap` (Network::FHttpHeader::FCookieMap), `FRemotingPostMap` (Network::FHttpHeader::FPostMap), `FRemotingQueryMap` (Network::FUri::FQueryMap), and `Network::FAddress` localhost; `EParameterLocation` maps to HTTP parameter locations. Connects to `Source/Runtime/RTTI/` as `FRTTIEndpoint`/`FSwaggerEndpoint` ultimately read `FMetaDatabase` and generate `FOpenAPI` schemas via `FOpenAPI.DefineRTTISchemas()`.
