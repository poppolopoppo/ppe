# Source/Runtime/Core/Private/HAL/Windows/

## Responsibility
This folder implements the Windows-specific HAL (Hardware Abstraction Layer) for the private Core layer, providing platform-native interfaces for core system operations on Windows systems within the private implementation scope. It concrete-izes the generic HAL abstractions for the Windows API, enabling cross-platform compatibility while leveraging Windows-specific primitives for performance and correctness. The private Windows HAL provides implementations for platform memory management, atomics, threading, file I/O, endianness, time, process management, console dialog, and target platform detection tailored to the Windows operating system, with all implementations hidden from public headers.

## Design
The private Windows HAL design concrete-izes the generic FGenericPlatform* base classes with Windows API implementations within the private layer. Platform memory uses VirtualAlloc/VirtualFree/HeapAlloc for virtual memory management, with decommit and release granularity. Atomics employ Interlocked family functions (InterlockedExchangeAdd, InterlockedCompareExchange, InterlockedIncrement, InterlockedDecrement) for lock-free operations on x86 and ARM. Thread creation uses CreateThread with LPTHREAD_START_ROUTINE, supports fiber creation via ConvertThreadToFiber and ConvertFiberToThread, and sets thread affinity and priority classes. File I/O leverages CreateFile/ReadFile/WriteFile/CloseHandle for file operations, with memory mapping via CreateFileMapping/MapViewOfFile. Endianness conversion uses RtlConvertUlongToUlong or a lookup table for byte-swap operations. Time queries employ GetTickCount64 for millisecond timestamps, QueryPerformanceCounter/QueryPerformanceFrequency for high-resolution timestamps, and GetLocalTime for system time. Process management uses CreateProcess/CreateProcessForWOW64, TerminateProcess, and WaitForSingleObject for process termination. Console dialog support implements Win32 console APIs for message boxes, file dialogs, and character output. Target platform detection uses GetVersionEx, GetNativeSystemInfo, and the ETargetPlatform enum to distinguish Windows, Windows64, and console variants (Xbox, etc.). All implementations are designed for internal use within Core/Private.

## Flow
Private Windows HAL initialization during FPlatform::Initialize() resolves the target platform via PPE_HAL_TARGETALIAS() macros and creates an FWindowsPlatform* instance within the private layer. Memory allocation: FPlatformMemory::Allocate() calls VirtualAlloc with MEM_COMMIT|MEM_RESERVE and appropriate page protection flags (PAGE_READWRITE, PAGE_EXECUTE_READWRITE, etc.), or HeapAlloc for smaller allocations; VirtualFree with MEM_RELEASE decommits and releases pages. Atomics: FPlatformAtomics::FetchAndAdd() compiles to InterlockedExchangeAdd for lock-free operations. Thread creation: FPlatformThread::Create() calls CreateThread, sets stack size and priority, and the resulting thread handle is registered with FTaskScheduler for fiber mapping. File I/O: FPlatformFile::OpenFile() calls CreateFile with GENERIC_READ|GENERIC_WRITE and FILE_SHARE_READ|FILE_SHARE_WRITE; Read/Write use ReadFile/WriteFile; memory mapping uses CreateFileMapping/MapViewOfFile. Endian conversion: FPlatformEndian::Byteswap32/64() calls RtlConvertUlongToUlong or uses a lookup table. Time queries: FPlatformTime::Now() calls QueryPerformanceCounter for high-resolution timestamps, divided by QueryPerformanceFrequency for seconds. Shutdown: FPlatform::Shutdown() VirtualFrees all allocated regions, closes file handles, and waits for pending threads to complete, within the private layer.

## Integration
Private Windows HAL/ is the concrete realization behind the Public HAL interface on Windows platforms within the Core module. Container/ TVector and TArray use FWindowsPlatformMemory for all memory operations. Smart pointers TRefPtr/TWeakPtr depend on FWindowsPlatformAtomics for reference count operations. Thread/ FTaskManager and FTaskScheduler use FWindowsPlatformThread for OS thread creation and fiber scheduling. Maths/ scalar types may use PlatformMaths SIMD intrinsics lowered for x86 AVX2. Diagnostic/ FLeakDetector, FStackMarker, and FProfiler integrate with Windows-level tracing and debug help within private code. IO/ FFileSystem::FindFile and FFileStream depend on FWindowsPlatformFile for concrete file operations (CreateFile, etc.). Modular/ FDynamicModule uses LoadLibrary/FPlatformLoadLibrary for dynamic module loading on Windows. The private Windows HAL is conditionalized via PPE_HAL_TARGETALIAS() macros, which resolve to FWindows* implementations at compile time when targeting Windows, with all implementations hidden from public headers. It is also the primary HAL for Windows editor and build pipeline integration within the Core module.
