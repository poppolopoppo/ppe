# Source/Runtime/Core/Private/HAL/Generic/

## Responsibility
This folder implements the generic, platform-agnostic HAL (Hardware Abstraction Layer) fallback implementations for the private Core layer, providing baseline behavior across all supported platforms from within the private implementation scope. It serves as the reference implementation from which platform-specific private variants (Windows, Linux) are derived, ensuring that a functional default exists even when platform-specific code is absent. The Private Generic HAL provides generic implementations of memory management, atomics, threading, file I/O, endianness, time, and console dialog operations that can serve as fallbacks or reference implementations for porting, testing, and internal use.

## Design
The Private Generic HAL design follows the same target-abstraction macro pattern as the Public HAL but within the private layer: PPE_HAL_TARGETALIAS(Component) maps to platform-specific private implementations (FWindows*, FLinux*), but when no platform-specific code is available, the Generic fallback provides a working baseline. FGenericPlatform* classes inherit from this Generic layer, overriding only platform-specific behaviors while reusing the generic infrastructure for memory allocation (FGenericPlatformMemory), atomics (FGenericPlatformAtomics), threading (FGenericPlatformThread), file I/O (FGenericPlatformFile), endianness (FGenericPlatformEndian), time (FGenericPlatformTime), and console dialog (FGenericPlatformConsole). The Generic implementations use preprocessor conditionals and template specialization to provide platform-appropriate defaults, such as using memset-based atomics on platforms without native support, or stub console implementations that no-op. Template parameters and compile-time flags control which Generic features are included, allowing platforms to strip out unused components. All implementations are designed for internal use within the Core module.

## Flow
Private Generic HAL initialization occurs during FPlatform::Initialize(), where the target platform is detected and the appropriate PPE_HAL_TARGETALIAS() resolution is attempted. If the target platform has a specific implementation (Windows, Linux), that is used; otherwise, the Generic fallback is instantiated. Generic memory operations (allocate, deallocate) use platform-agnostic primitives that may delegate to the OS's default allocator. Generic atomics use portable compare-and-swap loops or compiler built-ins. Generic thread creation may create OS threads with default attributes or no-op depending on configuration. File I/O stubs may return errors or provide minimal functionality for testing within private code. Endianness conversion may be a no-op on naturally aligned platforms or use lookup tables. Time queries may use monotonic clocks or system time. Shutdown of the Private Generic HAL is a no-op or cleanup of any allocated generic resources, with coordination through the private module system.

## Integration
The Private Generic HAL/ serves as the baseline dependency for all private Core subsystems when platform-specific implementations are not available. Container/ TVector and TArray use Generic memory allocation when no custom allocator is specified. Smart pointers TRefPtr/TWeakPtr fall back to Generic atomics when platform-specific atomics are not configured. Thread/ fiber scheduling may use Generic thread creation as a fallback. Diagnostics/ FStackMarker and FLeakDetector may integrate with Generic profiler data. IO/ FFileSystem::FindFile may use Generic file operations as a fallback. The Private Generic HAL is also used in unit testing and porting scenarios within the Core module, providing a known working implementation that can be incrementally replaced with platform-specific code. All platform-specific HAL private variants (Windows, Linux) inherit from or delegate to the Generic layer for unimplemented features, with integration coordinated through the private module layer.
