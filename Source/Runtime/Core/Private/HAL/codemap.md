# Source/Runtime/Core/Private/HAL/

## Responsibility
This folder serves as the parent aggregator for all Private HAL (Hardware Abstraction Layer) subsystems, containing the implementation details, platform-specific abstractions, and low-level infrastructure that underpins the Engine's cross-platform compatibility. It encompasses the HAL components for PlatformMemory, PlatformAtomics, PlatformThread, PlatformFile, PlatformEndian, PlatformMaths, PlatformLowLevelIO, PlatformConsole, PlatformDialog, PlatformProcess, PlatformProfiler, PlatformString, PlatformHash, PlatformMisc, PlatformTime, TargetPlatform, WindowsTargetPlatform, LinuxTargetPlatform, PlatformIncludes, PlatformCallstack, PlatformCrash, PlatformDebug, and PlatformIncludes. The Private HAL folder implements the concrete realizations of the Engine's platform abstractions, serving as the bridge between Engine code and OS-specific implementations for Windows, Linux, and console platforms. All types and implementations within this folder are private to the Core module and not intended for external client code.

## Design
The Private HAL design follows the target-abstraction macro pattern: PPE_HAL_TARGETALIAS(Component) maps to platform-specific implementations (FWindows*, FLinux*, FGeneric*) at compile time, with Generic fallbacks (FGenericPlatform*) providing baseline implementations when platform-specific code is not available. Windows and Linux implementations inherit from FGenericPlatform* base classes, ensuring interface consistency across platforms. Target platform detection uses ETargetPlatform enum and ITargetPlatform interface. Memory operations use FPlatformMemory with VirtualAlloc/VirtualFree on Windows and mmap/munmap on Linux. Atomics use platform intrinsics (Interlocked* on Windows, __atomic_* on Linux). Thread creation uses CreateThread/pthread_create with fiber support. File I/O uses CreateFile/open + memory mapping. Endianness conversion is handled via FPlatformEndian enum and compile-time byte-swap intrinsics. The folder also provides PlatformMaths with SIMD intrinsics abstraction, PlatformString with encoding conversion, and PlatformHash with hash algorithm implementations. All designs are optimized for the private Core module's performance and correctness requirements.

## Flow
Private HAL initialization flows from the modular system through platform detection: FPlatform::Initialize() resolves the target platform via PPE_HAL_TARGETALIAS() macros and creates the appropriate FPlatform* instance. Thread creation: FPlatformThread::Create() -> OS-specific thread creation -> fiber registration with FTaskScheduler. Atomic operations: FPlatformAtomics::FetchAndAdd() -> InterlockedExchangeAdd (Windows) or __atomic_fetch_and_add (Linux). File I/O: FPlatformFile::OpenFile() -> CreateFile (Windows) or open (Linux) + memory mapping -> FFile handle. Endian conversion: FPlatformEndian::Byteswap() -> platform intrinsics or lookup table. Profiler integration: FPlatformProfiler::BeginFrame() / EndFrame() -> OS-level tracing. Shutdown: FPlatform::Shutdown() -> cleanup of platform-specific resources in reverse initialization order. All flow operations are designed for the private Core module's internal use.

## Integration
The Private HAL/ is the lowest-level dependency in the Engine's Core module, directly integrated by all other private subsystems. Container/ TVector and TArray use PlatformMemory for allocator-backed memory. Allocator/ FVirtualAllocator<FMemoryDomain> queries PlatformMemory for OS-level memory usage statistics. Memory/ smart pointers TRefPtr/TWeakPtr depend on PlatformAtomics for reference count operations. Thread/ FTaskManager and FTaskScheduler use PlatformThread for OS thread creation and fiber scheduling. Maths/ scalar types may use PlatformMaths SIMD intrinsics. Diagnostic/ FLeakDetector, FStackMarker, and FProfiler all integrate with PlatformProfiler. IO/ FFileSystem and FArchive use PlatformFile for concrete file operations. Modular/ FDynamicModule uses PlatformLoadLibrary/FPlatformFreeLibrary for dynamic module loading. The HAL/PlatformMacros.h header defines the PPE_HAL_TARGETALIAS() macro used across the entire private Core codebase. All integration paths are within the Core/Private hierarchy.
