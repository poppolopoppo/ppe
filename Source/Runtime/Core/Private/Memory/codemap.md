# Source/Runtime/Core/Private/Memory/

## Responsibility
This folder implements smart pointer types and memory domain infrastructure for the PPE Engine's private Core layer, providing the internal implementation details of reference-counted smart pointers, memory arenas, and memory viewing primitives that underpin all Engine subsystems. It owns TInSituPtr, TRefPtr, TWeakPtr, FMemoryDomain, FMemoryPool, FMemoryProvider, FMemoryStream, FMemoryDomain_fwd, MemoryDomain.Definitions-inl, MemoryPool, MemoryView, PtrRef, RefPtr-inl, RefPtr, UniquePtr-inl, UniquePtr, UniqueView, RelativeView, SharedBuffer-inl, SharedBuffer, SharedBuffer_fwd, VirtualMemory, VirtualMemoryCache, CachedMemoryPool, HashFunctions, HashFunctions-inl, Compression, and WeakPtr-inl. All types and implementations within this folder are private to the Core module and not intended for external client code. TRefPtr and TWeakPtr provide reference-counted smart pointer semantics with FRefCountable integration. TInSituPtr stores a pointer within the object itself when feasible (EBCO). FMemoryDomain and FMemoryPool provide scoped memory allocation with domain-specific tracking. CachedMemoryPool and MemoryPool manage pooled allocation for hot types. Memory tracking, viewing, and unique ownership primitives (UniquePtr, SharedBuffer) round out the folder's scope, with all designs optimized for the private Core module.

## Design
Smart pointer design follows RAII patterns with platform-optimized atomics for TRefPtr's InterlockedIncrement/InterlockedDecrement within private code. TWeakPtr breaks reference cycles by storing a non-owning observer pointer that validates via IsValid() before access. TInSituPtr uses template specialization to store small pointers inside the object body when is_ebco_eligible_v is true, eliminating the indirection cost. FMemoryDomain provides scoped memory allocation domains, allowing different subsystems (rendering, audio, gameplay) to have independent memory arenas with independent tracking. FMemoryPool provides a two-level pool (page + size-class) for fast allocation of recurrent types, with thread-local caches under the FPlatformAtomics umbrella. CachedMemoryPool specializes for TRefPtr/TWeakPtr control block allocation. UniquePtr provides exclusive ownership with custom deleter support. SharedBuffer implements reference-counted buffer sharing across IO streams and serialization. All pointers integrate with FMemoryTracking and FLeakDetector for production leak validation, with all implementations within Core/Private.

## Flow
Reference-counted pointer creation: TRefPtr<T> increments the control block refcount atomically; TWeakPtr<T> stores only the raw pointer and generation counter. Pointer usage: IsValid() checks the generation counter; operator-> and operator* provide access. Pointer release: TRefPtr decrement triggers delete when refcount hits zero; TWeakPtr does not affect refcount. Memory domain allocation: FMemoryDomain::Allocate pulls from FMemoryPool, which pulls from FPageAllocator or FTrackingAllocator. Pool exhaustion falls back to the system FMalloc. Memory viewing: MemoryView<T> provides a non-owning span into allocated memory. Buffer sharing: SharedBuffer::AddRef/Release manages cross-stream references. Destruction: UniquePtr destructor calls Deallocate; RefPtr's control block is freed when refcount reaches zero. Leak detection: FLeakDetector scans all active TRefPtr/TWeakPtr/TUniquePtr at shutdown. All flow operations integrate with the private Allocator layer and are designed for Core/Private module use.

## Integration
Memory/ smart pointers are the primary ownership model used across every Engine subsystem within the private Core layer. Container/ TVector, TArray, THashMap all store TRefPtr<T> or TUniquePtr<T> elements when reference semantics are required. Allocator/ FTrackingAllocator and FMemoryPool are the default memory backends for pointer control blocks. Thread/ TThreadSafe<T> uses TInSituPtr for lock-free data sharing. Diagnostic/ FLeakDetector's entire tracking infrastructure depends on TRefPtr/TWeakPtr/FInSituPtr semantics. IO/ FMemoryStream reads/writes UniquePtr and SharedBuffer payloads. Maths/ TUnit<T> and TQuantity<T> store data via UniquePtr. Meta/ TFunction and TFunctor hold callables via UniquePtr type erasure. HAL/ PlatformMemory queries FMemoryDomain statistics for OOM detection. The MemoryDomain.Definitions-inl header defines the FMemoryDomain enum used to partition memory tracking across the Engine's private Core module. All integration paths are within Core/Private.
