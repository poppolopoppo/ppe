# Source/Runtime/Core/Private/Maths/

## Responsibility
This folder provides core mathematical utilities, geometric primitives, and spatial acceleration structures for the PPE Engine's private Core layer, implementing XorShift-based random number generators, bounding interval hierarchies for broad-phase collision and ray intersection culling, packing helpers, bounding volume hierarchies (spheres, boxes, frustums, spheres), and transform/sphere/ray/box collision support. All implementations are designed for internal use within the Core module, providing the mathematical foundation for rendering, physics, and gameplay subsystems without exposing public headers.

## Design
The random generator design uses XorShift+ variants seeded from process context: FXorShift64Star provides a 64-bit multiply-with-shift cycle, FXorShift128Plus maintains a two-state 128-bit generator with wrap-around carry, and FXorShift1024Star maintains a 16-state ring for massive-period generation. The state is initialized via MakeSeed(), which combines the process GUID, CPU ordinal, thread ID, and network time into a fingerprint. FBasicBIHTree nodes (FBIHNode) are packed u64 structs with Axis (few bits), Child0/Child1 child offsets, Clip0/Clip1 quantized plane bounds, and Split index, guaranteeing 64-byte alignment and POD static assertions. The BIH build algorithm (Build) uses a longest-axis split with clip-based quantization, recursing until maxItemsPerLeaf is reached, at which point the node is marked as a leaf. Intersection traversal (Intersects for ray, sphere, frustum, and AABB) uses the clipped bounds to cull early and only descend into potentially intersecting children. PackingHelpers provide utility for array and memory layout optimization. All random generators and BIH structures are designed for thread-local or per-instance state, with compile-time configurability via template parameters and preprocessor flags.

## Flow
Application or subsystems request random values by calling the generator's NextU64() method, which advances internal state via XorShift shift-and-multiply operations. For BIH construction, the caller invokes FBasicBIHTree::Build(maxItemsPerLeaf, bounds, indices, aabbs), which enters a split loop: the longest axis of the current grid is identified, a midpoint splitD is computed, and indices are partitioned into left (clip0) and right (clip1) groups based on whether their extent min/max falls below/above splitD; if a child would be empty, the grid boundary is adjusted and the loop retries; once partitioned, the node is assigned an axis, clip values are quantized and stored, the split index is recorded, and if the item count exceeds maxItemsPerLeaf * 2 the recursion continues by allocating two child nodes and pushing candidate frames onto a stack; otherwise the node is marked as a leaf. For intersection queries, the caller invokes FBasicBIHTree::Intersects(ray/sphere/frustum) which traverses from the root, testing clipped child bounds at each internal node and collecting hits from leaf nodes via the provided delegate. Random generator state is refreshed via Reset(seed) calls, and MakeSeed() is called once at process startup to produce a deterministic but process-unique seed. All flow operations are designed for the private Core module's internal use.

## Integration
Integration connects to Source/Runtime/Core/Private/Modular/ (RandomGenerator.cpp includes ModuleInfo.h and pulls FGuid from the modular system for seed generation), Source/Runtime/Core/Private/HAL/ (PlatformMaths provides CeilLog2 used in BIH depth approximation), and Source/Runtime/ (the random generators are used by the Task scheduler when USE_PPE_TASK_SCHEDULER_SHUFFLING is enabled, and by rendering/post-processing pipelines). The BIH tree intersects with Rendering/SceneQuery pipelines. Maths types (FBoundingBox, FBoundingSphere, FRay, FFrustum) are defined in Source/Runtime/Core/Private/Maths/ and shared across the engine's private subsystems.
