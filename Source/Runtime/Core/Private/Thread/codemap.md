# Source/Runtime/Core/Private/Thread/

## Responsibility
The Thread folder owns the task scheduler, thread pool, and fiber-based execution infrastructure for the PPE engine. It implements a priority work-stealing scheduler (FTaskScheduler) with multi-worker local queues, a completion-port-based task consumption model (FCompletionPort), and a task manager implementation (FTaskManagerImpl) that spawns and manages worker threads with affinity support. A fiber pool (FTaskFiberPool) provides lightweight cooperative multitasking on top of the thread pool. The scheduler supports fixed-priority non-preemptive scheduling with run-and-wait barriers, and integrates with the modular domain for duty-cycle processing.

## Design
The scheduler design centers on FTaskScheduler, which maintains VECTOR(Task, FWorkerQueue_) of per-worker priority heaps when USE_PPE_TASK_SCHEDULER_WORKSTEALINGQUEUE is enabled, or a single CONCURRENT_PRIORITY_QUEUE when the fallback path is used. Each FWorkerQueue_ holds a CACHELINE_ALIGNED priority heap (MIN_MinMaxHeap) of FTaskQueued entries, each carrying a priority tag and a SCompletionPort for wake-up. The work-stealing algorithm packs priority and revision into a single size_t key (priority_firstbit_ = 24 bits), enabling O(1) priority comparison and revision-aware insertion ordering. FTaskManagerImpl implements ITaskContext, managing a VECTOR(std::thread) of worker threads with affinity masks, a FSynchronizationBarrier for broadcast synchronization, and optional FTimeline for logger-backed duty-cycle stats. The fallback path uses a CONCURRENT_PRIORITY_QUEUE (based on a lock-free concurrent queue) for single-queue consumption without work stealing. FTaskFiberPool maps coroutine-style fiber execution to worker threads, allowing tasks to yield and resume without OS thread preemption.

## Flow
Application code creates tasks (FTaskFunc) and calls FTaskScheduler::Produce(priority, task, pport), which packs the task into an FTaskQueued and pushes it onto a per-worker priority heap via work-stealing round-robin distribution: the producer computes workerIndex = insertion_order_preserving_priority % numWorkers and attempts to try-lock that worker's barrier; on success the task is pushed onto the priority heap and Push_MinMaxHeap re-establishes heap order, then _onTask.notify_one() wakes a consumer. A worker calls FTaskScheduler::Consume(workerIndex, &pop), which spins through worker queues checking HasHigherPriorityTask_ and attempting to pop from the local priority heap; if no local task is available, it waits on _onTask condition variable for notification. When the task is eventually executed, FTaskManagerImpl::Consume worker loop dequeues from the completion port and runs the task function; RunAndWaitFor produces a task and immediately consumes it synchronously. The fiber pool pulls from the worker queue, yields back via the completion port, and re-queues when resumed.

## Integration
Integration connects to Source/Runtime/Core/Private/Allocator/ (memory allocation for task queues and fiber stacks via FMallocProxy), Source/Runtime/Core/Private/Maths/ (random generator used when USE_PPE_TASK_SCHEDULER_SHUFFLING is enabled for task shuffling), and Source/ (completion port and synchronization primitives from HAL/PlatformProcess). The thread scheduler's worker threads are the primary consumers of allocated memory from the allocator, and the random generator influences task ordering in shuffling mode. See Source/Runtime/Core/Private/Thread/Task/TaskScheduler.h for the full scheduler interface and Source/Runtime/Core/Private/Thread/Task/TaskManagerImpl.h for the thread manager implementation.
