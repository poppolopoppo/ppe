# Source/Runtime/Core/Private/Meta/

## Responsibility
This folder implements the Engine's meta-programming and type utilities for the private Core layer, providing the internal implementation details of template metaprogramming utilities, type traits, and compile-time constructs that underpin all Engine subsystems. It owns TCompressedPair, TFunction, TAutoStruct, TForRange, MD5, TStronglyTyped, FOpaque, FOpaqueBuilder, TEnableIf, TAlignedStorage, TInPlace, TOptional, TBitField, TBit, TTypeInfo, TSingleton, TAutoSingleton, TStaticSingleton, TBitField, TBit, Cast.h, TypeInfo.h, Algorithm.h, Arithmetic.h, Config.h, OneTimeInitialize.h, Optional.h, PointerWFlags.h, SafeBool.h, Enum.h, Hash_fwd.h, InPlace.h, NumericLimits.h, Utility.h, StronglyTyped.h, TypeTraits.h, Iterator.h, Functor.h, AutoEnum.h, AutoStruct.h, AlignedStorage.h, and MD5.h. All types and implementations within this folder are private to the Core module and not intended for external client code. TCompressedPair applies EBCO to eliminate padding between empty members. TFunction provides type-erased callable storage with IF_CONSTEXPR conditional compilation. TAutoStruct auto-generates reflection/serialization metadata via PPE_DEFINE_AUTOSTRUCT. TForRange provides compile-time foreach over TArray indices or ranges. StronglyTyped<T, Tag> creates compile-safe typed handles. MD5 hashing provides 128-bit message digests. Type traits (is_pod_v, is_ebco_eligible_v, etc.) are ubiquitous across the codebase. TSingleton, TAutoSingleton, and TStaticSingleton provide CRTP-based singleton patterns. TEnableIf and IF_CONSTEXPR enable SFINAE and compile-time branching.

## Design
Meta-programming design relies heavily on template metaprogramming and CRTP patterns within the private layer. TCompressedPair<Empty, NonEmpty> uses is_ebco_eligible_v to conditionally apply empty-base optimization, eliminating struct padding. TFunction<Sig> type-erases a callable into a heap-allocated control block sized by IF_CONSTEXPR compile-time size analysis. TAutoStruct<Fields> generates a TypeInfo entry and serialization metadata at instantiation via PPE_DEFINE_AUTOSTRUCT(name, fields...). TForRange<Iter> provides compile-time index sequences for TArray<N> or TRange<Min, Max>, expanded by the IF_CONSTEXPR macro. StronglyTyped<T, Tag> is a class template that wraps a T value but has a distinct type from T, enabling compile-safe handle/ID patterns (FOpaque<T>, FFileSystemToken). MD5 computes message digests over byte sequences, used for content identification and checksum validation. Type traits (Meta::TypeTraits) provide compile-time boolean constants (is_pod_v, is_ebco_eligible_v, has_trivial_move, etc.) used extensively in template specialization. TSingleton<Derived> uses CRTP with a friend static instance method for thread-safe singleton initialization. TEnableIf<Cond> wraps std::enable_if in a PPE-namespaced utility for custom SFINAE conditions. All designs are optimized for compile-time evaluation and minimal code bloat within the Core/Private module.

## Flow
Type trait queries: Meta::is_pod_v<T> and Meta::is_ebco_eligible_v<T> are evaluated at compile-time to select code paths. TCompressedPair construction aggregates members in declaration order, applying EBCO where eligible. TFunction::Assign<F> stores a callable functor, with IF_CONSTEXPR guards for constexpr vs runtime branches. TAutoStruct instantiation registers the type in PPE's reflection system, enabling serialization and editor inspection. TForRange expansion generates explicit index loops over TArray<N> or TRange<Min, Max>. StronglyTyped handle creation: StronglyTyped<int, Tag> wrapper converts implicitly only via explicit constructors. MD5 input: byte sequence -> feed -> finalize -> 128-bit digest. Type info registration: TTypeInfo::Get<T>() returns the compiled type descriptor for reflection. Singleton initialization: TSingleton::Get() creates the static instance on first call, using thread-safe static initialization (Meyers' pattern). TEnableIf conditional: IF_CONSTEXPR(TEnableIf<Cond>::value) selects template specializations at compile time. All flow operations are designed for compile-time evaluation within the Core/Private module and minimize runtime overhead.

## Integration
Meta/ utilities are foundational types used across every Engine subsystem within the private Core layer. Container/ TArray<T>, TVector<T>, THashMap<K,V> use TEnableIf and is_pod_v for optimizer fast-paths. Allocator/ FTrackingAllocator and FStlAllocator instantiate on Meta::is_pod_v and is_ebco_eligible_v traits. Memory/ TRefPtr/TWeakPtr control blocks use TCompressedPair<Deleter, void*> for EBCO. Thread/ TThreadSafe<T, Barrier> uses TEnableIf for barrier-conditioned code paths. IO/ TStaticString, TBasicString, FString all use TAlignedStorage and TOptional for buffer management. Maths/ TScalarVector and TScalarMatrix rely on Meta::NumericLimits<T> for component bounds. Diagnostic/ FLogger and FDebugFunction use TFunction<Sig> for callback registration. Modular/ FModuleStaticRegistration and FModularServices use TAutoStruct for module interface reflection. HAL/ PlatformString and PlatformHash use TBitField for flag packing. The Meta/TypeTraits.h header is one of the most included headers in the Codebase, governing template specialization decisions across all private Core modules. All integration paths are within Core/Private.
