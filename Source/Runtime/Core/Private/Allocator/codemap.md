# Source/Runtime/Core/Private/Allocator/

## Responsibility
The Allocator folder manages all memory allocation for the PPE engine core. It provides a layered abstraction over OS-level memory primitives, supporting bump allocation, binned size-class allocation, stomp-guard poisoning, and page-level virtual memory allocation. The folder implements the FMallocProxy/FMallocLowLevel machinery that resolves at compile time to one of several strategies (std, binned1, binned2, stomp) and integrates leak detection, histograms, and poisoning proxies for debug and final-release builds. PageAllocator extends this with virtual page caching and critical-section-guarded chunk management. All allocation funnels through the platform HAL, with domain tracking support for memory diagnostics.

## Design
The allocator design centers on the FAllocatorBlock type and FMallocLowLevel namespace, which encapsulate platform-independent allocation logic behind a policy-driven allocator selection mechanism. At compile time, PPE_MALLOC_ALLOCATOR selects between PPE_MALLOC_ALLOCATOR_STD (FMallocLowLevel wrapping FPlatformMemory), PPE_MALLOC_ALLOCATOR_BINNED1 (FMallocBinned size-class bins), PPE_MALLOC_ALLOCATOR_BINNED2 (FMallocBinned2 with 123 size classes and a histogram of 123 bins), PPE_MALLOC_ALLOCATOR_STOMP (FMallocStomp with poison guards), or the default binned1. The PageAllocator adds a virtual page cache layer on top, using FCriticalSection for thread safety and a free-page linked list with CACHELINE_ALIGNED struct layout. Debug proxies (PPE_MALLOC_DEBUG_PROXY, PPE_MALLOC_HISTOGRAM_PROXY, PPE_MALLOC_LEAKDETECTOR_PROXY, PPE_MALLOC_POISON_PROXY, PPE_MALLOC_UNACCOUNTED_PROXY) inject leak tracking, size-class histograms, block poisoning, and unaccounted-domain logging around the low-level allocator. FMallocProxy provides the public API entry point (malloc/free/calloc/realloc/aligned_*) and optional runtime diagnostics (region size, leak dump, histogram fetch).

## Flow
Application code calls standard C malloc/free or the engine's FMallocProxy::Malloc/Free, which routes through FMallocLowLevel to the selected concrete allocator strategy. For binned allocators, size classes are determined by FMallocBinned::Malloc snapping the request to the nearest power-of-two bin, with FMallocBinned2 using a 123-entry block-size table. If the debug proxy is enabled, FMallocProxy::Malloc passes through OnAllocate_, which fires PPE_DEBUG_ALLOCATEEVENT, FLeakDetector::Allocate, FMallocHistogram::Allocate, and FMallocUnaccounted::Allocate hooks. PageAllocator::Allocate delegates to FVirtualPageCache_::Get().Allocate, which either finds a free page from the CAS-backed FreePages list or calls FVirtualMemory::InternalAlloc to commit new virtual memory. On deallocation, FMallocProxy::Free → FMallocLowLevel::Free → the strategy's Free, then PageAllocator::Deallocate returns pages to the cache or calls FVirtualMemory::PageFree. The histogram and leak detector accumulate state throughout the allocation lifetime and can be dumped via FMallocDebug::DumpMemoryLeaks/FetchAllocationHistogram at shutdown.

## Integration
Integration connects to Source/Runtime/Core/Private/Memory/ (MemoryView, MemoryDomain, VirtualMemory implementations) for OS-backed page management, Source/Runtime/Core/Private/HAL/ (PlatformMemory, PlatformDebug) for system-aligned allocator support and debug hook integration, and Source/Runtime/Core/Private/Thread/ (CriticalSection used by PageAllocator's AllocationBarrier for thread-safe page cache operations). Out-of-tree modules such as the LeakDetector and MemoryDomain further extend tracing; see Source/Runtime/Core/Private/Diagnostic/ and Source/Runtime/Core/Private/Memory/ for details.
