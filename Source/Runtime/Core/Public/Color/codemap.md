# Source/Runtime/Core/Public/Color/

## Responsibility
This folder implements color types and utilities for the PPE Engine, providing type-safe color representations used across rendering, editing, and visualization subsystems. It defines color structs and classes that encapsulate RGBA/BGRA channel data, support hardware-specific formats (sRGB, linear, normalized), and integrate with the rendering pipeline's material and lighting systems. The folder also provides color conversion functions, color space conversion utilities, and hash utilities for color identification in asset pipelines and debugging tools.

## Design
Color design follows a type-safe hierarchy with strongly-typed color representations that prevent mixing incompatible color spaces. The primary color type stores four channels (red, green, blue, alpha) as float values in [0,1] range, with template specializations for half-precision (16-bit) and integer formats. Color conversion functions handle transitions between color spaces (sRGB to linear, linear to sRGB, XYZ to RGB and vice versa). The folder provides predefined color constants (Color::Black, Color::White, Color::Red, Color::Green, Color::Blue, Color::Transparent) and supports operator overloads for addition, subtraction, multiplication, and component access. Color hash functions enable reliable comparison and asset identification. All color types are allocator-aware and integrate with the Memory smart pointer system for persistent color data.

## Flow
Color creation typically begins with predefined constants or constructor initialization from RGB values, hex strings, or other color spaces. Color operations (addition, multiplication, lerp) produce new color values without mutating operands unless an in-place variant is called. Color space conversion flows through dedicated functions that apply gamma correction and tone mapping. Hash computation feeds color channel data into MD5 or fingerprint hash functions for asset identification. When used in rendering, colors are passed through the shader pipeline, potentially undergoing further transformation by material shaders. At shutdown, color data is released through the Memory smart pointer system if persistently allocated.

## Integration
Color/ integrates with Rendering/ material systems and lighting pipelines, where color types define material emissive, diffuse, and specular components. Maths/ TScalarVector and TScalarMatrix types are used in color transformation matrices. IO/ FString and FText display color names in editor tools. Diagnostic/ FLogger uses color types for verbosity-coded log output. Thread/ concurrent access to color data is synchronized through the Task system's completion port model. Container/ TVector and TArray store color arrays for material definitions and light lists. Meta/ type traits enable compile-time color space detection. The primary header Color.h defines the public color type used across the Codebase.
