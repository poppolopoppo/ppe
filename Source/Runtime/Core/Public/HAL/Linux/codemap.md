# Source/Runtime/Core/Public/HAL/Linux/

## Responsibility
This folder implements the Linux-specific HAL (Hardware Abstraction Layer) providing platform-native interfaces for core system operations on Linux systems. It concrete-izes the generic HAL abstractions for the Linux kernel, system calls, and libc facilities, enabling cross-platform compatibility while leveraging Linux-specific primitives for performance and correctness. The Linux HAL provides implementations for platform memory management, atomics, threading, file I/O, endianness, time, process management, and console dialog support tailored to Linux environments.

## Design
The Linux HAL design concrete-izes the generic FGenericPlatform* base classes with Linux-native implementations. Platform memory uses mmap/munmap for virtual memory management and /dev/zero for zero-initialized pages, with VirtualAlloc/free fallback for compatibility. Atomics employ GCC built-in atomics (__sync_fetch_and_add, __sync_compared_exchange) for lock-free operations. Thread creation uses pthread_create with pthread_attr_t for stack size and scheduling policy configuration, and supports pthread fiber mapping through user-space scheduling. File I/O leverages open/read/write/unlink/posix_fadvise for file operations, with memory mapping via mmap. Endianness conversion uses __builtin_bswap32/__builtin_bswap64 or a lookup table for byte-swap operations. Time queries employ clock_gettime(CLOCK_MONOTONIC) for high-resolution monotonic clocks and gettimeofday for compatibility. Process management uses fork/vfork/execve for process creation and waitpid for process termination. Console dialog support is typically a no-op on headless Linux servers, with full implementations for desktop environments.

## Flow
Linux HAL initialization during FPlatform::Initialize() resolves the target platform and creates an FLinuxPlatform* instance. Memory allocation: FPlatformMemory::Allocate() calls mmap with PROT_READ|PROT_WRITE|PROT_EXEC and MAP_ANONYMOUS|MAP_PRIVATE, or falls back to brk/sbrk for small allocations. Atomics: FPlatformAtomics::FetchAndAdd() compiles to __sync_fetch_and_add for lock-free operations. Thread creation: FPlatformThread::Create() calls pthread_create, sets up thread attributes, and registers the thread with the task scheduler's fiber mapping. File I/O: FPlatformFile::OpenFile() calls open() with appropriate flags (O_RDONLY, O_WRONLY, O_RDWR, O_CREAT, etc.); Read/Write use read()/write() syscalls; mmap is used for memory-mapped files. Endian conversion: FPlatformEndian::Byteswap32/64() compiles to __builtin_bswap32/64. Time queries: FPlatformTime::Now() calls clock_gettime(CLOCK_MONOTONIC) for monotonic timestamps. Shutdown: FPlatform::Shutdown() cleans up platform-specific resources, destroys thread attributes, and unmaps any memory-mapped regions.

## Integration
Linux HAL/ is the concrete realization behind the Public HAL interface on Linux platforms. Container/ TVector and TArray use FLinuxPlatformMemory for all memory operations. Smart pointers TRefPtr/TWeakPtr depend on FLinuxPlatformAtomics for reference count operations. Thread/ FTaskManager and FTaskScheduler use FLinuxPlatformThread for OS thread creation and fiber scheduling. Maths/ scalar types may use PlatformMaths SIMD intrinsics lowered for x86_64 ARM. Diagnostic/ FLeakDetector, FStackMarker, and FProfiler integrate with Linux-level tracing. IO/ FFileSystem::FindFile and FFileStream depend on FLinuxPlatformFile for concrete file operations. Modular/ FDynamicModule uses dlopen/dlsym/FPlatformLoadLibrary for dynamic module loading on Linux. The Linux HAL is conditionalized via PPE_HAL_TARGETALIAS() macros, which resolve to FLinux* implementations at compile time when targeting Linux.
