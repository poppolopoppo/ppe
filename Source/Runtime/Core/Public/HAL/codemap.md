# Source/Runtime/Core/Public/HAL/

## Responsibility
This folder implements the Hardware Abstraction Layer (HAL) providing platform-independent interfaces for core system operations: PlatformMacros, PlatformMemory, PlatformAtomics, PlatformThread, PlatformFile, PlatformEndian, PlatformMaths, PlatformLowLevelIO, PlatformConsole, PlatformDialog, PlatformProcess, PlatformProfiler, PlatformString, PlatformHash, PlatformMisc, PlatformTime, TargetPlatform, WindowsTargetPlatform, LinuxTargetPlatform, PlatformIncludes, PlatformCallstack, PlatformCrash, PlatformDebug, PlatformFile, and PlatformHash. The HAL serves as the bridge between Engine code and OS-specific implementations, enabling cross-platform compatibility for Windows, Linux, and console platforms. Platform macros (PPE_HAL_TARGETALIAS, PPE_PLATFORM_*) resolve to platform-specific implementations at compile time. Memory management, atomics, threading, file I/O, endianness, and console dialog support are the primary HAL responsibilities.

## Design
HAL design follows the target-abstraction macro pattern: `PPE_HAL_TARGETALIAS(Component)` maps to platform-specific implementations (`FWindows*`, `FLinux*`, `FConsole*`). Generic fallbacks (`FGenericPlatform*`) provide baseline implementations when platform-specific code is not available. Windows and Linux implementations inherit from `FGenericPlatform*` base classes, ensuring interface consistency. Target platform detection uses `ETargetPlatform` enum and `ITargetPlatform` interface. Memory operations use `FPlatformMemory` with `VirtualAlloc`/`VirtualFree` on Windows and `mmap`/`munmap` on Linux. Atomics use platform intrinsics (`Interlocked*`, `__atomic_*`). Thread creation uses `CreateThread`/`pthread_create` with fiber support. File I/O uses `CreateFile`/`open` + memory mapping. Endianness conversion is handled via `FPlatformEndian` enum and compile-time byte-swap intrinsics.

## Flow
Platform initialization: `FPlatform::Initialize()` resolves target platform via `PPE_HAL_TARGETALIAS` macros and creates the appropriate `FPlatform*` instance. Thread creation: `FPlatformThread::Create()` -> OS-specific thread creation -> fiber registration with `FTaskScheduler`. Atomic operations: `FPlatformAtomics::FetchAndAdd()` -> `InterlockedExchangeAdd` (Windows) or `__sync_fetch_and_add` (Linux). File I/O: `FPlatformFile::OpenFile()` -> `CreateFile` (Windows) or `open`/`mmap` (Linux) -> `FFile` handle. Endian conversion: `FPlatformEndian::Byteswap()` -> platform intrinsics or lookup table. Profiler integration: `FPlatformProfiler::BeginFrame()` / `EndFrame()` -> OS-level tracing. Shutdown: `FPlatform::Shutdown()` -> cleanup of platform-specific resources in reverse initialization order.

## Integration
HAL/ is the lowest-level dependency in the Engine, directly integrated by all other subsystems. Container/ TVector and TArray use PlatformMemory for allocator-backed memory. Allocator/ FVirtualAllocator<FMemoryDomain> queries FPlatformMemory for OS-level memory usage. Memory/ smart pointers TRefPtr/TWeakPtr depend on FPlatformAtomics for reference count operations. Thread/ FTaskManager and FTaskScheduler use FPlatformThread for OS thread creation and FPlatformAtomics for lock-free operations. Maths/ TScalarVector and TScalarMatrix operations may use PlatformMaths SIMD intrinsics. Diagnostic/ FLeakDetector, FStackMarker, and FProfiler all integrate with FPlatformProfiler. IO/ FFileSystem::FindFile and FFileStream depend on FPlatformFile for concrete file operations. Modular/ FDynamicModule uses FPlatformLoadLibrary/FPlatformFreeLibrary for dynamic module loading. The HAL/PlatformMacros.h header defines the `PPE_HAL_TARGETALIAS()` macro used across the entire codebase.
