# Source/Runtime/Core/Public/Diagnostic/

## Responsibility
This folder implements the Engine's diagnostics and profiling infrastructure: FStackMarker, FLeakDetector, Benchmark, FLogger, FLoggerCategory, FLoggerSiteInfo, FLoggerMessage, ELoggerVerbosity, FDebugFunction, FGlobalFeedbackContext, IFeedbackContext, FFearureProgressBar, FBuildVersion, FCurrentProcess, FIgnoreList, FIgnoreKey, FIgnoreScope, Callstack.h, DecodedCallstack.h, DebugFunction.h, Exception.h, FeedbackContext.h, IgnoreList.h, LeakDetector.h, Logger_fwd.h, Logger.h, StackMarker.h. FStackMarker provides RAII-scoped stack tracing for profiling scopes. FLeakDetector tracks all allocations via a compressed radix trie (FBlockCompressedRadixTrie) keyed by callstack hash. Benchmark offers high-resolution timing via FPlatformTime and FCounter/FTimer. FLogger and categories implement configurable verbosity (ELoggerVerbosity) and site-based message routing. FDebugFunction exposes script-debuggable functions. FBuildVersion and FCurrentProcess provide build identification and process-scoped singletons. FIgnoreList/FIgnoreScope support RAII-based suppression of logging and leak tracking.

## Design
Diagnostic design is centered on scoped RAII markers and singleton global state. FStackMarker constructor pushes a stack trace entry onto a thread-local stack; destructor pops it, recording duration for profiling. FLeakDetector uses FBlockCompressedRadixTrie to map block hashes (derived from callstack PC sampling) to leak reports, with FBlockTracker managing per-allocator tracking lists. Benchmark::Start/Stop reads FPlatformTime (QueryPerformanceCounter / clock_gettime) via FCounter/FTimer, supporting nested timing scopes. FLogger writes to configurable sinks (console, file, debug output) based on ELoggerVerbosity categories (Log, Warning, Error, Display). FDebugFunction provides a registry of name->function mappings for script-level introspection. FCurrentProcess (TSingleton) offers process ID, command line, and working directory at startup. FIgnoreScope pushes/pops a bitmask onto a thread-local stack, allowing callers to suppress logging/leak tracking for RAII-scoped regions.

## Flow
Profiling scope: FStackMarker marker("FunctionName") at function entry; marker destruction at exit records scope duration to FPlatformProfiler. Leak detection: FLeakDetector::TrackAllocation(ptr, callstack) inserts into FBlockCompressedRadixTrie; periodic compaction merges buckets. Benchmark timing: Benchmark::Start() records FPlatformTime::Now(); user code executes; Benchmark::Stop() delta = Now() - start; delta reported via FCounter. Logging flow: FLogger::Log(category, verbosity, message) -> FLoggerCategory::Matches(verbosity) -> FLoggerSiteInfo::Write(message) -> platform sink. Debug function lookup: FDebugFunction::Find(name) -> registered callback -> invoke with args. Process info: FCurrentProcess::Get() TSingleton::Get() returns cached process metadata. Ignore scope: FIgnoreScope constructor sets thread-local ignore bitmask; destructor restores previous mask. Leak report generation: FLeakDetector::GenerateReport() walks FBlockCompressedRadixTrie -> FCallstack -> FDecodedCallstack -> FDbghelpWrapper symbol resolution.

## Integration
Diagnostic/ components are integrated across the entire Engine. Thread/ FStackMarker is used in function prologues/epilogues for callstack profiling; FLeakDetector::TrackAllocation is called by FTrackingAllocator on every allocation. Memory/ TRefPtr/TWeakPtr increment/decrement trigger FLeakDetector refcount checks. Container/ TVector<T> and TArray<T> iteration may be annotated with FStackMarker for profiled traversal. Maths/ math operation loops may be bracketed by Benchmark scopes. IO/ FArchive read/write operations may be timed with Benchmark for I/O profiling. HAL/ PlatformProfiler integrates FStackMarker data into OS-level profiling pipelines. Modular/ FModularServices registration/logging passes through FLogger. IO/ FTextWriter and FLogger share the same ELoggerVerbosity enum for consistent output filtering. The Diagnostic/Logger.h header is included in nearly every subsystem source file for diagnostic enablement.
