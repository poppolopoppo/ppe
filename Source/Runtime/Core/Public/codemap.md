# Source/Runtime/Core/Public/

## Responsibility
This folder serves as the parent aggregator for all Public-facing Core subsystems, exposing the Engine's core interfaces, types, and implementations to other modules and subsystems. It encompasses the publicly visible layers: Allocator, Container, Diagnostic, HAL (Windows, Linux, Generic), IO, Maths, Memory, Meta, and Time. The Public folder organizes types that are safe to include in client code, with PPE_CORE_API marking DLL export/import boundaries on Windows. It provides the primary surface area for the Engine's data structures, memory management, threading primitives, diagnostics, and platform abstractions, organized so that downstream modules can depend on stable, documented interfaces without exposing internal implementation details.

## Design
The Public folder follows a consistent design pattern where each subfolder provides a complete set of types and utilities for its domain, with template parameters allowing allocator-aware customization (e.g., TVector<T, Allocator>, TArray takes Allocator). The HAL subfolder implements the target-abstraction macro pattern: PPE_HAL_TARGETALIAS(Component) resolves to platform-specific implementations (FWindows*, FLinux*, FGeneric*) at compile time, with Generic fallbacks providing baseline behavior. Smart pointers (TRefPtr, TWeakPtr, TUniquePtr) use platform-optimized atomics (Interlocked* on Windows, __atomic_* on Linux) for reference counting. Containers default to ALLOCATOR(Container) when no allocator is specified, and all allocator-aware templates integrate with FMemoryTracking and FLeakDetector. Type traits from Meta/ (is_pod_v, is_ebco_eligible_v) gate optimizer fast-paths across all subsystems. The folder enforces compile-time dimensional analysis via Meta::TUnit<T,R> and provides CRTP-based singletons (TSingleton) for global state.

## Flow
Public API exposure flows from the modular system downward: FModularDomain registers services through FModuleStaticRegistration, which iterates over Public container types (TArray, TVector) of module interfaces. Container allocation flows through the Allocator layer, with every template instantiation requesting memory from the chosen FMalloc variant. Smart pointer creation (TRefPtr::Create(), TWeakPtr::Init()) triggers atomic increment/decrement via FPlatformAtomics. Maths type operations (TScalarVector::operator+, FTransform::GetTranslation()) are inlined and compile-template specialized. Diagnostic registration (FLogger::Init(), FStackMarker::Push()) occurs at module startup and function entry/exit respectively. HAL initialization (FPlatform::Initialize()) resolves target platform macros and creates the appropriate platform-specific instance. IO subsystem initialization (FFileSystem::Mount()) sets up the mounting point trie for virtual path resolution. Shutdown flows reverse the initialization order, with leak detection reporting, profiler data flushed, and platform resources released.

## Integration
The Public folder is the primary integration point for all Engine subsystems: Container types (TVector, TArray) are used by every other subsystem for data storage; Smart pointers (TRefPtr, TWeakPtr) from Memory/ store elements across Thread, IO, Maths, and Diagnostic components; Maths types (TScalarVector, TScalarMatrix, FQuaternion, FTransform) form the numeric foundation used by Rendering, Physics, and IO; Threading primitives (FTaskManager, FCompletionPort, FAtomic*) integrate with Task and Fiber subsystems; Diagnostics (FLogger, FLeakDetector, FStackMarker) are included in source files across all modules; IO types (FString, FArchive, FFileStream) are the most ubiquitous data movement layer, passed as parameters across all modules; Memory/ smart pointer control blocks integrate with Allocator tracking; HAL/ Platform* implementations are the concrete realizations behind the Public interface; Meta/ type traits and utilities gate template specialization decisions; and Time/ timestamps and FTimer are used by Benchmark and Profiling systems. The Public folder's types are the most cross-referenced in the Codebase.
