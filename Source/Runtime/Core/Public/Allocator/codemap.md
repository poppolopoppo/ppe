# Source/Runtime/Core/Public/Allocator/

## Responsibility
This folder implements the Engine's memory allocation infrastructure: FMallocBinned, FMallocBinned2, FMallocBitmap, FMallocMipMap, FMallocStomp, FMalloc, FAllocatorPolicy, FNew, FBucketAllocator, FCascadedAllocator, FPageAllocator, FSlabAllocator, FBitmapAllocator, FPageAllocator, FTrackingAllocator, FVirtualAllocator, FStlAllocator, FStompAllocator, and FSystemAllocator. Allocators define the raw memory acquisition and release policy that containers and smart pointers depend upon. Allocator policies (FVirtualAllocator<Domain>, FCascadedAllocator, FTrackingAllocator) add tracking, batching, and domain scoping on top of the base FMalloc. Specialized allocators serve distinct patterns: FBitmapAllocator manages bit-level allocation maps, FSlabAllocator services fixed-size class allocations, FPageAllocator backs large virtual memory pages, and FBinned allocator splits size classes into bins. The folder also provides AllocatorHelpers, Allocation_fwd, and New-definition infrastructure used throughout the codebase.

## Design
Allocator design centers on the FAllocatorPolicy concept, a policy class that FMalloc and its variants satisfy. FMallocBinned partitions allocations into size bins (power-of-two or user-defined) for fast size-class lookup. FSlabAllocator groups same-sized objects into slabs for cache-efficient allocation and deallocation, tracking free lists per size class. FBitmapAllocator maintains a bit-level map of free/used pages, ideal for fine-grained allocation from a pre-reserved region. FPageAllocator wraps OS-level VirtualAlloc/ mmap for large page-aligned mappings. FCascadedAllocator chains multiple sub-allocators, delegating size-class requests and aggregating tracking. FTrackingAllocator adds leak-tracking metadata (block tags, callstack capture) by wrapping any base allocator. All allocators expose Allocate/Deallocate with debug flags (STATS, STOMP), and integrate with FMemoryTracking and FLeakDetector for production leak detection. Alignment is enforced via CACHELINE_ALIGNED and platform intrinsics.

## Flow
Allocation request arrives via Allocate(bytes, alignment) or AllocatorBlock(bytes). Size class determination routes to the appropriate bin/slab/bitmap path. Base OS memory is acquired by FPageAllocator via VirtualAlloc/ mmap if the size class has no free block. Tracked allocators record the calling file/line in FBlockHeader metadata. Deallocation calls Deallocate(ptr) which returns the block to the free list/bitmap and clears tracking metadata. Periodic garbage collection or leak detection scans FTrackingAllocator's block hash table. Cascaded allocator forwards the request to the appropriate sub-allocator based on size class. Allocator statistics (AllocatedBytes, MaxAllocations, TotalAllocations) are updated and exposed via FPlatformMemory for profiling introspection.

## Integration
Allocator implementations are the foundational dependency for every container in Container/ (every template takes an Allocator param). Memory/ smart pointers TRefPtr, TWeakPtr, TInSituPtr, and TUniquePtr all use the system allocator as their default and integrate with FTrackingAllocator for leak reporting. HAL/ PlatformMemory queries FVirtualAllocator<FMemoryDomain> for OS-level memory usage statistics. Thread/ lock-free structures (TConcurrentQueue, TAtomicPool, TAtomicRefPtrPool) use FSlabAllocator or FBitmapAllocator for per-thread slab management. Maths/ scalar types and SIMD containers rely on FMemoryPool for aligned allocation. Diagnostic/ FLeakDetector tracks all allocations through FBlockHeader metadata rooted in FTrackingAllocator. IO/ FFileSystem and FArchive allocate bulk data and buffer pages through FPageAllocator. The primary header AllocatorBase.h defines the interface implemented by all concrete allocator variants.
