# Source/Runtime/Core/Public/Thread/Task/

## Responsibility
This folder implements the priority work-stealing scheduler execution model for the Engine's public threading interface, including the task completion port mechanism, worker queue management, and fiber pool integration. It owns the FTaskQueued struct, per-worker priority heaps, and the consume loop that distributes tasks across worker threads. The folder also implements the FTaskFiberPool for cooperative multitasking and integrates with the public Task scheduler API.

## Design
The design centers on FTaskQueued, which carries a priority tag (ETaskPriority), a pending FTaskFunc, and a SCompletionPort for wake-up synchronization. Per-worker queues use VECTORMINSIZE(Task, FTaskQueued, 32) with a MIN_MinMaxHeap to maintain priority order. The work-stealing algorithm packs priority and revision into a single size_t key via priority_firstbit_ (24 bits), enabling O(1) priority comparison. FTaskScheduler maintains VECTOR(Task, FWorkerQueue_) of these per-worker queues, each protected by a FCriticalSection barrier. The fallback path uses a single CONCURRENT_PRIORITY_QUEUE for lock-free consumption. FTaskFiberPool maps coroutine fibers to worker threads, allowing tasks to yield via the completion port and resume without OS thread preemption.

## Flow
Application code calls FTaskScheduler::Produce(priority, task, pport), which creates an FTaskQueued and dispatches it to a worker queue via round-robin: workerIndex = insertion_order_preserving_priority % numWorkers. The producer try-locks the worker's barrier; on success, the task is pushed onto the priority heap and Push_MinMaxHeap re-establishes heap order, then _onTask.notify_one() wakes a consumer. A worker calls Consume(workerIndex, &pop), which iterates through worker queues checking HasHigherPriorityTask_ and attempting to pop from the local priority heap; if empty, it waits on the _onTask condition variable. When a task is dequeued, the worker loop in FTaskManagerImpl::Consume runs the task function. RunAndWaitFor produces a task and immediately consumes it synchronously. The fiber pool pulls tasks from the worker queue, yields back via the completion port, and re-queues when resumed.

## Integration
Integration connects to Source/Runtime/Core/Private/Allocator/ (memory for task queues and fiber stacks via FMallocProxy), Source/Runtime/Core/Private/Maths/ (random generator used when USE_PPE_TASK_SCHEDULER_SHUFFLING is enabled for task shuffling), and Source/Runtime/Core/Private/Thread/ (the parent folder containing the main scheduler and manager). Worker threads consume allocated memory from the allocator, and the random generator influences task ordering in shuffling mode. See Source/Runtime/Core/Private/Thread/Task/TaskScheduler.h for the full scheduler interface and Source/Runtime/Core/Private/Thread/Task/TaskManagerImpl.h for the thread manager implementation.
