# Source/Runtime/Core/Public/IO/

## Responsibility
This folder implements the Engine's I/O system: FString, FStringView, FStaticString, FText, FTextWriter, FTextReader, FArchive, FFileStream, FBufferedStream, FCompressedStream, FFormat, FFormatHelpers, FFormatFunctor, FOffset, FPointer, FQuoted, FDurationInMs, FCompressedStreamReader, FCompressedStreamWriter, FDeferredStreamReader, FDeferredStreamWriter, FFileSystem, FFileSystemToken, FFilename, FDirpath, FBasename, FExtname, FMountingPoint, FFileSystemTrie, FFileSystemToken, FRegexp, FTextFormat, FTextMemoization, FArchiveState, FBulkData, FArchiveHelpers, FStreamProvider, FStreamProvider-inl, FStream_fwd, FFileSystem_fwd, FFileSystemToken_fwd, and Format-inl/Format. FString and FStringView provide null-terminated and view string types with allocator awareness. FArchive provides serialization/deserialization with chunk-based formatting. FFileSystem abstracts platform file operations with trie-based path resolution. FFormat and functors provide type-safe formatted output. FRegexp implements regular expression matching. Compressed streams transparently handle LZJB decompression. All types are allocator-aware and integrate with the modular system and smart pointers.

## Design
I/O design centers on the FArchive abstraction for serialization and the FFileSystem for path resolution. FString<TAlloc> is a template on allocator, defaulting to ALLOCATOR(IO), enabling custom memory policies. FStringView is a non-owning string reference into FString or TCHAR arrays. FArchive supports chunk-based serialization with FArchiveState tracking (BeginLoad, EndLoad, BeginPostLoad, etc.). FFileSystem uses FMountingPoint + FFileSystemTrie (PatriciaTrie) for virtual path resolution, falling back to FPlatformFile HAL calls. FFormat functor family (FFormatFunctor, FOffset, FPointer, FQuoted, FDurationInMs) provides type-safe format arguments for FString::Format. FRegexp wraps platform regex facilities (PCRE, RegEx) with TMatch results. Compressed streams (FCompressedStreamReader/Writer) transparently apply LZJB compression around any FArchive or FFileStream. FDeferredStreamReader/Writer defer I/O until explicitly Read()/Write() called, useful for async asset loading. FFileSystemToken provides a hierarchical token system (FFilename > FDirpath > FBasename > FExtname) with operator/ overpath joining.

## Flow
String creation: FString::FromString(const TCHAR*) or FString::Append(...) allocates via stored allocator. String view: FStringView::Get() returns const TCHAR* without ownership. Archive serialization: FArchive << TString or FString reads/writes length-prefixed data; FFormat functor formats arguments into a TCompactInt length prefix. File resolution: FFileSystem::FindFile(Filename) -> FMountingPoint::Resolve -> FFileSystemTrie::Find -> FPlatformFile::FileExists. Format output: FString::Format(args...) matches FFormatFunctor arguments by type (FOffset, FPointer, FQuoted, FDurationInMs). Regex matching: FRegexp::Match(input) -> FMatch results with captured groups. Compressed I/O: FCompressedStreamReader::Read() decompresses LZJB bytes on the fly; writer compresses and flushes. Deferred stream: FDeferredStreamReader::IsReady() checks; Read() performs the actual I/O. Token resolution: FFileSystemToken::Combine(path1, path2) -> hierarchical token construction. Mounting: FFileSystem::Mount(path) -> FMountingPoint::Add -> trie rebalance.

## Integration
IO/ types are the primary data movement layer used by every subsystem. Container/ TVector<TArray> and TArray<uint8> store serialized payloads read through FArchive. Maths/ TScalarVector and TScalarMatrix elements are serialized via FArchive << operator. Thread/ async file reads use FFileStream and FCompressedStreamReader from the FTaskPool. Memory/ FMemoryStream and CachedMemoryPool back FFileStream buffers. Meta/ TAutoStruct and reflection data are serialized through FArchive << TAutoStruct. Diagnostic/ FBenchmark measures FArchive read/write throughput. HAL/ PlatformFile is the concrete impl behind FFileSystem::FindFile and FFileStream. Modular/ FModuleStaticRegistration reads/writes module state through FArchive. IO/ FString and FStringView are the most ubiquitous types in the Codebase, passed as function parameters across all modules. The Format-inl.h and Format.h headers define the formatting backbone used by FText, FString, and logging.
