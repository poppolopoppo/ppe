# Source/Runtime/Core/Public/Container/

## Responsibility
This folder encapsulates all core container types used throughout the Engine: TVector, TArray, TSparseArray, TDeque, TList, TBitSet, TBitMask, TBitTree, and associative containers including THashMap, THashSet, TFlatMap, TFlatSet, TDenseHashMap, TDenseHashSet, TPerfectHashing, TAssociativeVector, TToken, and TTree containers (TBitTree, TPatriciaTrie, TBurstTrie, TTernarySearchTree). Containers are allocator-aware template parameters, defaulting to ALLOCATOR(Container) when unspecified. This folder also provides bit manipulation primitives (BitMask, BitSet, ByteMask) and token/token hash infrastructure (Token, StringHashMap, StringHashSet). The container layer is the primary data structure foundation for all Engine subsystems, from rendering lists to actor arrays to serialization buffers.

## Design
Containers follow an allocator-aware template design where the Allocator template parameter governs all memory operations, enabling pluggable memory policies (FMBinned, FSlabHeap, FPageAllocator, FBitmapAllocator, FTrackingAllocator). Empty Base Class Optimization (EBCO) is applied via TCompressedPair and is_ebco_eligible_v to eliminate padding for empty allocators. POD fast-paths using is_pod_v<T> enable memcpy/memmove optimization for suitable types. Bit containers (TBitSet, TBitMask, TBitTree) provide space-efficient boolean/integral storage. Tree structures (TPatriciaTrie, TBurstTrie, TTernarySearchTree) deliver compact key->value mapping without external dependencies. Flat associative containers (TFlatMap, TFlatSet) trade logarithmic lookup for cache-friendly linear search. All containers are header-only or template-heavy, minimizing linker footprint.

## Flow
Data enters a container via construction/initialization (default, list, map, set constructors) or via Add/Emplace/Find operations. Element access follows Find->GetByIndex or iterator patterns. Iteration uses range-based for with TConstIter/TIter, or explicit ForEach lambdas. Removal uses RemoveBySwap, RemoveAt, or RemoveAll. Deletion triggers destructor calls and deallocates memory via the stored Allocator. Bit containers support Set/Test/Reset operations on individual bits. Tree containers support Insert/Find/Remove with logarithmic complexity. After destruction, container memory is returned to the allocator's free pool. Container notifications (OnContainerChanged) propagate to observing subsystems through delegate events.

## Integration
Container types integrate directly with Allocator/ for all memory operations (every container template takes an Allocator param). Smart pointers TRefPtr and TWeakPtr from Memory/ store containers and individual elements. Maths types TScalarVector and TScalarMatrix use TArray internally for coefficient storage. Thread tasks schedule work items stored in TQueue or TConcurrentQueue. IO streams FFileStream and FBufferedStream read/write TArray payloads. Modular system FModuleStaticRegistration iterates TArray of module interfaces. Diagnostic FLeakDetector tracks all allocations through TAllocatorTraits-aware containers. HAL PlatformMemory queries TVector of memory regions. The container/Array.h header is the most included file in the Codebase, foundational to every other subsystem.
