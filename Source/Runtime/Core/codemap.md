# Source/Runtime/Core/

## Responsibility
This folder serves as the root aggregator for the entire PPE Core module, organizing all Public and Private subsystems under a single hierarchy. It encompasses the core foundational layers: allocators, containers, math, memory, threading, diagnostics, IO, time, HAL, meta-programming, and modular system integration. The root map provides an overview of the module's architecture, directory structure, and cross-cutting dependencies, serving as the entry point for navigating the Core subsystem. It documents how each top-level subfolder relates to the others and how they collectively form the Engine's foundation.

## Design
The Core module is structured as a two-tier hierarchy of Public and Private folders, each containing specialized subdomains such as Allocator, Container, Diagnostic, HAL, IO, Maths, Memory, Meta, and Time. Public folders expose interfaces and implementations usable by external modules, while Private folders contain implementation details, internal schedulers, and lower-level utilities. Cross-cutting patterns unify the design: the FAllocatorPolicy / TAllocatorTraits template policy, the FNonCopyableNorMovable base for resource handles, the FMemoryTracking + FLeakDetector unified leak detection system, the FGenericPlatform* / platform-specific HAL abstraction pattern with PPE_HAL_TARGETALIAS() macros, the CRTP-based TSingleton<Derived> pattern for singletons, and extensive template metaprogramming via Meta::TypeTraits for compile-time decisions. The module is module-aware, with FModularDomain driving phased startup loading, and all major types guarded by PPE_CORE_API for DLL export/import.

## Flow
Initialization flows from the modular system (FModularDomain → FModuleStaticRegistration) through Core subsystems in dependency order: first the HAL resolves the target platform and creates FPlatform* instances; then Memory and Allocator subsystems initialize their tracking structures; Containers and Smart Pointers are constructed on top of the allocator; Maths types provide numeric operations used throughout; Threading subsystems (FTaskManager, FTaskScheduler, FCompletionPort) set up fiber-based concurrent execution; Diagnostics (FLogger, FLeakDetector, FStackMarker) register their sinks and markers; IO subsystem initializes the file system and archive format; Time and Meta subsystems establish their global state. Shutdown reverses this order, with leak detection reporting final state, profiler data flushed, and platform-specific resources cleaned up in reverse initialization sequence.

## Integration
The root Core folder integrates with every other subsystem in the Engine: Containers/TVector and TArray depend on Allocator/ for all memory operations; Smart pointers TRefPtr/TWeakPtr from Memory/ store elements and rely on FPlatformAtomics for refcount operations; Maths/ TScalarVector and TScalarMatrix types are used across rendering, physics, and gameplay; Thread/ FTaskManager and FTaskScheduler create OS threads via FPlatformThread and manage fiber scheduling; Diagnostics/ FLeakDetector and FLogger are included in nearly every subsystem source file; IO/ FArchive and FFileStream handle serialization and file resolution; Memory/ smart pointers provide ownership semantics for all container elements; HAL/ PlatformMemory and PlatformAtomics are the lowest-level dependencies; Time/ timestamps and FTimer are used for benchmarking and profiling; Color/ provides type-safe color types for rendering; and the root Atlas (codemap.md) itself serves as the directory map for the entire module.
