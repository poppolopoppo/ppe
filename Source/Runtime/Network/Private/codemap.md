# Source/Runtime/Network/Private/

## Responsibility
The Private networking folder implements the detail-level infrastructure underlying the public networking API, containing platform-specific socket implementations, connection context management, and protocol detail classes not exposed in the public header hierarchy. This folder provides the concrete implementations of `FSocket::`, `FListener::`, and `FServicingPort::` back-ends, along with `FHandShaker` variants for protocol upgrades, `FSocketBuffered` buffered I/O implementation, and platform-specific address resolution. The design separates public interface (`Source/Runtime/Network/Public/`) from private detail (`Source/Runtime/Network/Private/`), enabling cross-platform compatibility while isolating OS-specific code (Windows Winsock, POSIX sockets) in this folder. A `FNetworkModule` singleton manages the lifecycle of private subsystems during module startup and shutdown.

## Design
Key patterns include the platform abstraction pattern where platform-specific implementations conform to the `FSocket` interface defined in public headers; the connection context pattern where `FServicingPort` holds per-connection state (`FGuid` UID, `FHandShaker` owner, `FSocketBuffered` socket, keep-alive timeout) and is allocated on the heap via `TRefPtr`; the buffered I/O pattern where `FSocketBuffered` implements a slab-based read buffer with growable capacity, minimizing syscalls for protocol-level parsing; the handshaker strategy pattern where `FHandShaker` supports multiple upgrade paths (WebSocket upgrade, TLS handshake) via derived classes with a common `Dispatch()` interface; and the RAII scope pattern where `FConnectionScope` for `FSocket` and `FConnectionScope` for `FListener` auto-manage connect/disconnect lifecycles. Private types use detailed `FString` memory management and are not for direct client consumption.

## Flow
Module startup flow: `FNetworkModule.Start()` initializes the platform socket subsystem (WSAStartup on Windows, no-op on POSIX), creates the `FListener` instance, and registers the module with the RTTI database; per-connection flow: `FListener.Accept()` returns a new platform socket wrapped in `FSocket`, which is then wrapped in `FServicingPort` along with an `FSocketBuffered` for buffered reads and an `FHandShaker` for protocol negotiation; the servicing loop calls `FServicingPort.Servicing(ctx)` which reads requests via `FSocketBuffered::Read()`, dispatches to `OnRequest()`, writes responses, and checks keep-alive timeout; if timeout expires, the connection is gracefully closed; connection teardown: `OnDisconnect()` is called, `FServicingPort` is destroyed, and the underlying `FSocket` is closed; module shutdown: `FNetworkModule.Shutdown()` cleans up the platform socket subsystem and destroys all remaining components.

## Integration
Connects upward to `Source/Runtime/Network/Public/` as all private types implement the interfaces exposed by public headers; `FSocket::` private implementation satisfies the public `FSocket` contract; `FListener::` private implementation satisfies the public `FListener` contract. Connects downward to `Source/Runtime/Network/Private/Socket/` and `Source/Runtime/Network/Private/Http/` for further detail specialization. Connects to `Source/Runtime/Remoting/` as `FRemotingServer` uses private `FServicingPort` and `FHandShaker` implementations for request handling and protocol upgrades. Connects to `Source/Runtime/VFS/` as HTTP responses may carry serialized transactions. Real paths: `Source/Runtime/Network/Public/NetworkModule.h`, `Source/Runtime/Network/Private/Socket/`, `Source/Runtime/Network/Private/Http/`, `Source/Runtime/Network/Private/Socket` (Windows), `Source/Runtime/Network/Private/Socket` (POSIX).
