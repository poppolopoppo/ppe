# Source/Runtime/Network/Private/Socket/

## Responsibility
The Private Socket folder implements the platform-specific socket detail infrastructure underlying the public `FSocket` API, containing Windows Winsock and POSIX socket implementations, platform address conversion, and socket option management. This folder is not for direct client consumption; instead, it provides the concrete `FSocket::` implementation that the public `Source/Runtime/Network/Public/Socket/Socket.h` declares. The design separates platform abstraction from the public interface, enabling cross-platform compatibility while isolating OS-specific code (Winsock2.h on Windows, sys/socket.h on POSIX). `FNetworkModule` singleton manages socket subsystem initialization (WSAStartup/WSACleanup on Windows) during module lifecycle.

## Design
Key patterns include the platform abstraction pattern where `FSocket::` has derived classes `FSocketWinSock` (Windows) and `FSocketPosix` (POSIX), both conforming to the same interface with `Connect()`, `Read()`, `Write()`, `Disconnect()`, `Close()`, `IsValid()`, and `SetTimeouts()`; the socket option pattern where `SetNagleEnabled()` calls `setsockopt(socket, IPPROTO_TCP, TCP_NODELAY...)` on Windows or `int one = 1; setsockopt(socket, IPPROTO_TCP, TCP_NODELAY, &one, sizeof(one));` on POSIX; the timeout pattern where `SetReadTimeout()`/`SetWriteTimeout()` configure `setsockopt(socket, SOL_SOCKET, SO_RCVTIMEO...)` or `setsockopt(socket, SOL_SOCKET, SO_SNDTIMEO...)` with `FTime` duration conversion; the RAII pattern where the `FSocket` destructor always calls `Close()` ensuring `closesocket()`/`close()` is invoked even on error paths; and the address conversion pattern where `FAddress` private conversion methods translate between platform `sockaddr_in`/`sockaddr_in6` and `FAddress::FInternal`. All private socket classes are friend classes of `FServicingPort` and `FSocketBuffered` for efficient buffer management.

## Flow
Socket creation and initialization: `FSocket::Construct()` creates the platform-specific derived instance (WinSock or Posix), initializes the socket handle to `INVALID_SOCKET`/`-1`, and marks as invalid; `FSocket::Open(const FAddress&)` calls platform `socket(AF_INET/AF_INET6, SOCK_STREAM, IPPROTO_TCP)`, checks for `INVALID_SOCKET`, and sets the handle; `FSocket::Connect(const FAddress&)` calls platform `connect()` with the stored address, checks return value, and on success sets the valid flag; read/write flow: `FSocket::Read(void* buffer, int bytes)` calls platform `recv()` with timeout enforcement from `SetReadTimeout()`, returns bytes read or -1 on error/disconnect; `FSocket::Write(const void* buffer, int bytes)` calls platform `send()` with timeout enforcement from `SetWriteTimeout()`, returns bytes sent or -1 on error/disconnect; connection close: `FSocket::Disconnect()` calls `Close()` which invokes `closesocket()`/`close()`, resets the handle to `INVALID_SOCKET`, and clears the valid flag; error handling: any platform error sets `WSAGetLastError()`/`errno` and marks the socket invalid, with `IsValid()` returning false for subsequent operations.

## Integration
Connects to `Source/Runtime/Network/Private/Http/` as `FSocketBuffered` uses private `FSocket` implementation for its underlying transport; `FHandShaker` may wrap private `FSocket` for protocol upgrades. Connects to `Source/Runtime/Network/Public/Socket/` as the public `FSocket` type is implemented by these private detail classes. Connects to `Source/Runtime/Remoting/` as `FRemotingServer` uses private `FSocket` instances for transport connections; `FHandShaker` protocol upgrades originate from socket operations.
