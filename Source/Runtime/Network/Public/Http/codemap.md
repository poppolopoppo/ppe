# Source/Runtime/Network/Public/Http/

## Responsibility
The Public HTTP folder exposes the HTTP server and client APIs implemented by the PPE runtime, serving as the primary integration point for HTTP-based communication including remoting endpoints, REST APIs, and web services. This folder provides `FHttpServer` for hosting HTTP listeners with configurable worker pools, `FHttpClient` for persistent HTTP connections with cookie and post map support, and `FHttpRequest`/`FHttpResponse` message types. The design separates server infrastructure (`FHttpServer`, `FListener`) from client operations (`FHttpClient`) and message types (`FHttpRequest`, `FHttpResponse`), enabling both inbound request handling and outbound request generation. All types in this folder are declared in public headers usable by any module in the project.

## Design
Key patterns include the worker pool pattern where `FHttpServer.Start(workerCount)` spawns a configurable number of worker threads, each processing connections from a shared listening socket; the persistent connection pattern where `FHttpClient` maintains a `FSocketBuffered` connection across multiple requests, reusing cookie/post/query maps; the request-response cycle where `FHttpServer` invokes virtual hooks (`OnConnect`, `OnRequest`, `OnDisconnect`) allowing derived classes to customize behavior; and the handshaker pattern where `FHandShaker` supports protocol upgrades (WebSocket switch, TLS negotiation) during connection setup. `FHttpServer` uses a `TThreadSafe` event-driven model for connection acceptance, while `FHttpClient` employs a request queue and response parser. Message types `FHttpRequest` and `FHttpResponse` are designed for round-trip serialization via `FJsonSerializer` or `FBinarySerializer`.

## Flow
HTTP server flow: `FHttpServer.Start(workerCount)` initializes a worker pool and begins listening on the bound `FAddress`; each worker's event loop calls `FListener.Accept()` which returns a new `FSocket` or `FSocketBuffered` wrapping the raw connection; the worker creates a `FServicingPort` per-connection context and invokes `OnConnect()`; the servicing loop reads incoming `FHttpRequest` via `FSocketBuffered::Read()`, dispatches to `OnRequest(FServicingPort&, FHttpRequest&)`, generates an `FHttpResponse` with status and body, writes the response back via `FServicingPort.WriteResponse()`, and finally calls `OnDisconnect()` when the connection closes. HTTP client flow: `FHttpClient.Get/Head/Post(uri, response)` constructs an `FHttpRequest` with method, URI, headers, and optional body; sends the request over the persistent `FSocketBuffered` connection; reads the `FHttpResponse` with status code, headers, and body; returns the response object to caller. Cookie/post/map state is maintained across requests when `FHttpClient` retains the underlying socket connection.

## Integration
Connects to `Source/Runtime/Network/Public/Socket/` as `FHttpServer` and `FHttpClient` both depend on `FSocketBuffered` for transport; `FHandShaker` may be invoked during connection setup for protocol upgrades. Connects to `Source/Runtime/Remoting/` as `FRemotingServer` uses `FHttpServer` for request routing and endpoint dispatch; `FRTTIEndpoint` and `FSwaggerEndpoint` register routes via the HTTP server. Connects to `Source/Runtime/VFS/` as HTTP response bodies may contain serialized transactions that reference VFS paths. Real paths: `Source/Runtime/Network/Public/Http/Server.h`, `Source/Runtime/Network/Public/Http/Client.h`, `Source/Runtime/Network/Public/Http/Request.h`, `Source/Runtime/Network/Public/Http/Response.h`, `Source/Runtime/Network/Public/Socket/HandShaker.h`.
