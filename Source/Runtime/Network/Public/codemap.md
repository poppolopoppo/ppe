# Source/Runtime/Network/Public/

## Responsibility
The Public networking folder exposes the canonical networking API surface implemented by the PPE runtime, providing types and classes usable by client code and other modules. This includes `FSocket`, `FListener`, `FSocketBuffered`, `FHttpClient`, `FHttpServer`, `FHandShaker`, `FServicingPort`, `FAddress`, `FUri`, and `FNetworkModule`. The folder serves as the primary include point (`Network/Public/Network.h`) for all networking declarations, with public headers forwarding to their respective submodule headers (`Http/`, `Socket/`). The design ensures that client code depends only on stable public interfaces, while implementation details remain in the Private subfolder hierarchy.

## Design
Key patterns include the RAII wrapper pattern where `FSocket` and `FListener` encapsulate platform socket handles with deterministic cleanup via destructors, the buffered I/O pattern via `FSocketBuffered` for efficient HTTP-level parsing, and the server-client asymmetry where `FHttpServer` owns a worker pool and virtual callback hooks while `FHttpClient` owns persistent connections and credential maps. `FAddress` provides platform-independent IP:port representation with `ToString()` and `Parse()` utilities. `FUri` supports URI parsing, building, and query string manipulation. `FHandShaker` uses a strategy pattern for protocol upgrades (WebSocket handshake, TLS negotiation). All public types are designed for cross-platform compatibility, with platform-specific details deferred to Private implementations. The `FNetworkModule` singleton is exposed via `Get()` for module lifecycle management, and all public types are ref-counted or have well-defined ownership semantics.

## Flow
Client code includes `Source/Runtime/Network/Public/Network.h` to access all public networking types. For socket operations: create `FSocket`, call `Connect(address)`, perform read/write via `Read()`/`Write()`, then allow destructor to close. For HTTP server: call `FHttpServer.Start(workerCount)` → worker pool initializes → `FListener.Accept()` → `FServicingPort` per connection → `OnRequest` callback → response write → `OnDisconnect`. For HTTP client: create `FHttpClient`, call `Get/Head/Post(uri)` → `FSocketBuffered` connection established → `Process(request)` → read response body → receive `FHttpResponse` object. Connection lifecycle is managed by `FConnectionScope` RAII wrappers that auto-connect on construction and auto-disconnect on destruction.

## Integration
Connects downward to `Source/Runtime/Network/Private/` as all public types have corresponding Private implementation details under `Network/Private/`. Connects to `Source/Runtime/Network/Public/Http/` and `Source/Runtime/Network/Public/Socket/` as subdirectories containing further public specialization. Connects to `Source/Runtime/Remoting/` as `FRemotingServer` inherits from `FHttpServer` and uses public networking types for request transport. Connects to `Source/Runtime/VFS/` as HTTP responses may carry serialized transactions. Real paths: `Source/Runtime/Network/Public/Network.h`, `Source/Runtime/Network/Public/Network_fwd.h`, `Source/Runtime/Network/Public/Http/Server.h`, `Source/Runtime/Network/Public/Http/Client.h`, `Source/Runtime/Network/Public/Socket/Socket.h`, `Source/Runtime/Network/Public/Socket/Listener.h`, `Source/Runtime/Network/Public/Socket/ServicingPort.h`, `Source/Runtime/Network/Public/Socket/Address.h`, `Source/Runtime/Network/Public/Socket/HandShaker.h`.
