# Source/Runtime/Network/Public/Socket/

## Responsibility
The Public Socket folder exposes the TCP socket wrapper API implemented by the PPE runtime, providing a platform-abstraction layer for network connectivity used by both the HTTP subsystem and direct client code. This folder provides `FSocket` for raw socket operations with timeout and Nagle control, `FSocketBuffered` for buffered I/O optimized for HTTP-level parsing, and `FAddress`/`FUri` for network addressing and URI manipulation. The design emphasizes RAII resource management, efficient buffered reading for protocol parsing, and protocol-agnostic socket operations that can be used directly or through higher-level abstractions like `FListener` and `FHttpServer`.

## Design
Key patterns include the RAII wrapper pattern where `FSocket` encapsulates a platform socket handle (`SOCKET` on Windows, `int` on POSIX) with deterministic cleanup via destructor, ensuring `closesocket()`/`close()` is called even on exception paths; the buffered I/O pattern where `FSocketBuffered` provides a slab-allocated read buffer for efficient protocol parsing without repeated system calls; the timeout control pattern where `FSocket.SetReadTimeout()`/`SetWriteTimeout()` configure `setsockopt`/`SetTimer` for per-operation timeouts; and the Nagle algorithm control via `SetNagleEnabled(true/false)` to minimize latency for interactive protocols. `FAddress` provides IP+port storage with `Parse()`/`Build()` static methods and `ToString()` for human-readable representation. `FUri` supports URI parsing, authority extraction, and query string manipulation. All public socket types are designed for thread-safe use with external synchronization, and `FSocket` provides `IsValid()` for checking open state.

## Flow
Socket connect flow: application creates `FSocket`, calls `Connect(const FAddress&)` which resolves the address and invokes platform `connect()`, then checks `IsValid()`; on success, the application reads/writes via `Read(void*, int)`/`Write(const void*, int)`, which invoke platform `recv()`/`send()` with timeout enforcement; the application calls `Disconnect()` or allows the destructor to invoke `Close()`, which calls platform `closesocket()`/`close()` and clears the valid flag. Buffered socket flow: application creates `FSocketBuffered` with an existing `FSocket` or creates one independently; `FSocketBuffered::Read()` fills the internal slab buffer from the underlying socket, returning data to the caller while preserving unconsumed bytes for the next call; `FSocketBuffered::Write()` transmits data through the underlying socket; the buffered socket manages its own read/write pointers and automatically refills the buffer as needed. Connection teardown: `FSocketBuffered` destructor flushes any remaining buffer data and closes the underlying `FSocket` if owned.

## Integration
Connects to `Source/Runtime/Network/Public/Http/` as `FHttpClient` and `FHttpServer` both use `FSocketBuffered` for efficient HTTP-level parsing; `FHandShaker` may wrap `FSocket` for protocol upgrades. Connects to `Source/Runtime/Network/Public/` as the public API entry point through `Network.h`. Connects to `Source/Runtime/Remoting/` as `FRemotingServer` uses `FSocket`/`FSocketBuffered` for transport connections; `FHandShaker` protocol upgrades originate from socket operations. Real paths: `Source/Runtime/Network/Public/Socket/Socket.h`, `Source/Runtime/Network/Public/Socket/Listener.h`, `Source/Runtime/Network/Public/Socket/ServicingPort.h`, `Source/Runtime/Network/Public/Socket/Address.h`, `Source/Runtime/Network/Public/Socket/HandShaker.h`, `Source/Runtime/Network/Public/Socket/SocketBuffered.h`.
