# Source/Tools/IODetouring/

## Responsibility
This folder implements DLL-based IO interception and transparent tracing for child processes. The IODetouring subsystem injects a DLL into target processes using Microsoft Detours, hooking 40+ Win32 APIs to capture and log all file system and process creation operations. It serves as the foundational tracing layer for the IOWrapper infrastructure, enabling distributed build IO wrapping by transparently monitoring and recording I/O operations without modifying the target application's source code. The subsystem also provides path mounting and remapping capabilities for remote build scenarios, allowing build tools to redirect file paths to alternate locations.

## Design
The module follows a launcher-injector pattern centered on the `FIODetouringHooks` singleton (`IODetouringHooks.h:14`), which manages hook installation and teardown. Hook installation occurs in `DllMain::OnProcessAttach_` (`IODetouring.cpp:32`), which calls `AttachDetours()` to attach Microsoft Detours to target APIs including `Hook_CreateFileW/A`, `Hook_ReadFile`, `Hook_WriteFile`, and `Hook_CreateProcessW/A` (`IODetouringHooks.h:62,190,92`). Tracing output is funneled through `FIODetouringTblog` (`IODetouringTblog.h`), which writes to a named pipe consumed by the IOWrapper's IOCP message pump. Path mounting and remapping are handled by `FIODetouringFiles` (`IODetouringFiles.h`), which maintains a list of mounted paths and ignored applications via environment variables. The design uses genealogy tracking to maintain parent/child process tree awareness, and console signal forwarding forwards Ctrl+C as Ctrl+Break to child processes.

## Flow
Data flow begins when `IOWrapper.exe` creates a named pipe and invokes `DetourCreateProcessWithDllEx()` to inject `IODetouring.dll` into a target process. Upon DLL attachment, `DllMain` triggers `OnProcessAttach_`, which calls `AttachDetours()` to install hooks on 40+ Win32 APIs. When a hooked API such as `CreateFileW` or `ReadFile` is called, the detour redirects execution to the detour function, which logs the operation via `FIODetouringTblog::Get().Printf()` to the named pipe. The IOCP loop in `IOWrapper` (`Private/main.cpp:382`) reads completion packets from the pipe and outputs the logged data. Control flow flows through the process tree: the parent `IOWrapper` monitors child process lifecycles and cleans up hooks upon process termination. Path remapping is applied at hook time, where requested paths are translated against the `wzzMountedPaths` table before the actual API call is forwarded.

## Integration
This folder integrates directly with `Source/Tools/IOWrapper/` (`Source/Tools/IOWrapper/codemap.md`), which acts as the launcher and UI layer. The injection mechanism uses `DetourCreateProcessWithDllEx()` from the IOWrapper's `Private/main.cpp:238` to load `IODetouring.dll` into each target process. Hooked APIs relay tracing data through `FIODetouringTblog`'s named pipe, which the IOWrapper's `IOCompletionLoop_()` (`Private/main.cpp:382`) consumes via overlapped I/O. Path remapping configurations defined here are used by the IOWrapper's `RunProcessWithDetours()` (`Private/main.cpp:484`) when constructing the `FIODetouringPayload`. The folder also interfaces with `Source/Programs/IOWrapperTest/` (`Source/Programs/IOWrapperTest/codemap.md`) for integration validation, where test processes are launched under detour injection to verify tracing correctness and path remapping behavior under distributed build conditions.
