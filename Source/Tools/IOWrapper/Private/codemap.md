# Source/Tools/IOWrapper/Private/

## Responsibility
This directory contains the private implementation of the IOWrapper launcher, including the main orchestration, pipe client, IOCP message pump, and console signal handling. These components are not exposed in the public header but are the operational core of the wrapper.

## Design
`RunProcessWithDetours()` (`Private/main.cpp:484`) is the entry point: it parses command-line arguments, builds an `FIODetouringPayload` with the target executable, pipe name, mounted paths, and ignored application patterns, then creates a named pipe for receiving trace logs from the injected DLL. `FIOWrapperPipeClient` (`Private/main.cpp:268`) implements the overlapped I/O client that reads trace data from the pipe, using completion ports to avoid blocking. `IOCompletionLoop_()` (`Private/main.cpp:382`) is the central message pump: it calls `GetQueuedCompletionStatus()` on the pipe's completion port, processes each trace log entry, and outputs it to the console or a log file. `ConsoleHandler_()` (`Private/main.cpp:469`) registers as a Ctrl+C handler for the parent process, converting the signal to Ctrl+Break for the child process via the injection mechanism. The payload structure includes fields for the child process command line, the named pipe instance name, the count of mounted paths, and a pointer to the path remapping array.

## Flow
The launcher begins by creating the named pipe and then forking the target process via `DetourCreateProcessWithDllEx()` with `IODetouring.dll` pre-injected. The child process, now instrumented, hooks the 40+ Win32 APIs and writes each operation as a formatted trace entry to the named pipe. Meanwhile, the parent's `IOCompletionLoop_()` waits on the pipe's completion port. When a trace write completes, the IOCP delivers a completion packet containing the number of bytes written and a pointer to the overlapped structure. The pipe client reads the trace entry, formats it, and prints it to the console. If the user presses Ctrl+C, the console handler fires, which queues a Ctrl+Break to the child process via `GenerateConsoleCtrlEvent()`, ensuring the child terminates cleanly. After the child process exits, the loop drains any remaining pipe messages, prints a summary, and exits.

## Integration
The private implementation integrates directly with `Source/Tools/IODetouring/` (`Source/Tools/IODetouring/codemap.md`) at the DLL-injection level: the named pipe created here is the exact channel over which `FIODetouringTblog` writes trace data. The `FIODetouringPayload` constructed here matches the structure expected by the DLL's `OnProcessAttach_` hook installation sequence. Integration with `Source/Programs/IOWrapperTest/` (`Source/Programs/IOWrapperTest/codemap.md`) validates the full stack: the test harness launches processes through the wrapper, inspects the console output for trace entries, and verifies that path remapping and ignored-application filtering work correctly under distributed build scenarios.
