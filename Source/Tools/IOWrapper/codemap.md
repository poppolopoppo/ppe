# Source/Tools/IOWrapper/

## Responsibility
This folder implements the IOWrapper launcher and IOCP-based async logging infrastructure. The wrapper orchestrates DLL injection into child processes, manages the named pipe channel for trace data collection, and provides a console signal forwarding mechanism to propagate control events from parent to child processes. It serves as the primary user-facing tool for enabling transparent IO tracing across distributed build environments.

## Design
The module is centered on `RunProcessWithDetours()` (`Private/main.cpp:484`), the main orchestration function that parses command-line options, constructs the `FIODetouringPayload`, and creates the named pipe for IPC. `FIOWrapperPipeClient` (`Private/main.cpp:268`) implements the overlapped pipe client that reads trace log entries from the child process's writer end. `IOCompletionLoop_()` (`Private/main.cpp:382`) is the IOCP message pump that completes I/O operations on the pipe and forwards logged data to stdout or a log file. Console signal forwarding is handled by `ConsoleHandler_()` (`Private/main.cpp:469`), which intercepts Ctrl+C and converts it to Ctrl+Break for the child process, since Ctrl+C cannot be directly forwarded through the injection boundary. The `FIODetouringPayload` structure carries the pipe name, options, ignored applications list, and mounted path remapping configuration. Path remapping via `wzzMountedPaths` enables remote build support by translating child-process paths to host-file-system paths.

## Flow
The operational flow begins when the user invokes `IOWrapper.exe` with target application arguments. `RunProcessWithDetours()` constructs the payload and creates a named pipe for trace data. It then calls `DetourCreateProcessWithDllEx()` to inject `IODetouring.dll` into the child process, which begins hooking Win32 APIs and writing trace entries to the named pipe. The parent process's `IOCompletionLoop_()` enters an IOCP wait loop, reading completed I/O operations from the pipe and printing/logging the trace entries. If the child process terminates, the loop exits gracefully and the pipe is closed. Console events directed at the parent are intercepted by `ConsoleHandler_()` and forwarded to the child as Ctrl+Break, ensuring clean termination. Path remapping is applied at injection time: the `wzzMountedPaths` table translates any file paths the child process will reference, enabling the traced operations to be recorded against host-file-system locations rather than guest VM paths.

## Integration
The IOWrapper is the primary integration consumer of `Source/Tools/IODetouring/` (`Source/Tools/IODetouring/codemap.md`). The launcher calls `DetourCreateProcessWithDllEx()` to inject the DLL, and the named pipe created by the DLL is the IPC channel over which all traced operations flow. The `FIODetouringPayload` structure, constructed in `Private/main.cpp:238`, is passed to the DLL and contains the pipe name and remapping configuration. `Source/Programs/IOWrapperTest/` (`Source/Programs/IOWrapperTest/codemap.md`) tests the end-to-end integration, launching instrumented processes and validating that the captured trace stream matches expected patterns for the given application and path remapping configuration.
