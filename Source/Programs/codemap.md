# Source/Programs/

## Responsibility
Source/Programs/ aggregates standalone executables and test applications that demonstrate PPE engine capabilities and provide test harnesses for the modular system. This folder contains 6 programs: BuildRobot (CI/asset build orchestrator executed by the Go-based build system), ShaderToy (shader playground for experimenting with Vulkan compute and graphics shaders), VoxelCube (voxel rendering demo demonstrating the frame graph, BIH octree, and chunk-based mesh rendering), WindowTest (windowing test harness validating platform window creation, input handling, and integration with the fiber scheduler), UnitTest (test runner executing unit tests for engine containers, algorithms, and subsystems), and IOWrapperTest (test harness for the IOWrapper distributed build file system module). These programs serve as the primary integration points for the engine, each exercising specific subsystems and demonstrating the capabilities of the Runtime/, Extensions/, ContentPipeline/, and Tools/ folders. Each program follows the module lifecycle pattern (Start → PostStart → DutyCycle → PreShutdown → Shutdown) and initializes the core engine subsystems required for its functionality.

## Design
Source/Programs/ follows a demonstration-and-test design pattern where each program targets a specific engine subsystem or capability. BuildRobot/ is a Go-integrated CI orchestrator that triggers asset builds, runs the ContentPipeline/ BuildGraph DAG processor, and manages build pipelines across the engine's modular system. The Go build system generates BuildModules.generated.h from module JSON declarations, serving as the bridge between the Go build system and the C++ engine. ShaderToy/ is a shader experimentation tool that loads Vulkan compute and graphics shaders, demonstrating the RHI/ abstraction layer and RHIVulkan/ backend. It uses the fiber-based task scheduler for asynchronous shader compilation and resource loading. VoxelCube/ demonstrates the frame graph rendering pipeline, BIH (Bounding Interval Hierarchy) octree for spatial partitioning, and TCompressedPair empty-base optimization for descriptor set memory efficiency. It renders voxel data using the custom math library (TScalarVector, TQuaternion, FTransform) and the FBIH spatial structure. WindowTest/ validates platform window creation via FPlatformWindow, input handling through the fiber scheduler, and integration with the modular services registry. It tests window initialization, message pumping, and shutdown across the module lifecycle. UnitTest/ executes compiled unit tests for engine containers (TSparseArray, TVector, THashMap), algorithms, and core subsystems, leveraging the FLeakDetector and FLogger for memory and diagnostic reporting. IOWrapperTest/ specifically tests the IOWrapper/ distributed build file system module, verifying file redirection, mount point resolution, and cross-node file operation consistency. All programs use the PPE_DEFINE_AUTOPOD macro for RTTI reflection metadata and follow the engine's memory management conventions (custom allocators, TUniquePtr/TSharedBuffer ownership semantics).

## Flow
Source/Programs/ programs follow a consistent initialization and execution flow. At startup, each program initializes the modular system by calling the module registration anchors (extern "C" function pointers generated by the build system from `*-module.json` declarations). The program then starts core subsystems in dependency order: Core (allocators, containers, math) → Application (windowing, input) → RHI (rendering backend, with RHIVulkan for Vulkan) → RTTI (reflection metadata generation) → Serialize (format support as needed) → VFS (mount point resolution). After PostStart, the program enters its DutyCycle where it exercises its specific functionality: BuildRobot/ processes asset builds through ContentPipeline/'s BuildGraph, ShaderToy/ compiles and runs Vulkan shaders, VoxelCube/ renders voxel geometry using the frame graph and BIH octree, WindowTest/ processes window messages and input events, UnitTest/ runs compiled unit test suites, IOWrapperTest/ validates file system redirection operations. During DutyCycle, the FTaskManager with FTaskScheduler work-stealing scheduler distributes work across the thread pool. At PreShutdown and Shutdown, modules reverse through their lifecycle with deferred ReleaseMemory. Programs integrate with Tools/ (IOWrapperTest/ tests IOWrapper/, BuildRobot/ uses Go build system integration) and Extensions/ (ShaderToy/ and VoxelCube/ use RHIVulkan/; WindowTest/ uses ApplicationUI/ for ImGui features). Specific integration paths: BuildRobot/ → ContentPipeline/BuildGraph/ for asset processing → Texture/, MeshBuilder/, PipelineCompiler/; ShaderToy/ → RHI/ → Extensions/RHIVulkan/; VoxelCube/ → RHI/ → Extensions/RHIVulkan/ + Core/ math containers; WindowTest/ → Application/ + Core/; UnitTest/ → Core/ containers and algorithms; IOWrapperTest/ → Tools/IOWrapper/ → VFS/.

## Integration
Source/Programs/ integrates with all other top-level source folders to demonstrate and test engine capabilities. BuildRobot/ integrates with Source/ContentPipeline/ (BuildGraph, MeshBuilder, PipelineCompiler, PipelineReflection, Texture) for asset processing workflows, and with Source/Tools/IOWrapper/ for distributed build file management. ShaderToy/ integrates with Source/Runtime/RHI/ for the rendering abstraction and Source/Extensions/RHIVulkan/ for the Vulkan backend implementation, plus Source/Runtime/Core for math types (TScalarVector, TQuaternion) used in shader uniforms. VoxelCube/ integrates with Source/Runtime/RHI/ for the frame graph rendering pipeline, Source/Runtime/Core for math types and containers (TVector, TTransform, TQuaternion), and Source/Extensions/RHIVulkan/ for Vulkan-specific features (pipeline memory, descriptor sets, command buffers). WindowTest/ integrates with Source/Runtime/Application/ for windowing and input, Source/Runtime/Core for fiber scheduler and math types, and Source/Extensions/ApplicationUI/ for ImGui integration. UnitTest/ integrates with Source/Runtime/Core/ for container algorithms (TSparseArray operations, TVector manipulations, THashMap lookups), Source/Runtime/Serialize/ for serialization test data, and Source/Runtime/Core/Private/Diagnostic for leak detection and logging. IOWrapperTest/ integrates with Source/Tools/IOWrapper/ for distributed file system testing, Source/Runtime/VFS/ for mount point resolution, and Source/Runtime/Network/ for remote file operation simulation. Specific paths: Source/Programs/BuildRobot/ → Source/ContentPipeline/BuildGraph/ → Texture/, MeshBuilder/; Source/Programs/ShaderToy/ → Source/Runtime/RHI/ → Source/Extensions/RHIVulkan/; Source/Programs/VoxelCube/ → Source/Runtime/RHI/ → Source/Extensions/RHIVulkan/ + Source/Runtime/Core/; Source/Programs/WindowTest/ → Source/Runtime/Application/ + Source/Runtime/Core/; Source/Programs/UnitTest/ → Source/Runtime/Core/; Source/Programs/IOWrapperTest/ → Source/Tools/IOWrapper/ → Source/Runtime/VFS/.
