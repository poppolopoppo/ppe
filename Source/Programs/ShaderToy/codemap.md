# Source/Programs/ShaderToy/

## Responsibility
This folder implements the live GLSL shader playground, a windowed application that provides an interactive environment for editing and rendering GLSL fragments in real time. ShaderToy serves as a prototype platform for rendering pipeline experiments, live shader compilation, and ImGui-based UI prototyping. It is used by developers to iterate on fragment shaders quickly and validate visual output against changing inputs.

## Design
The module is built around `FApplicationWindow` as the base class (`WindowTest/ApplicationWindow.h`), providing the core windowing and RHI integration layer. The ImGui dockspace system is initialized at startup, providing a persistent UI layout with widgets for shader source editing, texture import, file dialog, and log viewing. Live recompilation is triggered on fragment shader file changes, which reloads the GLSL source, re-compiles the shader pipeline, and updates the rendering state without restarting the application. Shader inputs are uniform variables (`iTime`, `iMouse`, `iResolution`, `iFrame`, `iFrameRate`) that are automatically updated each frame. Four input channels (`iChannelResolution[4]`, `iChannel`) provide texture/buffer samplers that can be populated from imported images or memory buffers. A dummy source fallback renders a checkerboard pattern when no shader is loaded or compilation fails.

## Flow
The rendering flow begins at the main application loop, which processes OS messages and ImGui events. Each frame, uniform variables are updated (`iTime` increments, `iMouse` tracks cursor position, `iResolution` reflects the window size). The fragment shader source is read from disk; if the file modification time has changed since the last frame, the shader is re-compiled live. Compiled shader output is rendered to the screen as a full-screen quad. If live compilation fails, the error log is displayed via ImGui widgets and the checkerboard fallback is rendered. Input channels are sampled either from loaded textures or from memory buffers populated by other modules. The ImGui dockspace handles widget layout, including shader source import, file dialog interactions, texture memory usage display, and a log viewer for compilation errors.

## Integration
ShaderToy integrates with `Source/Extensions/ApplicationUI/` (`Source/Extensions/ApplicationUI`) for module loading and remoting service support. The ImGui dockspace widgets interact with the remoting module for remote rendering scenarios. The shader live-recompilation pipeline interfaces with `Source/ContentPipeline/PipelineCompiler/` (`Source/ContentPipeline/PipelineCompiler/codemap.md`) for GLSL-to-SPIR-V compilation under the hood, though the live UI presents a simplified interface. `Source/Programs/WindowTest/` (`Source/Programs/WindowTest/codemap.md`) shares the same `FApplicationWindow` base class, and both apps register themselves with the modular domain for lifecycle coordination. Asset textures can be imported via the UI channel, which integrates with `Source/ContentPipeline/Texture/` (`Source/ContentPipeline/Texture/codemap.md`) for compression and format conversion. The `FModularDomain` drives app lifecycle coordination across all programs.
