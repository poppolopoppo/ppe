# Source/Programs/WindowTest/

## Responsibility
This folder implements the RHI test harness, a comprehensive test suite for the rendering pipeline covering graphics, compute, ray tracing, command queues, and debugger integration. WindowTest extends `FApplicationWindow` and contains 50+ test files that exercise every major subsystem of the RHI, providing regression validation for the rendering engine's feature set.

## Design
The test harness is organized into subsystems that each target a specific RHI domain: Drawing tests (`Drawing_Draw*.cpp`, `Drawing_TraceRays*.cpp`, `Drawing_ShadingRate1.cpp`, `Drawing_ReadAttachment1.cpp`) validate the graphics pipeline, texture rendering, ray tracing, and attachment reading. Compute tests (`Compute_Compute*.cpp`, `Compute_AsyncCompute*.cpp`, `Compute_ArrayOfTextures*.cpp`, `Compute_PushConstant1.cpp`, `Compute_DynamicOffset1.cpp`) exercise shader compute functionality, async compute command queues, and push constant/dynamic offset handling. Queue tests (`Queue_CopyBuffer1.cpp`, `Queue_CopyImage*.cpp`) validate copy command operations between buffers and images. Debugger tests (`Debugger_ShaderDebugger*.cpp`, `Debugger_RayTracingDebugger1.cpp`) provide shader source-level debugging and ray tracing debug support. Compiler annotation tests (`Compiler_Annotation*.cpp`) validate the pipeline compiler's reflection and annotation parsing. Each test file follows a common pattern: initialize the RHI, run the specific test operation, check the result via structured assertions, and log the outcome. The harness uses `EXTERN_LOG_CATEGORY` for test outcome reporting and provides a console command list for selecting and running individual test groups.

## Flow
The test harness flow begins at the console entry point, which initializes the RHI subsystem and enters the test selection menu. The user can select a test category (Drawing, Compute, Queue, Debugger, Compiler) and a specific test file. The selected test initializes its required RHI resources, executes the test operation, and checks the result against expected assertions. Outcomes are logged via `EXTERN_LOG_CATEGORY` at info, warning, or error levels. The console event loop allows the user to run multiple tests in sequence, skip tests, or exit the harness. After all selected tests complete, the harness reports a summary of passed/failed tests and exits with an appropriate return code. The test selection menu is driven by the file listing in the `Private/` subdirectories, automatically discovering test files at startup.

## Integration
WindowTest integrates with `Source/Runtime/RHI/` (`Source/Runtime/RHI`) for the core rendering infrastructure, frame graph, and command queue management. It shares the `FApplicationWindow` base class with `Source/Programs/ShaderToy/` (`Source/Programs/ShaderToy/codemap.md`) and `Source/Programs/VoxelCube/` (`Source/Programs/VoxelCube/codemap.md`), and all three register with the `FModularDomain` for coordinated lifecycle. The Drawing and Compute test subsystems interface with `Source/ContentPipeline/PipelineCompiler/` (`Source/ContentPipeline/PipelineCompiler/codemap.md`) for shader compilation validation. Debugger tests integrate with the remoting module via `Source/Extensions/ApplicationUI/` (`Source/Extensions/ApplicationUI`). Test output and regression results feed into the CI pipeline, where BuildRobot (`Source/Programs/BuildRobot/codemap.md`) may pre-build assets before test execution.
