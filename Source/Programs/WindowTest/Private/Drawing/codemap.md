# Source/Programs/WindowTest/Private/Drawing/

## Responsibility
This directory implements the Drawing test subsystem, validating the graphics pipeline through a set of tests that cover basic draw operations, ray tracing, shading rate, and attachment reading. These tests exercise the full RHI graphics command path from resource creation to pixel output.

## Design
The drawing test definitions follow a consistent pattern: each test creates the required RHI resources (textures, buffers, pipelines), sets up the scene geometry and materials, and issues a draw command list. The test suite includes `Drawing_Draw*.cpp` for basic triangle and mesh rendering, `Drawing_TraceRays*.cpp` for ray tracing with bottom-level and top-level acceleration structures, `Drawing_ShadingRate1.cpp` for shading rate tier validation, and `Drawing_ReadAttachment1.cpp` for render target attachment sampling and validation. Each test uses structured assertions to check the result, such as comparing pixel values against expected ranges, verifying that the correct number of samples were rendered, or confirming that the ray tracing output contains valid acceleration structure hits. The tests are designed to be independent of specific RHI implementations, depending only on the base `RHI::IFrameGraph` and resource creation APIs.

## Flow
The test flow begins when the test function creates the required RHI resources and sets up the scene. The geometry and materials are configured, and the pipeline is bound. The draw command list is issued, either a simple triangle draw or a complex ray tracing dispatch. For ray tracing tests, the test builds bottom-level acceleration structures from the scene geometry and a top-level structure from instance transforms. After the draw/dispatch completes, the test reads back the result: for draw tests, the pixel color is read from the render target and compared against expected values; for ray tracing tests, the acceleration structure hit data is read back and validated; for shading rate tests, the sample count is verified; for attachment read tests, the sampled value is checked against the expected format. The result is logged via `EXTERN_LOG_CATEGORY`, and the test function returns a pass/fail status.

## Integration
The Drawing subsystem integrates with `Source/Runtime/RHI/` (`Source/Runtime/RHI`) for pipeline creation, resource management, and ray tracing acceleration structure building. It interfaces with `Source/ContentPipeline/PipelineCompiler/` (`Source/ContentPipeline/PipelineCompiler/codemap.md`) for shader compilation validation, as the test shaders are compiled through the pipeline compiler before the test runs. The test definitions are auto-discovered by the WindowTest harness at startup, and the results are reported through the harness's console summary. The drawing tests may also exercise `Source/Runtime/Application/` (`Source/Runtime/Application`) window management for resize and focus events.
