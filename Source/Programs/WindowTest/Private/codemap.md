# Source/Programs/WindowTest/Private/

## Responsibility
This directory contains the private implementation of the WindowTest RHI test harness subsystems, including Drawing, Compute, Queue, Debugger, and Compiler test modules. These components exercise the full RHI feature set through automated test cases, validating graphics pipeline operations, compute shader dispatch, command queue operations, shader source-level debugging, and pipeline compiler annotation parsing. The test harness extends FApplicationWindow and provides a console-driven interface for selecting and running individual test suites, with structured logging via EXTERN_LOG_CATEGORY and automatic test discovery through the RTTI_TEST_REGISTRY macro.

## Design
The private implementation centers on the FWindowTestHarness base class, which provides core infrastructure for all test subsystems: RHI device creation, swap chain setup, command queue acquisition, and result reporting. Each test subsystem (Drawing, Compute, Queue, Debugger, Compiler) follows a consistent pattern: initialize required RHI resources, execute the test operation, read back the result, and check structured assertions. The harness provides a console command list for test selection, skipping, and exit. Test definitions register themselves at static initialization time using RTTI_TEST_REGISTRY, enabling automatic discovery at harness startup. Resource creation patterns follow the RHI's buffer, texture, pipeline, and command list APIs, with synchronization provided by fences and barriers. Memory management uses TPtrRef smart pointers for resource handles, and error reporting follows the EXTERN_LOG_CATEGORY macro format with pass/fail status and timing information.

## Flow
The orchestration flow begins when the harness creates the RHI device and swap chain, then enters the console event loop. The user can select a test category (Drawing, Compute, Queue, Debugger, Compiler) and a specific test file via console commands. The RunTest method dispatches to the appropriate private subsystem. Each subsystem initializes its required RHI resources, executes the test operation, and reads back the result. The harness collects the result, logs it via EXTERN_LOG_CATEGORY, and returns to the console menu. After all selected tests complete, the harness reports a summary of passed/failed tests and shuts down the RHI device cleanly. The registry of test files is auto-discovered from the Private subdirectories at startup. Per-subsystem flow: Drawing tests create pipelines and render geometry, Compute tests dispatch compute kernels, Queue tests submit copy commands, Debugger tests enable the debug layer and validate breakpoint hits, and Compiler tests invoke the pipeline compiler's reflection API.

## Integration
This folder integrates with Source/Runtime/RHI/ (Source/Runtime/RHI) for the core rendering infrastructure, frame graph, and command queue management. It shares the FApplicationWindow base class with Source/Programs/ShaderToy/ (Source/Programs/ShaderToy/codemap.md) and Source/Programs/VoxelCube/ (Source/Programs/VoxelCube/codemap.md), and all three register with the FModularDomain for coordinated lifecycle. The Drawing subsystem interfaces with Source/ContentPipeline/PipelineCompiler/ (Source/ContentPipeline/PipelineCompiler/codemap.md) for shader compilation validation. Debugger tests integrate with the remoting module via Source/Extensions/ApplicationUI/ (Source/Extensions/ApplicationUI). Test results feed into the CI pipeline, where BuildRobot (Source/Programs/BuildRobot/codemap.md) may pre-build assets before test execution. The public types are consumed by CI scripts through Source/Programs/WindowTest/Public/ (Source/Programs/WindowTest/Public/codemap.md).
