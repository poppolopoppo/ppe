# Source/Programs/BuildRobot/Private/

## Responsibility
This directory contains the private implementation details of the BuildRobot headless orchestrator, including the console entry point, build graph execution loop, and integration with the ContentPipeline subsystems. These components are the operational core of the CI/asset build orchestrator.

## Design
The private implementation centers on the console application's `Main()` function, which initializes the `FBuildEnvironment`, parses the build configuration from a descriptor file, and drives the three-phase pipeline. The build graph execution loop calls `FBuildEnvironment::ScanAll()` to discover assets, then `FBuildEnvironment::BuildAll()` to process nodes in dependency order, followed by `FBuildEnvironment::CleanAll()` to remove intermediate files. The `IBuildExecutor` interface queues nodes for parallel execution across available CPU cores, and the build cache (`IBuildCache`) is consulted before each build step to skip already-processed assets. RTTI-enabled revision tracking (`FBuildRevision`) ensures that only assets with changed source data are rebuilt. The private implementation also handles progress reporting through `EXTERN_LOG_CATEGORY` structured logging, and cancellation via console event callbacks.

## Flow
The orchestration flow begins when the console entry point reads the build configuration and instantiates the build environment. The Scan phase (`FBuildEnvironment::ScanAll()`) walks the content directory, populates the `FBuildGraph` with nodes, and records file hashes for revision tracking. The Build phase (`FBuildEnvironment::BuildAll()`) iterates through the graph, calling each node's `Import()` and `Process()` methods in topological order. The executor queues nodes for parallel processing, and the cache ensures that only dirty nodes are rebuilt. After building, the Clean phase (`FBuildEnvironment::CleanAll()`) removes generated artifacts and temporary files. Progress is logged via `EXTERN_LOG_CATEGORY` at info and warning levels, and the console monitors for cancellation requests. The flow terminates when all nodes are built or a fatal error is encountered.

## Integration
The private implementation integrates with `Source/ContentPipeline/BuildGraph/` (`Source/ContentPipeline/BuildGraph/codemap.md`) for the core DAG execution engine, with `Source/ContentPipeline/MeshBuilder/` (`Source/ContentPipeline/MeshBuilder/codemap.md`) for mesh import nodes, and `Source/ContentPipeline/PipelineCompiler/` (`Source/ContentPipeline/PipelineCompiler/codemap.md`) for shader compilation. The headless nature means no integration with Program folders' RHI or window subsystems. Output artifacts are consumed by `Source/Programs/VoxelCube/` and `Source/Programs/ShaderToy/` for test content validation, and the build orchestrator may be invoked as a prelude to test runs in `Source/Programs/UnitTest/` (`Source/Programs/UnitTest/codemap.md`).
