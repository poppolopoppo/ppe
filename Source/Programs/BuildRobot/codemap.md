# Source/Programs/BuildRobot/

## Responsibility
This folder implements the CI/asset build orchestrator, a headless application that drives the ContentPipeline build graph programmatically without requiring a window or RHI subsystem. BuildRobot extends `FApplicationConsole` and is used for automated asset builds, CI pipelines, and batch processing of content pipeline operations. Its primary job is to load the build graph, execute the scan-build-clean phases, and produce artifact outputs according to the configured build environment.

## Design
BuildRobot relies on the `FBuildEnvironment` (`Public/BuildEnvironment.h:15`) to provide platform, cache, executor, and logging services. The build orchestration follows the three-phase pipeline established by the ContentPipeline: Scan, Build, and Clean. Each phase uses dedicated context objects (`FScanContext`, `FBuildContext`, `FCleanContext`) to manage state and node discovery. The executor interface (`IBuildExecutor`) queues build nodes for parallel execution, while the build cache (`IBuildCache`) ensures that already-processed assets are not re-processed. BuildRobot's console entry point reads a build configuration descriptor, instantiates the build environment, and drives the graph execution loop until all nodes are complete or a fatal error halts the process. RTTI-enabled nodes (`FBuildRevision`) support revision tracking, ensuring that only genuinely changed assets are rebuilt.

## Flow
The orchestration flow begins when the console entry point parses the build configuration and initializes the `FBuildEnvironment`. The Scan phase (`FScanContext::Scan()`) walks the content directory, discovers assets, and adds nodes to the `FBuildGraph`. During the Build phase (`FBuildContext::Build()`), each node's `Import()` and `Process()` methods are called in dependency order, respecting the DAG structure. The executor queues nodes for parallel processing, and the cache checks are performed before each build step. After building, the Clean phase (`FCleanContext::Clean()`) removes intermediate artifacts. The console event loop monitors for cancellation requests and reports progress via structured logging. Results are aggregated atomically using `compare_exchange_weak` to ensure correctness under concurrent access.

## Integration
BuildRobot drives the `ContentPipeline` module (`Source/ContentPipeline/`) and interacts with `Source/ContentPipeline/BuildGraph/` (`Source/ContentPipeline/BuildGraph/codemap.md`) for DAG operations, `Source/ContentPipeline/MeshBuilder/` (`Source/ContentPipeline/MeshBuilder/codemap.md`) for mesh import nodes, and `Source/ContentPipeline/PipelineCompiler/` (`Source/ContentPipeline/PipelineCompiler/codemap.md`) for shader compilation nodes. The headless design means it does not integrate with any Program folder's RHI or window subsystem, but it may be invoked by CI systems that also manage `Source/Programs/WindowTest/` for regression validation. Output artifacts from BuildRobot feeds into `Source/Programs/VoxelCube/` and `Source/Programs/ShaderToy/` as pre-built asset packages for subsequent test runs.
