# Source/Programs/UnitTest/

## Responsibility
This folder implements the test runner, a console-based test orchestrator that runs test suites across the content pipeline and rendering subsystems. UnitTest extends `FApplicationConsole` and provides a framework for loading, initializing, and running test programs such as texture compression tests, RHI validation suites, and content pipeline integration tests.

## Design
The test runner centers on the console application entry point, which reads a test configuration and discovers test executables in the `Private/` and `Public/` subdirectories. Each test program follows a common interface: initialize the subsystems it depends on (RHI, content pipeline, texture compression, etc.), run the test operation, and report the result via structured logging. The `TPtrRef` smart pointer type is used throughout for resource management, and the `EXTERN_LOG_CATEGORY` macro provides structured test outcome reporting. The test runner provides a console command list for selecting and running individual test suites, and it supports running tests in sequence, skipping tests, or exiting the runner. Test results are aggregated and reported as a summary at the end of the session.

## Flow
The orchestration flow begins when the console entry point reads the test configuration and discovers available test executables. The user can select a test suite from the menu (e.g., texture compression, RHI validation, content pipeline integration). The selected test is loaded and executed, its subsystems are initialized, the test operation is run, and the result is read back. The outcome is logged via `EXTERN_LOG_CATEGORY`, and the console returns to the menu for further test selection. After all selected tests complete, the runner reports a summary of passed/failed tests and exits with an appropriate return code. The test discovery is auto-driven from the file system, making it easy to add new test programs without modifying the runner core.

## Integration
UnitTest integrates with `Source/ContentPipeline/` (`Source/ContentPipeline`) for content pipeline integration tests, particularly texture compression tests that exercise the `Source/ContentPipeline/Texture/` (`Source/ContentPipeline/Texture/codemap.md`) module. It also interfaces with `Source/Runtime/RHI/` (`Source/Runtime/RHI`) for RHI validation test suites. The headless design (extending `FApplicationConsole`) means it does not require a window or swap chain, but it may still initialize the RHI in headless mode for tests that need graphics resources. Output from UnitTest may feed into `Source/Programs/BuildRobot/` (`Source/Programs/BuildRobot/codemap.md`) for CI-driven asset builds, and test results may be consumed by the CI pipeline for regression validation.
