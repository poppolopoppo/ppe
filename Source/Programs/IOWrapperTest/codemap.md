# Source/Programs/IOWrapperTest/

## Responsibility
This folder implements the IO wrapper integration test harness, which validates the end-to-end integration between IOWrapper and IODetouring under controlled test conditions. The test harness launches instrumented processes under DLL injection, captures the trace stream through the named pipe, and verifies that the captured operations match expected patterns for the given application and path remapping configuration.

## Design
The test harness design follows a simple pattern: a test driver process launches a target application through IOWrapper with `DetourCreateProcessWithDllEx()`, injecting `IODetouring.dll`. The driver then connects to the named pipe created by the DLL and reads trace log entries. Each entry is validated against a set of expected operations (e.g., "CreateFileW on path X", "ReadFile on handle Y"). The harness supports configurable ignored application lists, mounted path remapping, and verification of the path remapping translations. Test outcomes are reported via `EXTERN_LOG_CATEGORY`, and the harness exits with a return code indicating the number of validation failures.

## Flow
The test flow begins when the driver process calls the IOWrapper's `RunProcessWithDetours()` function with the target executable and arguments. The wrapper creates the named pipe, injects the DLL, and the target process begins hooking Win32 APIs and writing trace entries to the pipe. The driver connects to the pipe's read end and enters a read loop, consuming trace entries as they are written. Each entry is validated against the expected operation set. If an entry does not match an expected pattern, it is logged as a discrepancy. The driver may also verify that path remapping was applied correctly by checking that the recorded paths correspond to the mounted paths configuration. After all expected operations are validated, or a timeout expires, the driver disconnects from the pipe and the target process is allowed to run normally (with tracing active) or is terminated. The result is reported as a pass/fail summary.

## Integration
This folder is the primary integration consumer of `Source/Tools/IODetouring/` (`Source/Tools/IODetouring/codemap.md`) and `Source/Tools/IOWrapper/` (`Source/Tools/IOWrapper/codemap.md`). The test harness uses the DLL injection mechanism and named pipe from IOWrapper, and the hook definitions and trace log format from IODetouring. The `FIODetouringPayload` structure and the `FIODetouringTblog` named pipe are the concrete integration points. Test scenarios may also verify that path remapping configurations defined in `Source/Tools/IODetouring/` are correctly applied and that the ignored applications list filters out the expected processes. The harness may also interact with `Source/Programs/BuildRobot/` (`Source/Programs/BuildRobot/codemap.md`) to validate that traced operations during automated builds match the expected pattern.
