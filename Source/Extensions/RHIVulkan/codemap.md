# Source/Extensions/RHIVulkan/

The RHIVulkan extension module provides the Vulkan-specific implementation of the rendering pipeline, serving as the primary integration point between the RHI abstraction layer and the Vulkan API. This module implements all Vulkan-specific backend logic for the engine's rendering subsystem, encompassing the frame graph architecture, command processing, resource management, and presentation pipeline.

## Responsibility
This module owns the Vulkan-specific implementation of the rendering pipeline. It provides the frame graph, command buffers, task graph, memory allocation, descriptor sets, pipelines, and swapchain presentation. It is the primary integration point between the RHI abstraction layer (Source/Runtime/RHI/) and the Vulkan API, implementing all Vulkan-specific backend logic. The module is structured into subfolders: Private/HAL (hardware abstraction layer), Public/Vulkan/Buffer (buffer management), Public/Vulkan/Common (shared utilities), and Public/Vulkan/RenderPass (render pass management).

## Design
The design is centered on the Vulkan frame graph architecture, where TVulkanTaskGraph<_Visitor> manages a dependency graph of TVulkanFrameTask<_Task> nodes, each representing draw, compute, copy, or ray tracing work. FVulkanCommandBuffer owns the command buffer and integrates task graph nodes via slab allocation. FVulkanCommandBatch tracks queue family usage and batch boundaries. TMemoryPool and TSlabHeap provide memory allocation with per-thread bucket caching and WAVL-tree free-block management. FVulkanDescriptorSetLayout handles descriptor set layout creation, pooling, and caching with hash-based deduplication. FVulkanPipelineResources manages dynamic resource bindings with type-safe Get<T>() access. The two-pass task processing model (Pass1 for setup/barriers, Pass2 for execution) is a deliberate design choice to separate dependency resolution from command execution. Key type names include FVulkanFrameGraph, TVulkanFrameTask, FVulkanDescriptorSetLayout, FVulkanPipelineResources, FVulkanCommandBuffer, FVulkanCommandBatch, FVulkanRenderPass, FVulkanFramebuffer, FVulkanSwapchain, and FVulkanDevice.

## Flow
The rendering flow begins with FVulkanFrameGraph constructing the dependency graph of TVulkanFrameTask<_Task> nodes. Pass1 processes each task: barriers are inserted, descriptors are bound, and dependencies are recorded. Tasks are added to the TVulkanTaskGraph<_Visitor>, which tracks inputs/outputs and automatic attachment. Pass2 executes each task: vkCmdDraw/Dispatch/TraceRays are called with the appropriate dynamic state. FVulkanCommandBuffer records commands into its slab allocator, and FVulkanCommandBatch tracks queue family usage. At present, synchronization relies on semaphores (RenderFinished[]), fences, and pipeline barriers within the task graph. Presentation flows through FVulkanSwapchain::Present(), which acquires the next image, waits on the render-finished semaphore, and calls vkQueuePresentKHR. The HAL layer (Private/HAL) translates RHI commands to Vulkan API calls, with memory allocation drawing from TMemoryPool and TSlabHeap.

## Integration
This module integrates with Source/Runtime/RHI/ through FVulkanDeviceAPI, which provides Vulkan device operations and creates buffer types consumed by the frame graph. Memory allocation draws from TMemoryPool in Source/Runtime/Core/Public/Memory/ and TSlabHeap in Source/Runtime/Core/Public/Allocator/. The swapchain and presentation flow connects to FVulkanSwapchain, which handles image acquisition, semaphore signaling, and vkQueuePresentKHR. Descriptor set layouts (FVulkanDescriptorSetLayout) are consumed by FVulkanPipelineResources, which binds resources to pipelines. The task graph (TVulkanTaskGraph<_Visitor>) is consumed by FVulkanCommandBuffer, which records command buffers for submission to queues. Ray tracing shader tables (FVulkanRayTracingShaderTable) integrate with the pipeline system for ray tracing workloads. Buffer management (FVulkanBuffer) integrates with FVulkanDevice for creation and destruction. Common utilities (FVulkanDevice, FVulkanRHI) are used across all Public/Vulkan/ subfolders.
