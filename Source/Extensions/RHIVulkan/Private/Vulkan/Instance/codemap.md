# Source/Extensions/RHIVulkan/Private/Vulkan/Instance/

## Responsibility
The Private Vulkan Instance folder contains the full Vulkan implementation for instance creation, device creation, surface creation, and queue family management. This is where all Vulkan-specific backend logic for instance and device setup is realized, implementing the integration between the RHI abstraction layer and the Vulkan API. The Private folder is not intended for inclusion in public engine headers; it contains the concrete implementations of all types declared in the Public folder.

## Design
The design implements FVulkanInstance with methods for surface creation (VkSurfaceKHR from window handle), device creation (with/without surface), and queue family management. Surface creation is platform-specific (Win32/X11/Wayland), creating the VkSurfaceKHR from the window handle and instance. Device creation has two overloads: one with a surface (back-buffer) and one headless. Queue family information is queried from the physical device, enumerating the available queues (graphics, compute, transfer, present). The present queue family index is used for swapchain presentation. The graphics queue family is used for command submission and rendering. All instance and device creation flows are implemented concretely here, hiding Vulkan API details behind the public interface declared in the Public folder.

## Flow
Instance creation begins with the construction of FVulkanInstance, which initializes the Vulkan instance with the required extensions and callbacks. Surface creation is performed by the CreateSurface() method, which is platform-specific (Win32/X11/Wayland), creating a VkSurfaceKHR from the window handle and instance. Device creation is performed by the CreateDevice() method, which has two overloads: one with a surface (back-buffer) and one headless. The CreateDevice() method queries queue family information from the physical device, enumerating the available queues (graphics, compute, transfer, present). The present queue family index is stored for use by the swapchain. The graphics queue family is used for command submission and rendering. At device destruction, the VkDevice is destroyed, and the surface is destroyed if it was created.

## Integration
This folder is the primary integration point for the entire Vulkan subsystem. It integrates with Source/Runtime/RHI/ through the FVulkanDeviceAPI, which creates the VkDevice and queues using the private instance implementation. The swapchain and presentation flow connects to FVulkanSwapchain, which handles image acquisition, semaphore signaling, and vkQueuePresentKHR. Descriptor set layouts are created and cached using the memory allocation subsystem (TMemoryPool, TSlabHeap). The command buffer system (FVulkanCommandBuffer) uses the created queues for submission. The fiber scheduler (Source/Runtime/Core/Private/Thread/Task/) queries queue family information when scheduling rendering work across worker fibers. Ray tracing shader tables (FVulkanRayTracingShaderTable) are created during device initialization and require the VkDevice and queue families.
