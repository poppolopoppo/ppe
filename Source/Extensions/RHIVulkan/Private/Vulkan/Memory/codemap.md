# Source/Extensions/RHIVulkan/Private/Vulkan/Memory/

## Responsibility
The Private Vulkan Memory folder contains the implementation of Vulkan-specific memory allocation, resource tracking, and synchronization primitives for the rendering pipeline. This folder implements the memory allocator types (TMemoryPool, TSlabHeap) that are used throughout the Vulkan subsystem, as well as synchronization primitives (semaphores, fences, events) that are used to coordinate command submission and execution across queues.

## Design
The design is centered on TMemoryPool, a lock-free block allocator with per-thread bucket caching and bundle recycling. Per-thread TLS bucket hints reduce contention, and the FBundleRecycler_ provides lock-free bundle reuse with std::atomic index tracking. The FBitTree_ tracks chunk-level allocation state. TSlabHeap is a general-purpose slab allocator using a WAVL tree for free-block management, supporting variable-size allocations with FBlockHeader metadata embedded in the allocation overhead. Memory domains are optionally supported via FMemoryTracking for leak detection. Synchronization primitives include Vulkan semaphores (binary/timeline), fences for command buffer completion, and pipeline barriers for GPU-side synchronization.

## Flow
Memory allocation begins with TMemoryPool::Allocate(), which acquires a block from the per-thread TLS bucket. If the bucket is empty, a new chunk is allocated from the heap and the bucket index is updated. TMemoryPool::Deallocate() returns the block to the bucket, and the FBundleRecycler_ may reuse it lock-free. TSlabHeap::Allocate() acquires a variable-size block from the WAVL tree, and TSlabHeap::ReleaseAll() releases all blocks, typically at the start of a new frame. Synchronization primitives are created during device initialization: semaphores (RenderFinished[]) are binary/semaphores that cycle through the RenderFinished array, fences track command buffer completion, and pipeline barriers are inserted within the task graph (Process1/Pass1) to coordinate GPU execution. Memory tracking (FMemoryTracking) optionally records allocation sites for leak detection.

## Integration
This folder is the central memory allocator for the entire Vulkan subsystem. TMemoryPool and TSlabHeap are consumed by all other Vulkan subsystems: buffers (FVulkanLocalBuffer, FVulkanSharedBuffer), images (FVulkanLocalImage, FVulkanSharedImage), descriptor sets (FVulkanDescriptorSetLayout), pipelines (FVulkanPipelineResources), and ray tracing (FVulkanRayTracingShaderTable). The RHI layer (Source/Runtime/RHI/) also draws from TMemoryPool for buffer allocation. The fiber scheduler (Source/Runtime/Core/Private/Thread/Task/) queries memory allocation patterns when scheduling rendering work across worker fibers. The swapchain (FVulkanSwapchain) uses memory from TMemoryPool for swapchain image storage. Synchronization primitives (semaphores, fences) are consumed by the command submission and presentation flow.
