# Source/Extensions/RHIVulkan/Private/Vulkan/Pipeline/

## Responsibility
The Private Vulkan Pipeline folder contains the implementation of Vulkan graphics and compute pipeline creation, resource binding, and pipeline state management. This folder implements the pipeline types (FVulkanGraphicsPipeline, FVulkanComputePipeline, FVulkanMeshPipeline, FVulkanRTPipeline) and the dynamic resource binding system (FVulkanPipelineResources) that are used by the frame graph and draw tasks.

## Design
The design implements FVulkanGraphicsPipeline for graphics pipeline creation, with shader stage creation, vertex input state, input assembly, tessellation, geometry shading, viewport, and state configuration. FVulkanComputePipeline handles compute pipeline creation with shader stage and dispatch state. FVulkanMeshPipeline supports NV_mesh_shader extensions with mesh and task shader stages. FVulkanRTPipeline handles ray tracing pipeline creation with shader group binding and SBT linkage. FPipelineResources manages dynamic resource bindings (uniforms, images, buffers) with type-safe Get<T>() access. The VECTORINSITU optimization is used for small descriptor sets (maximum 5 bindings). Descriptor set layouts are cached per-pipeline with hash-based deduplication.

## Flow
Pipeline creation begins with the specification of shader stages (vertex, fragment, compute, mesh, task, ray generation, miss, hit). The pipeline is created with VkGraphicsPipelineCreateInfo or VkComputePipelineCreateInfo, specifying the shader stages, vertex input state, input assembly, tessellation, geometry shading, viewport, and rasterization state. Dynamic state is configured via FDrawDynamicStates and DynamicOffsets. The pipeline layout is created with the required descriptor set layouts. FPipelineResources is constructed with the pipeline layout, and dynamic resource bindings (uniform updates, image bindings, buffer bindings) are recorded. During rendering, the pipeline is bound to the command buffer, and FPipelineResources.BindImage(), BindTexture(), BindBuffer(), and other methods are called to bind the required resources to the pipeline.

## Integration
This folder integrates with the frame graph subsystem (FVulkanFrameGraph) which creates pipelines during initialization and references them in TVulkanFrameTask<_Task> descriptions. Descriptor set layouts (FVulkanDescriptorSetLayout) are consumed by the pipeline layout creation. FPipelineResources binds resources that are used by draw tasks (FDrawVertices, FDrawIndexed, etc.) and compute tasks. The ray tracing pipeline (FVulkanRTPipeline) integrates with the ray tracing subsystem (FVulkanRayTracingShaderTable). Draw tasks process through the visitor pattern (IVulkanDrawTask::Process1/Process2), with Process1 setting up the pipeline and dynamic state, and Process2 issuing the draw command. The task graph (TVulkanTaskGraph<_Visitor>) processes tasks in dependency order.
