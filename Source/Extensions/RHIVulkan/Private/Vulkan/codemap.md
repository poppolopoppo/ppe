# Source/Extensions/RHIVulkan/Private/Vulkan/

## Responsibility
The Private Vulkan root folder contains the core Vulkan implementation files that serve as the foundation for all Vulkan-specific subsystems. This includes the fundamental types and implementations for command buffers, command batches, task graphs, memory allocation, descriptor sets, pipelines, ray tracing, and swapchain presentation. All other Vulkan subsystems (Command/, Descriptors/, Memory/, Image/, Pipeline/, RayTracing/) are built upon the types and patterns defined in this root folder.

## Design
The design is centered on the Vulkan frame graph architecture, where TVulkanTaskGraph<_Visitor> manages a dependency graph of TVulkanFrameTask<_Task> nodes. FVulkanCommandBuffer owns the Vulkan command buffer and integrates task graph nodes via slab allocation from the command buffer's memory pool. FVulkanCommandBatch tracks queue family usage and batch boundaries, ensuring that commands are submitted to the correct queue family. TMemoryPool provides lock-free block allocation with per-thread bucket caching, while TSlabHeap provides general-purpose slab allocation with WAVL-tree free-block management. FVulkanDescriptorSetLayout handles descriptor set layout creation, pooling, and caching with hash-based deduplication. The two-pass task processing model (Pass1 for setup/barriers, Pass2 for execution) is a deliberate design choice. Ray tracing support is provided through FVulkanRayTracingShaderTable, which manages shader binding tables per debug mode.

## Flow
The rendering flow begins with FVulkanFrameGraph constructing the dependency graph of TVulkanFrameTask<_Task> nodes. Pass1 processes each task: barriers are inserted, descriptors are bound, and dependencies are recorded in the task graph. Tasks are added to the TVulkanTaskGraph<_Visitor>, which tracks inputs/outputs and automatic attachment. Pass2 executes each task: vkCmdDraw/Dispatch/TraceRays are called with the appropriate dynamic state. FVulkanCommandBuffer records commands into the Vulkan command buffer, using its slab allocator for TVulkanFrameTask<_Task> node allocation. FVulkanCommandBatch tracks queue family usage across batches. Synchronization relies on semaphores (RenderFinished[]), fences, and pipeline barriers within the task graph. Presentation flows through FVulkanSwapchain::Present(), which acquires the next image, waits on the render-finished semaphore, and calls vkQueuePresentKHR.

## Integration
This folder integrates directly with Source/Runtime/RHI/ through FVulkanDeviceAPI, which implements FVulkanDeviceAPI for Vulkan and creates buffer types consumed by the frame graph. Memory allocation draws from TMemoryPool in Source/Runtime/Core/Public/Memory/ and TSlabHeap in Source/Runtime/Core/Public/Allocator/. The swapchain and presentation flow connects to FVulkanSwapchain in Private/Vulkan/Instance/. Descriptor set layouts are consumed by the Descriptors subsystem (Private/Vulkan/Descriptors/). Pipeline resources are consumed by the Pipeline subsystem (Private/Vulkan/Pipeline/). Ray tracing shader tables integrate with the RayTracing subsystem (Private/Vulkan/RayTracing/). Image resources are consumed by the Image subsystem (Private/Vulkan/Image/).
