# Source/Extensions/RHIVulkan/Private/

## Responsibility
The Private Vulkan folder contains the full Vulkan implementation, including the frame graph, command buffers, command batches, task graph, memory allocation, descriptor sets, pipelines, ray tracing, debug utilities, and swapchain presentation. This is where all Vulkan-specific backend logic is realized, implementing the integration between the RHI abstraction layer and the Vulkan API. The Private folder is not intended for inclusion in public engine headers; it contains the concrete implementations of all types declared in the Public folder.

## Design
The design is centered on the Vulkan frame graph architecture, where TVulkanTaskGraph<_Visitor> manages a dependency graph of TVulkanFrameTask<_Task> nodes. Each task node tracks its inputs and outputs, and automatic dependency resolution is achieved through input attachment. FVulkanCommandBuffer owns the Vulkan command buffer and integrates task graph nodes via slab allocation. FVulkanCommandBatch tracks queue family usage and batch boundaries, ensuring that commands are submitted to the correct queue family. TMemoryPool and TSlabHeap provide memory allocation with per-thread bucket caching and WAVL-tree free-block management. FVulkanDescriptorSetLayout handles descriptor set layout creation, pooling, and caching with hash-based deduplication. The two-pass task processing model (Pass1 for setup/barriers, Pass2 for execution) is a deliberate design choice to separate dependency resolution from command execution. Ray tracing is supported through FVulkanRayTracingShaderTable, which manages shader binding tables per debug mode.

## Flow
The rendering flow begins with FVulkanFrameGraph constructing the dependency graph of TVulkanFrameTask<_Task> nodes. Pass1 processes each task: barriers are inserted, descriptors are bound via FVulkanDescriptorSetLayout, and dependencies are recorded in the task graph. Tasks are added to the TVulkanTaskGraph<_Visitor>, which tracks inputs/outputs and automatic attachment. Pass2 executes each task: vkCmdDraw/Dispatch/TraceRays are called with the appropriate dynamic state. FVulkanCommandBuffer records commands into the Vulkan command buffer, using its slab allocator for TVulkanFrameTask<_Task> node allocation. FVulkanCommandBatch tracks queue family usage across batches. Synchronization relies on semaphores (RenderFinished[]), fences, and pipeline barriers within the task graph. At present, events are not directly observed — likely via barriers. Presentation flows through FVulkanSwapchain::Present(), which acquires the next image, waits on the render-finished semaphore, and calls vkQueuePresentKHR.

## Integration
This folder is the primary integration point for the entire rendering subsystem. It integrates with Source/Runtime/RHI/ through FVulkanDeviceAPI, which implements FVulkanDeviceAPI for Vulkan and creates buffer types consumed by the frame graph. Memory allocation draws from TMemoryPool in Source/Runtime/Core/Public/Memory/ and TSlabHeap in Source/Runtime/Core/Public/Allocator/. The swapchain and presentation flow connects to FVulkanSwapchain, which handles image acquisition, semaphore signaling, and vkQueuePresentKHR. Descriptor set layouts are consumed by FVulkanPipelineResources, which binds resources to pipelines. The task graph is consumed by FVulkanCommandBuffer, which records command buffers for submission to queues. Ray tracing shader tables integrate with the pipeline system for ray tracing workloads. The debuggger utilities (FVulkanDebugger) integrate with the command processing flow for validation and diagnostics.
