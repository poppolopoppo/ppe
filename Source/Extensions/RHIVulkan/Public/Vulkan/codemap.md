# Source/Extensions/RHIVulkan/Public/Vulkan/

## Responsibility
The Public Vulkan root folder exposes the API-visible Vulkan types and interfaces used by engine code and the private implementation. It declares the core types that are safe to include in public headers: FVulkanTaskGraph, TVulkanFrameTask, FVulkanCommandBuffer, FVulkanCommandBatch, IVulkanDrawTask, and the various task-specific types (FDispatchCompute, FCopyBuffer, FDrawVertices, etc.). This folder ensures that engine rendering code depends only on publicly documented Vulkan types, allowing the private implementation to evolve independently.

## Design
The public API is designed around well-defined interfaces and template types that hide implementation details. IVulkanDrawTask declares the visitor pattern (Process1/Process2) for draw task processing. TVulkanTaskGraph<_Visitor> is a template class managing the dependency graph of frame tasks. TVulkanFrameTask<_Task> is a template class representing a single frame task with inputs, outputs, and dependencies. FVulkanCommandBuffer owns the Vulkan command buffer and integrates task graph nodes. FVulkanCommandBatch tracks queue family usage and batch boundaries. Draw task templates (FDrawVertices, FDrawIndexed, etc.) are zero-cost abstractions specialized at compile time. The two-pass task processing model (Pass1 for setup/barriers, Pass2 for execution) is documented for engine code that needs to understand the processing pipeline.

## Flow
The rendering flow begins with engine code creating frame tasks via TVulkanFrameTask<_Task> and adding them to the TVulkanTaskGraph<_Visitor>, which builds the dependency graph. The task graph processes tasks in two passes: Pass1 sets up barriers and binds descriptors for each task, while Pass2 executes commands (vkCmdDraw, vkCmdDispatch, vkCmdTraceRaysKHR). FVulkanCommandBuffer records commands into the Vulkan command buffer, using its slab allocator for TVulkanFrameTask<_Task> nodes. FVulkanCommandBatch tracks queue family usage across batches. Draw tasks are processed by the visitor pattern: Process1 sets up barriers and binds descriptors, Process2 issues the draw/dispatch/trace rays command. Descriptor sets are cached per-task via FVulkanDescriptorSets.

## Integration
This folder is consumed by Source/Extensions/RHIVulkan/Private/ through the private implementation classes. FVulkanTaskGraph and TVulkanFrameTask are used by the private frame graph to build the dependency graph. FVulkanCommandBuffer is the primary integration point, recording commands that feed into the command buffer system. Draw task types (FDrawVertices, FDrawIndexed, etc.) are processed by the private task processor (VulkanTaskProcessor). The two-pass processing model is documented for engine code that needs to understand the processing pipeline. Swapchain integration occurs through FVulkanSwapchain, which is defined in the Private folder but referenced here for public API consistency.
