# Source/Extensions/RHIVulkan/Public/Vulkan/Common/

The Common folder provides shared Vulkan types, utilities, and base classes used across all Public/Vulkan/ subsystems. This is the foundational layer that ensures consistency across the Vulkan extension and minimizes code duplication.

## Responsibility
This folder owns shared Vulkan types, utilities, and base classes used across all Public/Vulkan/ subsystems. It provides the foundational types and helper functions that ensure consistency across the entire Vulkan extension. The Common folder defines type traits, utility functions, error handling, and base classes that are included by Buffer, RenderPass, and other subsystems. It is the lowest-level Public API folder, meaning it has no dependency on other Public/Vulkan/ subfolders—other modules depend on it instead.

## Design
The Common design focuses on small, focused types and utilities that are used pervasively across the Vulkan extension. FVulkanDeviceAPI provides a type-safe wrapper around VkDevice with methods for creating buffers, images, pipelines, and descriptor sets. TVulkanTypeTraits provides type traits for Vulkan types, including format conversion, feature flags, and memory property mapping. FVulkanResult and FVulkanError provide consistent error handling and logging across all Vulkan calls. TVulkanStringRef provides a zero-overhead string reference type used for debug names and labels. FVulkanNonCopyable provides a base class that deletes copy constructors and provides move semantics, used as a base for all Vulkan objects. FVulkanVulkanHeaders provides the Vulkan function pointers and struct definitions loaded dynamically at runtime. The design emphasizes compile-time safety with minimal runtime overhead. Key type names include FVulkanDeviceAPI, TVulkanTypeTraits, FVulkanResult, FVulkanError, TVulkanStringRef, and FVulkanNonCopyable.

## Flow
The Common flow begins with inclusion by all other Public/Vulkan/ subsystems. FVulkanDeviceAPI is the first point of contact for most Vulkan operations—buffer creation, image creation, pipeline creation, and descriptor set creation all go through this type. TVulkanTypeTraits is consulted whenever format conversion, feature checking, or memory property mapping is needed. FVulkanResult wraps VkResult and provides context-aware error messages, logging, and fallback behavior. FVulkanError provides detailed error reporting with file and line information, integrated with the engine's logging system. TVulkanStringRef is used for debug object naming (vkSetDebugObjectName) and for pass names in the frame graph. The flow is largely header-inclusion driven, with template metaprogramming via TVulkanTypeTraits resolving types at compile time. Error handling flows through FVulkanResult, which can either return the error or trigger a debug break depending on configuration.

## Integration
Common utilities are integrated by all Public/Vulkan/ subsystems. FVulkanDeviceAPI is consumed by FVulkanBuffer, FVulkanRenderPass, FVulkanPipelineResources, and all other Vulkan modules for device operations. TVulkanTypeTraits is consumed by TMemoryPool, TSlabHeap, and memory allocation code in the HAL for format and property mapping. FVulkanResult and FVulkanError are consumed by every Vulkan API call for error handling. TVulkanStringRef is consumed by the frame graph for attachment names, by pipeline resources for debug labels, and by the HAL for object naming. FVulkanNonCopyable is consumed as a base class by FVulkanDevice, FVulkanCommandBuffer, FVulkanBuffer, and all other Vulkan-owned objects. The Common folder has no outgoing dependencies on other Public/Vulkan/ folders—it is the foundation that all others build upon.
