# Source/Extensions/RHIVulkan/Public/Vulkan/RenderPass/

The RenderPass folder manages Vulkan render pass creation, framebuffer management, and render pass lifecycle. This is a core subsystem used by the frame graph to begin and end rendering passes, manage attachments, and handle framebuffer setup and teardown.

## Responsibility
This folder owns Vulkan render pass creation, framebuffer management, and render pass lifecycle. It provides the infrastructure for defining render pass instances, specifying attachments, load/store operations, and subpass dependencies. The folder handles single-pass and multi-pass rendering workflows, including complex rendering graphs that require multiple render passes. It provides type-safe FVulkanRenderPass objects that encapsulate VkRenderPass and VkFramebuffer, with automatic lifecycle management. The design supports both simple fixed-function rendering and complex deferred rendering pipelines.

## Design
Render pass design is centered on FVulkanRenderPass, which encapsulates a VkRenderPass and its associated VkFramebuffer. FVulkanRenderPass defines attachments, load/store operations, stencil operations, and subpass dependencies at construction time. The render pass creation process specifies attachment formats, resolve attachments, and color space conversion. FVulkanFramebuffer wraps VkFramebuffer and is created alongside the render pass, providing the framebuffer object used during rendering. FVulkanRenderPassBeginInfo and FVulkanRenderPassEndInfo provide type-safe structures for beginning and ending rendering, recording clear values and render area. The design supports render pass instances that can be reused across frames via the frame graph's attachment tracking. For complex scenes, FVulkanMultiRenderPass chains multiple render passes together, each with its own set of attachments and framebuffers. Depth/stencil attachments are managed via FVulkanDepthStencilAttachment. Key type names include FVulkanRenderPass, FVulkanFramebuffer, FVulkanRenderPassBeginInfo, FVulkanRenderPassEndInfo, FVulkanDepthStencilAttachment, and FVulkanMultiRenderPass.

## Flow
The render pass flow begins with FVulkanRenderPass::Create(), which takes a list of attachments with their formats, load/store operations, and sample counts. The render pass object creates VkRenderPass with the appropriate subpass dependencies. Simultaneously, FVulkanFramebuffer::Create() creates a VkFramebuffer using the render pass and the current swapchain image view. During rendering, the frame graph calls FVulkanRenderPass::Begin() to record vkCmdBeginRenderPass with clear values and render area, followed by vkCmdBeginRenderPass. After geometry submission, the frame graph calls FVulkanRenderPass::End() to record vkCmdEndRenderPass. The render pass and framebuffer are stored per-frame in the frame graph's attachment tracking, ensuring that the correct framebuffer is bound for each frame. Render pass cleanup happens at the end of the frame, with VkRenderPass and VkFramebuffer destroyed in the correct order. The flow is integrated with FVulkanFrameGraph, which tracks attachment lifecycles and resolves render pass dependencies across frames.

## Integration
Render pass management integrates with FVulkanFrameGraph (module root), which calls Create(), Begin(), and End() on the render pass for each rendering pass in the frame graph. Framebuffer integration connects to FVulkanSwapchain, which creates one framebuffer per swapchain image. Buffer integration connects to FVulkanBuffer, which provides vertex and uniform buffers bound during rendering. Descriptor set integration connects to FVulkanPipelineResources, which binds descriptor sets during the render pass. The render pass system is also integrated with FVulkanCommandBuffer for command recording within the render pass, and with the HAL's FVulkanDevice for VkRenderPass and VkFramebuffer creation. Debug marker integration connects to the Common folder's TVulkanStringRef for render pass naming.
