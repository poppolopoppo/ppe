# Source/Extensions/ApplicationUI/

## Responsibility
Application extension group containing the ImGui-based UI service and widget library that windowed applications integrate into their duty cycle. This group encompasses both public and private folders providing the UI service layer, widget implementations, and module infrastructure that concrete applications (such as ShaderToy) depend on for in-game UI. The group sits at the application layer, integrating with the runtime application layer (window management, HAL) and the content pipeline modules through the modular domain system. It provides the ImGui dockspace foundation, widget registry, and lifecycle management that all windowed apps use for their user interfaces.

## Design
The group follows the IModuleInterface pattern with StartShutdownDutyCycleReleaseMemory lifecycle across all module folders. The public API (Source/Extensions/ApplicationUI/Public/) exposes ImGui context management, dockspace setup, and widget registry through RTTI_MODULE_DECL-registered modules. The private folders (Source/Extensions/ApplicationUI/Private/) conceal concrete widget types, registry details, and ImGui context ownership behind clean interfaces. Widget library is organized by functional groups (import, file dialog, log, memory) with base classes and derived implementations. RTTI enables reflection and editor integration. ImGuiSettingsHandler provides per-widget state persistence across sessions. The design separates concerns between the public API that applications depend on and the private implementations that fulfill the API contract.

## Flow
Module Start() → ImGui context creation → dockspace setup → widget library loaded → Module DutyCycle() → ImGui::NewFrame() → widget rendering → Module Shutdown() → ImGui context destruction. Settings persistence across sessions via ImGuiSettingsHandler. Each frame, the duty cycle calls NewFrame, widgets render their UI, and the dockspace remains available for additional widgets or program-specific ImGui code. Input flows from the application's input service into widget event handling. The public API flow is: application requests widget → registry resolves type → widget renders → state update → next frame re-render. The private flow manages context ownership, widget factory registration, and event dispatch behind the scenes.

## Integration
Source/Runtime/Application/Public/Window/ (ImGui dockspace host for windowed apps), Source/Runtime/Application/Public/HAL/ (platform behind ImGui), Source/Programs/ShaderToy/ (ImGui UI consumer: dockspace, widgets, log viewer, memory usage), Source/Extensions/ApplicationUI/Public/ (public module API and widget registry), Source/Extensions/ApplicationUI/Public/UI/ (public widget API), Source/Extensions/ApplicationUI/Public/UI/Widgets/ (concrete public widget types), Source/Extensions/ApplicationUI/Private/ (private module details), Source/Extensions/ApplicationUI/Private/UI/ (private service layer), Source/Extensions/ApplicationUI/Private/UI/Widgets/ (concrete private widget implementations), Source/ContentPipeline/ (content pipeline modules integrated through modular domain)
