## Responsibility
This folder implements private Texture compression components for the Texture/Private/Texture submodule, handling low-level block compression operations for texture assets. It provides the DXT1/DXT5 compression implementations and associated metadata management that sits at the lowest level of the texture content pipeline.

## Design
Key patterns rely on `FCompressedImage` as the primary compressed image type, with `DXT1` and `DXT5` block compression formats as the core operations. The design follows the established block-compression pattern: `Compress(dst, src, quality)` → `Compress_()` → `BlockCompress_<DXT1/DXT5>()` with 4x4 alignment requirements. Color mask detection routes RGB data to DXT1 and RGBA data to DXT5 format selection automatically. `FTextureSourceProperties` stores dimensions, format, gamma, and flags metadata. `FTextureSource` attaches bulk data with source file for dependency tracking. Mip chain validation via `HasFullMipChain2D()` ensures generated mipmaps meet quality requirements. HDR and LongLat cubemap detection are supported for specialized texture types. The design adheres to the repo's ref-counted smart pointer conventions (`TPtrRef`, `U*`) for deterministic memory management.

## Flow
Scan phase: `FScanContext::Scan()` discovers texture source files and registers each as a dependency with `FBuildEnvironment`, validating source metadata via `FTextureSourceProperties`. Build phase: `FBuildContext::Build()` triggers compression operations, flowing through `Compress()` → `Compress_()` → `BlockCompress_<DXT1/DXT5>()` with 4x4 block alignment. The compressed image is stored in `FCompressedImage` with the appropriate format. Color mask detection determines DXT1 vs DXT5 routing based on RGB vs RGBA source data. Mip chain generation and validation execute via `HasFullMipChain2D()`. HDR/LongLat cubemap detection may trigger format overrides. Clean phase: `FCleanContext::Clean()` removes compressed artifacts and intermediate texture files.

## Integration
Connects to `Source/ContentPipeline/Texture/Private/Texture/Image/` for source image data feeding compression, `Source/ContentPipeline/Texture/Private/Texture/` for higher-level texture orchestration, `Source/ContentPipeline/Texture/Public/Texture` for public texture symbol consumption, and `Source/ContentPipeline/BuildGraph/Private/` for graph execution orchestration of compression builds. Downstream, compressed textures flow into `Source/ContentPipeline/PipelineCompiler/Private/Vulkan/Pipeline/` for Vulkan shader compilation with compressed texture assets.
