# Source/ContentPipeline/PipelineCompiler/

## Responsibility
The PipelineCompiler folder orchestrates the shader pipeline compilation process, managing the GLSL-to-SPIR-V-to-Vulkan-shader-module compilation chain for all pipeline types (graphics, compute, ray-tracing). It defines FVulkanPipelineCompiler as the main compilation backend, IPipelineCompiler as the abstraction interface, FVulkanSpirvCompiler for the SPIR-V compilation backend, and pipeline descriptor types (FMeshPipelineDesc, FGraphicsPipelineDesc, FComputePipelineDesc, FRayTracingPipelineDesc). The folder manages the full compilation flow from GLSL source parsing through SPIR-V assembly, reflection extraction, and Vulkan shader module creation with caching.

## Design
The pipeline compiler implements a multi-format support architecture: GLSL source → SPIR-V → Vulkan shader module, with the core compilation flow centralized in FVulkanPipelineCompiler::Compile(desc, fmt, logger) for each pipeline type. FVulkanSpirvCompiler::Compile() → ParseGLSL_() → CompileSPIRV_() → BuildReflection_() → ParseAnnotations_() handles the GLSL-to-SPIR-V conversion, with ParseGLSL_() performing source parsing, CompileSPIRV_() performing the actual SPIR-V assembly, BuildReflection_() extracting shader reflection metadata, and ParseAnnotations_() processing custom GLSL annotations for pipeline configuration. MergePipelineResources_() merges descriptor sets from all shader stages into a unified pipeline layout. CreateVulkanShader_() creates VkShaderModule instances with caching for repeated pipeline compilations. The folder supports specialization constants for task/mesh group sizes and local group sizes, and format negotiation via HighestPriorityShaderFormat_() selects the best available format. The Public/Private folder splitting separates the compiler abstraction interface from the Vulkan-specific implementation details.

## Flow
The compilation entry point is FVulkanPipelineCompiler::Compile(desc, fmt, logger) which is called for each pipeline type (graphics, compute, ray-tracing). For SPIR-V compilation, the flow proceeds through FVulkanSpirvCompiler::Compile() → ParseGLSL_() → CompileSPIRV_() → BuildReflection_() → ParseAnnotations_(). ParseGLSL_() parses the GLSL source code, CompileSPIRV_() assembles the SPIR-V binary, BuildReflection_() extracts descriptor set and push constant information from the shader, and ParseAnnotations_() processes custom annotations that configure the pipeline (specialization constants, group sizes, etc.). After SPIR-V compilation, CreateVulkanShader_() creates the VkShaderModule with caching. MergePipelineResources_() then merges descriptor sets from all shader stages into a unified pipeline layout. The BuildGraph system tracks pipeline compilation build nodes through the three-phase pipeline (Scan → Build → Clean), with revision tracking via FBuildRevision ensuring re-compilation when shader source changes.

## Integration
PipelineCompiler integrates with Source/ContentPipeline/BuildGraph/ for DAG-based pipeline compilation build node registration, with Source/ContentPipeline/Asset/ for asset-type-specific compilation triggers, with Source/ContentPipeline/MeshBuilder/ for mesh shader compilation when mesh-associated shaders are involved, with Source/ContentPipeline/Texture/ for texture shader compilation when texture-related shaders need compilation, with Source/ContentPipeline/PipelineReflection/ for reflection metadata that influences pipeline layout decisions, and with the Vulkan RHI layer for device-dependent shader module creation. Specific paths include Source/ContentPipeline/BuildGraph/ for compilation build node tracking, Source/ContentPipeline/PipelineReflection/Public for reflection types used in pipeline layout construction, Source/ContentPipeline/MeshBuilder/Public/Mesh for mesh-associated shader stages, Source/ContentPipeline/Texture/Public/Texture for texture-related shader stages, and Source/Runtime/RHI/ for Vulkan device integration and VkShaderModule creation.
