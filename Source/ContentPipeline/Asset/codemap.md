# Source/ContentPipeline/Asset/

## Responsibility
The Asset folder orchestrates the full content toolchain lifecycle, coordinating FAbstractContentToolchain, TContentToolchain, importers, processors, and serializers across all asset types. It serves as the central dispatch point for asset import and processing, ensuring type-safe routing of source assets through the pipeline. The folder houses the abstract base class FAbstractContentToolchain and its concrete specialization TContentToolchain, which manages dependency resolution, context injection, and output generation for every asset category. Serialization logic converts processed intermediate data into persistent asset formats, while importers and processors handle source-to-intermediate and intermediate-to-output transformations respectively. The Public/Private folder splitting separates API surface from implementation details, allowing module consumers to depend only on headers.

## Design
Key abstractions include the template-based TContentImporter<_Import> and TContentProcessor<_Process> types, both META_DYNAMIC_CASTABLE_IMPL-enabled for runtime type safety. The three context types—FContentImporterContext, FContentProcessorContext, and FContentSerializerContext—inject source directories, dependency lists, and intermediate output paths. FAbstractContentToolchain defines the toolchain interface (Initialize, Import, Process, Serialize, Clean) while TContentToolchain implements the concrete DAG-driven execution flow. Exception throwing via FContentImporterException enforces type mismatch guards. The Asset/Public folder exposes the public API for asset type registration and toolchain configuration, while Asset/Private contains implementation details including FContentImporterException and concrete importer/procesor specializations. META_DYNAMIC_CASTABLE_IMPL enables dynamic type resolution across the content toolchain, and the toolchain's Initialize/Shutdown cycle manages global state across the content build lifecycle.

## Flow
Data flow originates from source asset detection, proceeds through TContentToolchain::Import which dynamically dispatches to the appropriate IContentImporter::Import(ctx, dst), then through TContentImporter<_Import>::Import to produce intermediate data. Processors are invoked via IContentProcessor::Process(ctx, dst) → TContentProcessor<_Process>::Process, transforming intermediate data. Finally, serializers run IContentSerializer::Serialize(ctx, dst) to produce the final asset artifact. Each stage records dependencies via the context injection system, and the BuildGraph folder tracks these as DAG nodes for scan/build/clean orchestration. The toolchain flow follows Initialize() → Import() → Process() → Serialize() → Clean(), with context injection providing source dirs, dependency lists, and intermediate output paths at each stage. Type-safe routing ensures the correct importer or processor is selected via dynamic cast from the templated base.

## Integration
The Asset folder connects directly to every other ContentPipeline module. It references Source/ContentPipeline/BuildGraph/ for DAG-based build node tracking, Source/ContentPipeline/MeshBuilder/ for mesh importer integration, Source/ContentPipeline/Texture/ for texture processor coordination, Source/ContentPipeline/PipelineCompiler/ for compiled shader output handling, Source/ContentPipeline/Asset.Geometry/ for geometry asset type specialization, and Source/ContentPipeline/Asset.Texture/ for texture asset type routing. Specific paths include Source/ContentPipeline/Asset/Public/ for public API headers, Source/ContentPipeline/Asset/Private/ for implementation details, Source/ContentPipeline/Asset.Geometry/Public for geometry public API, Source/ContentPipeline/Asset.Geometry/Private for geometry implementation, Source/ContentPipeline/Asset.Texture/Public for texture public API, and Source/ContentPipeline/Asset.Texture/Private for texture implementation. The Asset folder's Public headers are consumed by Source/ContentPipeline/BuildGraph/ for node registration and by Source/ContentPipeline/MeshBuilder/Public for mesh importer dependencies.
