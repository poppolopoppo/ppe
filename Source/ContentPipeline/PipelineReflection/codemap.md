# Source/ContentPipeline/PipelineReflection/

## Responsibility
The PipelineReflection folder provides the pipeline reflection and shader metadata extraction infrastructure, enabling the ContentPipeline to inspect compiled shader reflection information and use it for build decisions, pipeline layout construction, and resource binding validation. It defines the reflection types and interfaces that inspect SPIR-V shader reflection data, enabling dynamic pipeline configuration based on actual shader resource usage rather than hardcoded assumptions.

## Design
The folder implements reflection type definitions that extract descriptor set information, push constant ranges, and shader resource bindings from compiled SPIR-V shaders. The reflection system integrates with the pipeline compiler to provide runtime introspection of shader resource usage, enabling build-time decisions about pipeline layout and resource allocation. META_DYNAMIC_CASTABLE_IMPL is applied to reflection types for runtime type identification, enabling dynamic dispatch of reflection queries based on shader type and configuration. The folder provides interfaces for querying descriptor set ranges, push constant sizes, and shader resource bindings, with the reflection data driving pipeline layout construction in the PipelineCompiler subsystem.

## Flow
Shader reflection data flows from the compiler output through the PipelineReflection subsystem, where SPIR-V reflection information is extracted and converted into usable build-time metadata. The reflection system queries descriptor set ranges, push constant sizes, and shader resource bindings from the compiled shader, and this metadata is consumed by the PipelineCompiler during pipeline layout construction (MergePipelineResources_()). The BuildGraph system tracks reflection-driven build nodes, with revision tracking ensuring that pipeline re-construction occurs when shader reflection changes. The reflection types are queried during the build phase to validate resource bindings and configure pipeline state dynamically.

## Integration
PipelineReflection integrates with Source/ContentPipeline/BuildGraph/ for reflection-driven build node registration, with Source/ContentPipeline/PipelineCompiler/Public for reflection metadata consumed during pipeline compilation, with Source/ContentPipeline/PipelineCompiler/Private for reflection data extracted during the compilation flow, with Source/ContentPipeline/MeshBuilder/ for mesh shader reflection queries, and with Source/ContentPipeline/Texture/ for texture shader reflection queries. Specific paths include Source/ContentPipeline/BuildGraph/ for reflection build node types, Source/ContentPipeline/PipelineCompiler/Public/Vulkan for reflection types used in pipeline layout construction, Source/ContentPipeline/MeshBuilder/Public/Mesh for mesh shader reflection queries, and Source/ContentPipeline/Texture/Public/Texture for texture shader reflection queries.
