# Source/ContentPipeline/MeshBuilder/

## Responsibility
The MeshBuilder folder provides the mesh content pipeline infrastructure, handling the import, processing, and serialization of mesh assets from source formats into the engine's internal mesh representation. It defines the importer and processor types that integrate with the TContentToolchain framework, enabling DAG-based build node registration in the BuildGraph system for scan/build/clean orchestration. The folder provides type-safe routing for mesh source assets through the content toolchain, ensuring that mesh assets can be tracked through the full content build lifecycle with proper dependency resolution and revision tracking.

## Design
Mesh processing follows the template-based pattern established by TContentImporter<_Import> and TContentProcessor<_Process>, with mesh-specific specializations registered through the content toolchain. The folder leverages META_DYNAMIC_CASTABLE_IMPL for runtime type identification of mesh importers and processors, enabling dynamic dispatch within the content toolchain's Import() and Process() stages. FContentImporterContext and FContentProcessorContext inject mesh-specific source directories, dependency lists, and intermediate output paths. The MeshBuilder folder integrates with the BuildGraph DAG for build node lifecycle management, and with the Asset.Geometry folder for geometry asset specialization. Mesh types support revision tracking via FBuildRevision, ensuring incremental builds only re-process source meshes when dependencies change. The Public/Private folder splitting within MeshBuilder separates the mesh API surface from implementation details, with mesh format definitions and importer interfaces exposed through Public headers.

## Flow
Mesh data flow begins with source asset detection, proceeds through TContentToolchain::Import which dispatches to the appropriate mesh IContentImporter::Import(ctx, dst), converting source mesh files (FBX, OBJ, etc.) into the engine's internal mesh format. The intermediate mesh data then flows through TContentProcessor::Process(ctx, dst) for any required post-processing (normal generation, tangent calculation, LOD setup). Finally, serializers produce the persistent mesh artifact. Each stage records dependencies via context injection, and the BuildGraph folder tracks mesh build nodes through the three-phase pipeline. The MeshBuilder.Public/ folder exposes the type definitions and API surface, while MeshBuilder.Private/ provides concrete importer implementations.

## Integration
MeshBuilder integrates with Source/ContentPipeline/BuildGraph/ for DAG-based build node registration of mesh pipeline nodes, with Source/ContentPipeline/Asset.Geometry/ for geometry asset type specialization, with Source/ContentPipeline/Asset/Public for the abstract toolchain interface and template types, with Source/ContentPipeline/Texture/ for texture coordinate and material mapping coordination, and with Source/ContentPipeline/PipelineCompiler/ for compiled shader output when mesh shaders are involved. Specific paths include Source/ContentPipeline/MeshBuilder/Public for mesh type API, Source/ContentPipeline/MeshBuilder/Private for concrete mesh importer implementations, Source/ContentPipeline/Asset.Geometry/Public for geometry type definitions, Source/ContentPipeline/Asset.Geometry/Private for geometry importer implementations that depend on mesh types, and Source/ContentPipeline/Asset.Texture/Public for texture coordinate and material mapping dependencies.
